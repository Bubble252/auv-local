# Goal73 结果：command-demand/曲率不区分 newly-lost，false-success 由 terminal p_nav 偏差主导

**日期**：2026-11-10<br>
**状态**：`COMMAND_DEMAND_NOT_SUPPORTED` / `PIVOT_TO_CAPTURE_AUDIT`<br>
**预注册**：`doc/goals/goal73_command_demand_speed_governor_20261110.md`<br>
**上游**：Goal72 `LIMITER_GEOMETRY_TRADEOFF`

## 1. 结论

```text
H73-A -> NOT SUPPORTED
H73-B -> NOT TESTED (预注册禁止在 H73-A 失败后实现 governor)
H73-C -> SUPPORTED (false-success 由 terminal capture / p_nav 估计偏差主导)
decision -> pivot
```

- heading/pitch command rate P90 在 `newly_lost` 与 `both_true` 两组都顶到
  limiter 上下限（`0.5236` / `0.2618 rad/s`），已经不是区分变量。
- default 的曲率代理只高 `+0.0215 1/m`，刚过预注册的 `0.02`；strict125
  反而是 `-0.0245 1/m`，方向相反。
- material saturation 在 default/strict125 的 newly-lost 都低于 both-true。
- 因此不实现 command-demand/curvature speed governor，不扫速度比例。

同一次审计发现 false-success 全部是 `sphere` 捕获：`p_nav` 距离刚好在
tight radius 内（余量 `0.01–0.04 m`），true `eta` 距离仍在半径外。
`p_nav-eta` 误差中位 default `0.4475 m`、strict125 `0.6131 m`，远大于
`p_nav` 到半径的余量。下一步应做 terminal capture / estimator bias 审计，
而不是继续加控制 authority 或换 RL 算法。

## 4. False-success 终端证据

| scenario | group | n | terminal p_nav-eta error (m) | terminal eta dist (m) |
|---|---|---:|---:|---:|
| default | newly_lost | 8 | 0.4475 | 2.3464 |
| default | both_true | 59 | 0.4012 | 1.5366 |
| strict125 | newly_lost | 3 | 0.6131 | 1.4870 |
| strict125 | both_true | 23 | 0.4184 | 0.8226 |

- default false-success：`p_nav` 距离约 `1.71–1.75 m`（tight radius
  `1.75 m`），true `eta` 距离约 `2.01–2.88 m`；
- strict125 false-success：`p_nav` 距离约 `0.94–0.99 m`（tight radius
  `1.00 m`），true `eta` 距离约 `1.25–1.62 m`；
- 所有 false-success 的 `terminal_capture_mode` 都是 `sphere`，不是
  plane crossing 的大横向 offset。

这说明控制器按 `p_nav` 捕获是“协议正确”的；但 true `eta` 未进半径时，
`success=true, terminal_eta_capture=false` 主要是 terminal 估计误差在
capture 边界附近翻转标签。
