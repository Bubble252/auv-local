## 1. 结论

128 条新 eval 全部完成。八个 arm 全部 `ACTION_PARAM_NO_EFFECT`：

```text
zero        strict 24.000 / default 33.000
M1.0        strict 19.750 / default 28.250
R0.10       strict 20.250 / default 29.625
R0.25       strict 19.750 / default 29.750
R0.50       strict 19.250 / default 29.500
F0.25       strict 21.875 / default 31.625
P0.25       strict 22.750 / default 32.750
D0.0        strict 21.125 / default 31.625
D0.5        strict 23.125 / default 32.375
R0.25D0.0   strict 21.500 / default 31.750
```

关键判读：

1. **只 cap rpm 反而更差**。R0.10/R0.25/R0.50 分别只有 20.25/19.75/19.25
   strict，均低于 M1.0 的 19.75（R0.25 持平，R0.10 略高但远低于 zero）。
   rpm 残差不是单纯“太大”，它至少承担了一部分 approach 修正。
2. **fin-only cap 也不够**。F0.25 为 21.875/31.625，比 P0.25 差，说明单独
   压 fin 会损失接近段的转向/俯仰修正。
3. **per-channel cap 与 global cap 等价**。P0.25 为 22.75/32.75，与 Goal129
   C1.0 的 22.75/32.875 基本相同；没有通道特异性增益。
4. **方向 gate 是唯一略有改善的轴，但仍未 parity**。D0.5 为 23.125/32.375，
   3/8 seed strict 提升，但 worst Δ=-4，default 仍低于 33。
5. **方向假设基本被证伪**。近区 `cos(L,B)` 均值约 -0.03，约 51% 的控制步
   为负；learner 与 frozen BC 在近区几乎正交/无关，不是“方向对、只是幅值错”。

因此 H130-A（rpm-only cap 是正确粒度）被证伪；H130-B（方向 gate 是第二因素）
只得到很弱的支持；H130-C（所有通道都该压）不成立；H130-D（参数化已到上限）
得到支持。动作参数化家族（global cap、shell gate、channel cap、direction gate）
已经覆盖，继续扫同一家族没有证据支持。

## 4. 通道与方向证据

| R0.10 | 2.614 | 1.568 | 0.100 | -0.117 | 0.579 |
| R0.25 | 2.584 | 1.572 | 0.249 | -0.117 | 0.583 |
| R0.50 | 2.535 | 1.572 | 0.494 | -0.114 | 0.580 |
| F0.25 | 0.244 | 0.243 | 6.391 | -0.085 | 0.566 |
| P0.25 | 0.244 | 0.242 | 0.248 | -0.062 | 0.534 |
| D0.0 | 1.225 | 0.607 | 2.906 | -0.013 | 0.508 |
| D0.5 | 0.685 | 0.373 | 1.644 | -0.013 | 0.506 |
| R0.25D0.0 | 1.216 | 0.676 | 0.109 | -0.063 | 0.542 |

两点很重要：

- rpm 的 learner/BC 确实最大（6.24×），但把它压到 0.10 反而比 M1.0 更差；
  这说明“rpm 幅值过大”不是充分解释，rpm 残差可能在补偿速度/几何。
- 方向 gate 在 `cos<0` 时把 learner 置零，但近区 cos 本来就在 0 附近，
  等于随机丢掉约一半控制步；D0.5 的 23.125 是“少做一点错事”，不是
  “保留了正确方向”。

## 5. 网络结构对照

本 Goal 仍未改变网络结构。当前 SAC 与 Goal108 audit 对齐：

```text
features_dim = 131 = z_t64 + zero-DADE64 + command3
state encoder = 20 -> 128 -> 128 -> 60 (+4 reserved)
path encoder  = bc_path_dim 8 -> 64 -> 64；endpoint 4 -> 32 -> 64（末层零初始化）
current encoder = 3 -> 64 -> 64（末层零初始化）
actor = 131 -> 256 -> 128 -> 3，ELU，mu 零初始化，log_std=-3.0
critic q input = 131 + 3 = 134，256 -> 128 -> 1
NoisyNet parameters = none
```

Goal108 audit 已有 63/63 tensor parity、PPO/SAC state encoder 逐元素相同、
`mu` 与 `actor.4.weight` 全零等证据。Goal130 的所有 arms 共用同一
checkpoint，只有推理期动作变换不同；因此 arm 间差异只能来自动作参数化，
不能归因于网络结构或 NoisyNet。用户提示的“网络结构问题与旧代码比对”
在这里的结论是：**结构一致，问题不在结构**。
