## 1. 结论

Goal98 修正了 scale 锚点：目标配置的真实
`pc.actuator_residual_scale=1.50`，1.50 no-op 复现 Goal95 final 的 30/19。
在 `0.75–2.00` 的六点网格上：

```text
status = SCALE_PARTIAL
qualifying_scale = 2.00
default: D3 31/40, BC15 32/40  (达到或超过 frozen 31)
strict125: D3 18/40, BC15 18/40 (低于 frozen 20)
```

所以“放大 residual scale”不是一个全局修复：它能救 default 的边界 seed，
但会把 strict 的两个边界 seed 推出 1.25 m capture radius。下一步不是换
SAC，也不是继续盲扫 scale，而是审计 terminal residual 的方向/闭合。

## 5. 终端闭合机制

从 Goal98 的 24 份全 trace 截取 `3–2 m` 和 `2–1.25 m` 窗口，按
`goal_distance_eta_m` 计算 radial closure：

| group/scale | 窗口 | success mean closure | failure mean closure | n(success/failure) |
|---|---|---:|---:|---:|
| P_D3 default 1.50 | 3–2 | 1.488 | 0.501 | 30/6 |
| P_D3 default 2.00 | 3–2 | 1.450 | 0.509 | 31/5 |
| P_D3 strict 1.50 | 2–1.25 | 1.422 | 0.536 | 19/11 |
| P_D3 strict 2.00 | 2–1.25 | 1.501 | 0.457 | 18/13 |
| P_BC15 strict 1.50 | 2–1.25 | 1.439 | 0.526 | 19/11 |
| P_BC15 strict 2.00 | 2–1.25 | 1.525 | 0.503 | 18/14 |

成功率与失败率的 closure 分离在所有 scale 都存在。关键在边界 seed：

| seed/group | 1.50 2–1.25 closure | 2.00 2–1.25 closure | 结果 |
|---|---:|---:|---|
| strict 22, D3 | 1.028 | 0.668 | success→miss |
| strict 29, D3 | 1.016 | 0.442 | success→miss |
| strict 44, D3 | 0.328 | 2.047 | miss→success |
| strict 22, BC15 | 1.058 | 0.688 | success→miss |
| strict 29, BC15 | 1.363 | 0.587 | success→miss |
| strict 44, BC15 | 0.232 | 2.057 | miss→success |

default 的 gained seed 27 在 2.00 把 `3–2 m` closure 从 `0.13` 提到
`0.66`；seed 49 从 `0.70` 提到 `1.22`。也就是说，2.00 对某些 seed
显著加快闭合，对另一些 seed 显著减慢闭合；这不是一个全局幅度问题。

## 6. 网络结构对照

本次仍然不是 NoisyNet 或接线问题：

- 当前低层 PPO 没有 NoisyNet，评价走确定性 `act_inference()`；
- checkpoint SHA 与 Goal95 final 一致；
- 1.50 no-op 精确复现 30/19；
- Goal86/87/89 parity 的 `d_z_total=64`、`n_z_reserved=4`、state encoder
  `[128,128]`、actor/critic `[256,128]` ELU、path12、command3 未变。

问题落在 terminal residual 的方向/有效动作，而不是网络容量或探索噪声。

## 8. 下一步

预注册 Goal99：只读复用 Goal98 的 24 份 trace，检查 scale 1.50 与 2.00 在
terminal window 的 residual 方向、applied/effective ratio、clip 和
plane-miss 几何。判据预先写死为：

- `DIRECTION_SUPPORTED`：失败 seed 的 residual 与闭合方向系统性相反；
- `AUTHORITY_LIMITED`：方向一致，但 effective/applied 被 clip/rate 限制；
- `GEOMETRY_LIMITED`：plane miss 主要是横向/纵向几何，不是 residual 方向；
- `INVALID`：trace 缺失或口径不一致。

只有 `DIRECTION_SUPPORTED` 才值得预注册 direction-aware gate；仍不换算法。
