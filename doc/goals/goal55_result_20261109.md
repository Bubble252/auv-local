## 1. 结论

Goal55 在 server 隔离目录对 seeds `60-99` 执行了一个
`default/baseline` 40-seed preflight。该 preflight 不是正式结果，只用于验证
新 seed block 的窗口、trace schema 和运行环境；它发现冻结的
`0 <= t < 8.0 s` 窗口在新 seed block 上不是普遍 pre-terminal：

```text

overall                 = INVALID_INPUT
decision                = stop
```

因此 Goal55 不能按冻结协议运行四个 block，也不能把结果写成
`PRETERMINAL_FEATURES_NOT_REPLICATED`。本 Goal 没有进行任何 hypothesis test，
没有用新 trace 计算 feature-outcome association，也没有用 seeds `60-99` 的 outcome
去选择窗口或 seed。

## 2. 为什么这是 protocol invalid，而不是 FAIL

Goal54 的 `8.48 s` 是 dev seeds `20-59` 上的观测最小值，不是理论保证。Goal55
预先复用了 `8.0 s` 窗口和 `8.48 s` terminal-entry 安全边界；新 seed block 中：

- seed `67` 的 `guidance_terminal_phase` 在 `7.98 s` 第一次为 true，直接落入
  `[0, 8.0)`；
- seed `77` 在 `8.36 s` 进入 terminal phase，早于 `8.48 s`；
- terminal phase 在 episode 内保持 true，seed 67 的 episode 正常结束于
  `16.08 s`，不是截断或 trace 损坏。

如果此时把窗口改成 `7.0 s`、删除两个 seed、换 seed block 或放宽
`8.48 s` 边界，就是看到 preflight 后修改预注册协议。这样做既不再是 Goal54 的
独立复现，也会污染后续 outcome association。因此本 Goal 的正确状态是
`INVALID_INPUT`，不是 `FALSIFIED`。

## 5. 文献边界与下一设计约束

早期预测必须先定义 prediction cutoff，并在 cutoff 前截断所有 feature，
否则会出现 temporal/label leakage；这与 LEAP 的 cutoff-first truncation 和
feature provenance audit 一致。lead-time / time-to-fault 工作也把 horizon、
false-alarm 和可操作预警视为同一个协议的一部分，而不是事后选择窗口。

所以如果未来继续，必须先开新的预注册 Goal，且至少满足：

1. 使用新的独立 seed block（例如 `150-189`）；seeds `60-99` 因本次 preflight
   的 outcome 和 terminal timing 已被污染，不再用于独立复现；
2. 明确 `cutoff`：例如 `window_end = min(8.0, first_terminal_s - 0.5)`，或用
   固定更短窗口；
3. 同时冻结 false-alarm 预算、outcome endpoint、covariates、permutation RNG
   和 held-out 隔离；
4. 明确这是 oracle-truncated 的只读审计还是可部署 early-warning；前者不能
   声称在线可用。

本 Goal 不执行上述新设计，也不授权训练、controller 修改、参数 sweep 或 held-out。
