## 1. 结论

本 Goal 没有产生关于 H-R1/H-R2/H-R3 的有效证据。现有 trace 在 `p_nav` 首次进入
当前 goal radius 时结束，所有 baseline success 的 terminal row 都紧贴终止边界。
因此任意正 margin 都会同时删除 true success 和 false success，
`candidate_success_count` 在两个场景、所有 checkpoint、zero-residual 和三个
margin 下全部为 `0`。这不是“收紧半径无法保留 true capture”的闭环结论，而是
terminal-row 离线反事实的结构性退化。

正式判读：

```text
INVALID_COUNTERFACTUAL_DEGENERATE_BOUNDARY
```

不能写成 `FAIL_STATIC_RADIUS`，也不能据此否定 terminal radius/dwell 方向。下一
步必须做抑制终止后的继续 rollout，才能评估闭环中 episode 是否会继续进入更紧的
`p_nav` 半径或 true `eta` capture。

## 4. 为什么判定为 INVALID

Goal60 trace 的终止规则是：`p_nav` 到 goal 的距离首次小于等于
`plant.goal_radius_m` 时写入 GOAL terminal 并停止记录。于是 baseline success 的
terminal distance 几乎都落在原半径边界上。离线把半径减去 `0.15/0.25/0.35 m`
后，所有成功 episode 都被排除；但真实闭环可能继续飞行并进入更紧的半径。离线
trace 没有这段继续 rollout，无法区分：

- 规则抑制了 false success 并在后续捕获；
- 规则抑制后 timeout/plane-miss；
- 规则始终无法进入更紧半径，暴露 estimator/geometry 问题。

因此本结果只证明“静态重放 terminal row 不可用”，不证明 radius margin 本身
无效。
