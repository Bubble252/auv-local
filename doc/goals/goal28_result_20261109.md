## 1. 结论

Goal28 回答的是“终点捕获失败是什么机制”，不是“哪个策略更好”。现有 40-seed
dev 证据给出两个 material 结论：

1. **H1 成立：现有 protocol success 明显高估真实状态捕获。** D3 的 protocol
   success 为 `0.725/0.500`，true-state capture 只有 `0.425/0.250`；p_nav-only
   success 占 protocol success 的 `48.3%/55.0%`。8 个 arm/scenario 的 pnav-only
   share 都在 `42.9%–55.0%`，超过预注册的 `20%` 门槛。
2. **H2 成立：plane miss 主要是终端横向几何误差，不是纵向过冲。** D3/P2 的
   plane miss 在过平面时 median horizontal-normal offset 为
   `2.18–2.58 m`，median tangent offset 仅 `0.011–0.013 m`；horizontal-normal
   占 terminal miss 的 `81%–87%`。miss distance 是 goal radius 的
   `1.27–1.79` 倍。

同时得到两个清晰的负结果：

3. **H3 被证伪：不是“速度过高/纵向过冲”。** plane miss 的 terminal speed
   ratio median 为 `1.02–1.03`，反而低于 true-state success 的
   `1.28–1.34`；两者差为 `-0.25` 到 `-0.31`。
4. **H4 被证伪：不是终端执行器饱和。** plane miss 的 terminal material
   saturation median 为 `0.000–0.005`，低于 true-state success 的
   `0.109–0.183`。miss 组的 terminal yaw error 更高（约 `0.75–0.76 rad`），
   但没有伴随更高饱和，因此不能写成“权限不够”。

因此下一步不应继续 residual PPO、奖励权重或训练预算搜索。更合适的下一目标是
**终端横向捕获/航向对齐**，并且 success 必须同时报告 protocol（p_nav）与
true-state（eta）两个口径。具体干预必须在 Goal29 预注册后再测试。

观察：

- pnav-only episode 的最终 true distance 仍然大于 goal radius；它们不是“最后刚好
  进半径”的边界样本，而是 true state 没有完成捕获；
- D3 default/strict125 分别有 `14/29`、`11/20` 个 protocol success 是 pnav-only；
- 反向也存在：D3 default 的 11 个 plane miss 中有 2 个 true eta 曾进入半径，
  strict125 的 20 个中有 1 个；所以不能把所有 plane miss 都当成真实 miss；
- terminal nav error 并不是单调解释项：default 的 pnav-only 误差高于 eta-success，
  但 strict125 不一定更高。因此 H1 的证据是“估计器会改变 outcome 分类”，不是
  “所有错误都由某个固定 nav bias 造成”。

裁决：**H1 MATERIAL**，且 **H5 METRIC VALIDITY MATERIAL**。以后报告必须同时给出
`success_protocol` 和 `success_eta`，不能只写一个 success。

观察：

- miss 在过平面时 longitudinal offset 接近 0，说明终止时刻本身正确，问题不是
  “冲过平面太远”；
- horizontal-normal offset 已明显超过 goal radius，且解释了大部分 miss distance；
- vertical offset 是次级项，default 约 `-0.34 m`，strict125 约 `-0.12` 到
  `-0.18 m`；不能把主因写成深度/垂向捕获；
- miss 组 terminal yaw error median 约 `0.75 rad`，远高于 true-state success 的
  `0.21–0.31 rad`。这支持“横向位置误差伴随航向对齐失败”，但本 Goal 只做诊断，
  不能把相关性直接当成因果干预。

裁决：**H2 MATERIAL**。主失败机制是 terminal horizontal cross-track / heading
alignment，而不是纵向 overshoot。

- miss 组的高 yaw error 不能被解释成“舵角饱和吃掉修正”，因为其 material
  saturation 更低；更像是终端横向/航向误差没有被有效消除。

裁决：**H3 FALSIFIED**，**H4 FALSIFIED**。不能把“更大的动作权限/更多 PPO 预算”

## 7. 解释与下一步

本结果排除了两个常见但错误的下一步：

- 不是“再训练 residual 去学更快/更大的终端动作”；
- 不是“放宽 goal radius 或阈值来救 success”。

下一步应在新的 Goal29 中预注册**终端横向捕获 / 航向对齐**的最小干预，并且：

1. 主报告同时给出 `success_protocol` 和 `success_eta`；
2. 保留 dev `20–59` 和 held-out `100–149` 的隔离；
3. 先做 1-seed screen，再决定是否 40-seed 确认；
4. 不以 path RMSE 改善替代 terminal capture；
5. 只有在 Goal29 预注册后才允许改控制器、reward 或 residual。

本 Goal 不启动任何训练，也不把 H2 的相关性写成已证明的因果机制。
