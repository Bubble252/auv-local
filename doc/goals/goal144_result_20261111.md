## 1. 课程 Gate 是否严格落实

结论：**是，gatefix2 已验证**。修复前的两个接线问题分别是：

1. `StageGate.stratified_default_success_min` 非空，但 `parse_eval_summary()` 从未
   填充分层，导致总体过阈值也永远 `gate not met`；
2. 回滚到上一 stage 后，预算仍用全局 transitions 判断，导致 500k 误判 C0
   `STAGE_BUDGET_EXHAUSTED`，没有执行 rollback anchor。

修复后，command 与 actuator 两条 PPO 臂的 `curriculum_decisions.jsonl` 完全一致：

| transitions | stage | decision | default / strict | plane miss | 分层 |
|---:|---|---|---:|---:|---|
| 100k | C0 | `CONTINUE` | `0.925 / 0.925` | `0.075` | `start_heading:nonneg 0.952 / neg 0.895` |
| 200k | C0 | `PROMOTE -> C1` | `0.925 / 0.925` | `0.075` | 同上 |
| 300k | C1 | `CONTINUE` | `0.65 / 0.65` | `0.35` | `path:P0 0.633 / P1 0.700` |
| 400k | C1 | `ROLLBACK -> C0` | `0.65 / 0.65` | `0.35` | 同上 |
| 500k | C0 | `CONTINUE` | `0.925 / 0.925` | `0.075` | 同上 |
| 600k | C0 | `STAGE_BUDGET_EXHAUSTED` | `0.925 / 0.925` | `0.075` | 同上 |

因此分层、连续两次通过后的 promotion、严重失败回滚、回滚后 anchor 和 per-stage
hard cap 都真实执行。全课程尚未跑通：C1 是当前瓶颈，不是 Gate 接线问题。

## 2. C1 失败模式

C1 在 300k/400k dev40 为 default/strict `0.65`、plane miss `0.35`、
timeout/safety `0`：

- `path:P0` `0.633`，`path:P1` `0.700`，两个分层都低于 C1 Gate `0.80`；
- 失败模式是 `goal_plane_miss`，不是 timeout、safety、NaN 或 flew-out；
- 这说明当前纯 ALOS + PPO 残差在低曲率正弦路径与噪声档上没有完成捕获。

## 3. PPO 残差活性

同一批 C0/C1 评估中：

- command 臂 `command_residual_abs_mean` 约 `8e-5–1.5e-4`，基本为零；
- actuator 臂 `actuator_residual_abs_mean` 约 `0.08–0.25`，但它的 success/plane-miss
  与 command 臂逐项完全相同；
- PPO 的 `approx_kl` 很小、entropy 基本不动，说明策略更新没有把残差推向有意义的
  闭环修正。

判读：`PPO_RESIDUAL_COLLAPSE / RESIDUAL_NO_CLOSED_LOOP_EFFECT`。这不是 reward
或 terminal 能解释的差异，也不是“样本效率不足”优先；因此按预注册做 SAC 同协议
对照，并把“残差是否真正改变动作与末段几何”作为主诊断（结果见 §4.1）。

## 4. 决策与下一步

- 保留 gatefix2 PPO 作为课程机制与 C1 瓶颈证据；gatefix1 400k 之后的决策不再使用。
- SAC command/actuator 同协议运行到 600k 后早停：C0 已达 hard-cap、C1 已回滚且
  回滚预算用尽，继续到 1M 不会产生新的课程裁决。早停不影响已记录的 C0/C1 Gate。
- 如果后续 trace 证明失败主要由纵向误差主导，按
  `goal140_vertical_tracking_reward_plan_20261111.md` §0/§4.2 的 potential-based
  vertical/heave/predicted-error reward 另开 reward arm；当前 Gate 中途不改 reward。
- Goal140 仍为 `P2`，不得提前启动。

## 4.1 SAC 同协议结果（600k 早停）

| arm | C0 100k/200k | C1 300k/400k | 回滚后 C0 500k/600k | 判读 |
|---|---:|---:|---:|---|
| SAC command | `0.925` -> `PROMOTE` | `0.15` / `0.225` -> `ROLLBACK` | `0.65` / `0.525` -> hard-cap | command residual 主动破坏 C1 与 C0 |
| SAC actuator | `0.925` -> `PROMOTE` | `0.625` / `0.625` -> `ROLLBACK` | `0.875` / `1.000` -> hard-cap | actuator residual 能改善 C0，但 C1 仍不达标 |

关键对照：

- PPO command 残差约 `1e-4`，SAC command 残差 L2 比约 `0.6%`；SAC 一旦真正改变
  command，C1 从 PPO 的 `0.65` 掉到 `0.15–0.225`，说明 command residual 的权限/
  参数化在 C1 上方向错误。
- PPO actuator 残差非零但闭环结果与纯 ALOS 相同；SAC actuator 残差 L2 比约 `1–5%`，
  C0 可到 `1.000`，但 C1 仍 `0.625`，说明 actuator 残差有局部作用、没有解决 C1
  的路径/终端捕获问题。
- 两种算法都没有把 C1 推到 `0.90`；因此当前瓶颈不是 on-policy vs off-policy，
  而是 **动作参数化/权限与 C1 末段控制**。不启动 REDQ/DroQ，不继续扫算法。

下一审计顺序固定为：command residual 的 heading/pitch/speed 尺度与 rate limit →
terminal gate 在 C1 的介入距离 → actuator residual 通道/限幅 → 失败几何
（横向 vs 纵向）；只有在确认纵向误差主导后，才启用 Goal140 reward arm。
