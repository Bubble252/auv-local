# Goal72 结果：limiter 的 tracking 改善伴随终端几何恶化，NoisyNet/residual 仍不是主导

**日期**：2026-11-10<br>
**状态**：`LIMITER_GEOMETRY_TRADEOFF`<br>
**预注册**：`doc/goals/goal72_terminal_geometry_limiter_20261110.md`<br>
**上游**：Goal71 `TRACKING_IMPROVES_OUTCOME_UNCHANGED`

## 1. 结论

正式判定：

```text
overall  -> LIMITER_GEOMETRY_TRADEOFF
default  -> LIMITER_GEOMETRY_TRADEOFF (H72-A + H72-B)
strict125 -> TRACKING_DECOUPLED_FROM_TERMINAL (H72-B; H72-A sample < 5)
```

- **default 的 H72-A 成立**：8 个 `newly_lost` 中，terminal `eta`、
  `p_nav`、`|signed offset|`、horizontal offset 的中位数分别恶化
  `+0.668 / +0.770 / +1.736 / +1.483 m`，任一几何量恶化 `>=0.10 m` 的
  seed 比例为 `8/8`。相对 `both_true` 的最大中位差为 `+1.741 m`。
- **strict125 的几何方向同向**：3 个 `newly_lost` 的 terminal `eta`、
  `|signed offset|`、horizontal offset 中位数分别恶化
  `+0.284 / +0.182 / +0.282 m`，worse fraction 为 `3/3`。由于预注册要求
  default 至少 5 个 newly lost 才单独判 H72-A，strict125 的 H72-A 保持
  `false`，但 overall 按“default 支持且 strict 同向”判 geometry trade-off。
- **H72-B 在两个 scenario 都成立**：default heading tracking 改善
  `0.577 rad`、pitch 改善 `0.160 rad`（crossing 前 1 s）；strict125 pitch
  改善 `0.245 rad`。但 closing speed 没有改善（default `-0.295 m/s`，
  即反而变差），terminal speed error 也没有改善（default `-0.063 m/s`）。
  tracking error 不是 terminal retention 的充分统计量。
- **NoisyNet/residual 不是主导**：default 的 `newly_lost` residual
  gate-ratio/abs 都低于 `both_true`；strict125 的 gate-ratio 高
  `0.094`，但 zero-residual true delta 为 `0`，没有因果恢复。所有正式
  评估使用 deterministic mean，`sample_noise=False`。不启动 SAC/REDQ/DroQ。

## 3. Outcome 主结果

| scenario | baseline true | off true | on true | original lost | recovered | newly lost | true delta | false-success off -> on | RMSE rel. |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| default | 70 | 99 | 97 | 9 | 5 | 8 | -2 | 29 -> 31 | -1.43% |
| strict125 | 30 | 43 | 44 | 7 | 0 | 3 | +1 | 17 -> 14 | -1.47% |

default 的 8 个 newly lost 中：

- `5` 个是 `GOAL_PLANE_MISS`（terminal kind 9）；
- `3` 个是 goal termination 但 `terminal_eta_capture=false`，即
  false-success：`s752/seed59`、`s880/seed59`、`zero/seed46`。

strict125 的 3 个 newly lost 中：

- `2` 个是 false-success：`s752/seed37`、`s880/seed37`；
- `1` 个是 plane miss：`zero/seed56`。

这说明 limiter 不是单纯“让所有轨迹更差”，而是同时：

1. 把一部分 original-lost 拉回 goal shell；
2. 把另一部分原本 true 的轨迹推成 plane miss 或
   `p_nav` 已进目标但 `eta` 未进目标的 false-success。

## 4. H72-A：default 几何 trade-off 成立

### 4.1 newly-lost 的终端几何

| scenario | field | n | off median | on median | median Δ on-off | worse fraction |
|---|---|---:|---:|---:|---:|---:|
| default | terminal eta distance (m) | 8 | 1.888 | 2.346 | **+0.668** | 0.875 |
| default | terminal p_nav distance (m) | 8 | 1.743 | 2.512 | **+0.770** | 0.625 |
| default | terminal abs(signed offset) (m) | 8 | 0.152 | 1.889 | **+1.736** | 1.000 |
| default | terminal vertical offset (m) | 8 | 1.563 | 1.094 | -0.381 | 0.000 |
| default | terminal horizontal offset (m) | 8 | 0.911 | 2.046 | **+1.483** | 1.000 |
| default | crossing eta distance (m) | 2 | 2.063 | 2.356 | **+0.293** | 1.000 |
| default | crossing p_nav distance (m) | 2 | 1.919 | 2.277 | **+0.358** | 1.000 |
| strict125 | terminal eta distance (m) | 3 | 1.203 | 1.487 | **+0.284** | 1.000 |
| strict125 | terminal p_nav distance (m) | 3 | 0.997 | 0.992 | -0.005 | 0.333 |
| strict125 | terminal abs(signed offset) (m) | 3 | 1.162 | 1.376 | **+0.182** | 1.000 |
| strict125 | terminal horizontal offset (m) | 3 | 1.151 | 1.465 | **+0.282** | 1.000 |

default 的“任一几何量恶化 >=0.10 m”比例为 `8/8`；strict125 为 `3/3`。
default 相对 `both_true` 的最大中位恶化差为 `+1.741 m`，strict125 为
`+0.296 m`，都超过预注册的 `+0.05 m`。

vertical offset 在 default 反而改善 `-0.381 m`，说明不是所有几何维度一起变差；
主导变化是 horizontal/signed offset 和 plane 方向。这排除了“只是整体尺度变大”
的简单解释。

### 4.2 crossing 的限制

只有 off/on 两侧都 crossing 的 seed 才进入 crossing 距离统计：

- default 的 8 个 newly lost 中只有 `2` 个两侧都 crossing；
- strict125 的 3 个 newly lost 中 `0` 个两侧都 crossing。

因此 crossing 几何只能作为 default 的小样本一致性证据，不能替代 terminal
geometry。没有 crossing 的失败主要是 plane miss 或 goal-shell 几何问题。

## 5. H72-B：tracking 改善与 terminal outcome 脱钩

crossing 前 1 s，`original_lost` 子集：

| scenario | heading improvement | pitch improvement | closing improvement | speed-error improvement | terminal eta improvement | terminal p_nav improvement |
|---|---:|---:|---:|---:|---:|---:|
| default | **+0.577 rad** | **+0.160 rad** | **-0.295 m/s** | **-0.063 m/s** | +1.193 m | +1.120 m |
| strict125 | -0.041 rad | **+0.245 rad** | +0.014 m/s | +0.005 m/s | +0.081 m | +0.089 m |

正号表示 on 更好。default 的 heading tracking 改善很强，但 closing 和
terminal speed error 都变差；strict125 的 pitch 改善明显，但 closing 和
speed-error 只有毫米到厘米级变化。

窗口一致性：

| scenario | delta | heading improvement | pitch improvement |
|---|---:|---:|---:|
| default | 1 s | +0.577 | +0.160 |
| default | 2 s | +0.216 | +0.089 |
| default | 3 s | +0.030 | +0.014 |
| strict125 | 1 s | -0.041 | +0.245 |
| strict125 | 2 s | -0.059 | +0.068 |
| strict125 | 3 s | +0.004 | +0.015 |

改善主要集中在 crossing 前最后 1 s，3 s 窗口接近零。这意味着 limiter 的
tracking 收益是 terminal-local 的，不能支撑“更早建立稳定接近轨迹”的解释。

default 的 `original_lost` 中 recovered seed 的 terminal `eta/p_nav` 确实更近
（中位改善 `+1.19/+1.12 m`），但同一 scenario 的 `newly_lost` 同时恶化
`+0.67/+0.77 m`。因此不能用 original-lost 的总体改善掩盖新丢失子集的几何
trade-off。

## 6. H72-C：NoisyNet / residual 负控

### 6.1 residual 幅度不区分 newly-lost

limiter-on，`policy` 子集：

| scenario | group | n | residual gate-ratio median | residual abs mean median |
|---|---|---:|---:|---:|
| default | newly lost | 8 | 0.109 | 0.123 |
| default | both true | 91 | 0.160 | 0.150 |
| strict125 | newly lost | 3 | 0.252 | 0.170 |
| strict125 | both true | 40 | 0.158 | 0.157 |

default 的 newly-lost residual 幅度**低于** retained，方向与“residual 太大导致失败”
相反。strict125 的 gate-ratio 高出 `0.094`，但 abs mean 只高 `0.012`，属于相关
信号而不是充分原因。

zero-residual 负控：

| scenario | off true | on true | true delta |
|---|---:|---:|---:|
| default | 19 | 17 | -2 |
| strict125 | 11 | 11 | 0 |

去掉 residual 后 true retention 没有恢复，因此不能满足预注册的 residual-dominant
判据（需要 residual 信号 + zero-residual 恢复 `>= +3`）。

### 6.2 NoisyNet probe 的历史证据

Goal59 的 frozen checkpoints 已有 read-only NoisyNet probe：

| checkpoint | noise std / deterministic L2 (mean / median) | noisy-vs-mean cosine median | deterministic saturation any dim |
|---|---:|---:|---:|
| s240 | 0.0093 / 0.0049 | 0.99999 | 1.0 |
| s752 | 0.0220 / 0.0083 | 0.99999 | 1.0 |
| s880 | 0.00054 / 0.00049 | 0.9999999 | 1.0 |
| s1008 | **1.033 / 1.056** | **0.689** | 1.0 |

s1008 是唯一一个 NoisyNet 噪声与 deterministic action 同量级的 checkpoint；
如果后续要查训练期 credit assignment，s1008 是最值得单独看的 seed。但：

- 正式评估使用 deterministic mean，不是 sampled noise；
- s1008 在 Goal71 default 的 true 只从 `17` 变 `16`，strict125 从 `4` 变 `4`；
- zero-residual 仍没有恢复 true retention。

所以当前闭环失败不能归因于 NoisyNet 采样主导。之前遇到过的 NoisyNet 问题是真的，
但这次不是同一个根因。

## 8. 机制解释与下一步

这组结果把机制从“tracking error 不够好”推进到“tracking 变好但终端几何变差”：

1. limiter 把 command rate 压到 envelope 内，final 1 s 的 heading/pitch
   tracking error 下降；
2. 但默认 scenario 的 horizontal/signed offset 同时恶化，新增丢失主要来自
   plane miss 和 `p_nav` 已进、`eta` 未进的 false-success；
3. strict125 的失败更偏向 false-success，说明 `p_nav` 与 `eta` capture
   口径的差异在更紧半径下更敏感；
4. residual 幅度和 NoisyNet 采样不能解释这些转移。

`decision = continue`。下一步优先预注册 terminal-aware action parameterization
或 controller bandwidth 的单因素 arm，重点检查：

- horizontal/signed offset 是否能在保持 command rate feasible 的同时被压回；
- `p_nav` 与 `eta` capture 的 false-success 是否减少；
- 1 s tracking 改善能否延续到 2–3 s，而不是只在 terminal 末端出现。

没有 optimization/exploration 或 sample-efficiency 证据前，不启动 SAC/REDQ/DroQ；
也不因 8×4090 空闲而改变正式评估协议。

### 8.1 算法切换提醒（本次未触发）

后续只有在**独立预注册 Gate** 给出对应失败证据时才允许换算法，且必须保持
同一场景、checkpoint、dev seeds、CPU/float64 评估协议和 held-out 关闭：

| 失败证据 | 允许的新预注册 goal | 不允许做的事 |
|---|---|---|
| 明确是 optimization/exploration：同一 MDP、同一数据/奖励下，策略梯度方差或探索不足导致 return 不升，且 zero-residual/冻结策略对照无法解释 | 新开 SAC 同协议对照，固定总 transitions、replay 比例、UTD、eval seeds | 不在当前 Goal 中把 PPO/DDPG 换成 SAC |
| 明确是 sample efficiency：单位环境交互的 return 显著低于对照，且增加并行采样/batch 后仍无改善 | 考虑 REDQ/DroQ，先做吞吐与 UTD 基准 | 不用“换算法”掩盖 reward/terminal 定义问题 |
| 残差大但闭环不动 | 先查动作参数化、reward、terminal capture | 不换算法、不放大 residual、不换 seed |

本次 Goal72 的失败模式是 terminal geometry trade-off 与 false-success，
既没有 optimization/exploration 证据，也没有 sample-efficiency 证据，因此
SAC/REDQ/DroQ 全部保持关闭。
