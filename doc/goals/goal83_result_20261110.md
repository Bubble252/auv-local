## 1. 结论

本轮只读复用 20 个已记录 run、800 个 episode，不训练、不新增 rollout、不打开
held-out、不启动 SAC/REDQ/DroQ。结论是：

```text
H83-A residual / base / scale / rate / projection / replay -> NOT SUPPORTED
H83-B p_nav-eta capture frame ambiguity                    -> SUPPORTED
H83-C terminal chain loss without frame ambiguity          -> NOT SUPPORTED overall
                                                               (strict125 secondary signal)
overall                                                     -> CAPTURE_FRAME_AMBIGUITY
```

最重要的三条事实：

1. residual 的命令映射是干净的：`base_command` 时序、scale、rate limit、
   `goal_distance`/`signed_offset` 投影和 done 行终止复现全部通过；
2. 差异不在 done 快照，也不在 `terminal_eta_capture` 的 protocol 半径标签，而在
   首次 p_nav crossing 处：p_nav 与 eta 的 plane sign 经常相反；
3. 用 true eta 的 tight-radius capture 作为 oracle，四个 group 共恢复 `12/29`
   lost，新增 false-success 均在预注册 `0.05` 以内；但 eta 是真实状态，不能直接
   当作可部署 success 规则。

因此当前不应改 reward、动作参数化或算法。下一步先做预注册的 eval-only
capture-frame 单因素审计，确认 frame 规则本身能解释多少 lost，再决定是否需要
可观测估计器或 terminal approach 修复。

## 4. H83-B：capture frame ambiguity 支持

### 4.1 lost 与 frame 分歧

| root | scenario | lost | done capture disagree | crossing capture disagree | crossing plane-sign disagree | done protocol disagree | eta tight recovered | additive false |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| baseline | default | 1 | 0 | 1 | 1 | 0 | 1 | 0.0063 |
| baseline | strict125 | 6 | 0 | 1 | 6 | 0 | 2 | 0.0375 |
| candidate | default | 15 | 0 | 4 | 8 | 0 | 8 | 0.0187 |
| candidate | strict125 | 7 | 0 | 0 | 6 | 0 | 1 | 0.0250 |

`done capture disagree` 和 `done protocol disagree` 全为 `0`，说明差异不是 done
快照或 protocol 半径标签造成的。支持来自首次 p_nav crossing：p_nav 已越过平面，
但 eta 的 signed offset 仍为负；四个 group 都有至少 `10%` 的 lost 出现该现象。
candidate default 还有 `4/15` 的 crossing 出现 capture 分歧。

### 4.2 true eta 的 oracle upper bound

用 `eta` 在 tight radius 内曾经出现过作为 oracle 规则，四个 group 分别恢复
`1/1`、`2/6`、`8/15`、`1/7` lost，合计 `12/29`。新增 false-success 分别为
`0.0063`、`0.0375`、`0.0187`、`0.0250`，都低于预注册的 `0.05`。

这不是可部署结果：eta 是真实状态，真实系统只有 p_nav/估计状态。它只说明
“部分 lost 在 true-state frame 下其实接近或进入过 tight capture”，因此
capture frame 是值得单独审计的次级因素，而不是直接改写正式 success。

candidate default 的 `8/15` 最强，candidate strict125 只有 `1/7`；后者主要贡献
的是 crossing plane-sign 分歧，不是 eta 实际 capture。这个差异必须保留，不能把
default 的 frame 结论外推到 strict125。

## 5. H83-C：strict125 有 terminal-chain 信号，但预注册优先级选中了 frame ambiguity

policy 相对 zero-residual 的 paired median diff 如下；距离和 tracking error 都是
“越小越好”，负值表示 policy 改善。配对要求 policy 与 zero 两侧都 reference-true；
default 为 16 个 seed、54 个 policy reference 行，strict125 为 7 个 seed、23 个
policy reference 行，与 Goal82 口径一致。

| root | scenario | heading diff [95% CI] | pitch diff [95% CI] | terminal p_nav diff [95% CI] | terminal eta diff [95% CI] | true diff |
|---|---|---:|---:|---:|---:|---:|
| baseline | default | `-0.0594 [-0.4173, 0.0141]` | `+0.0188 [-0.0176, 0.0639]` | `-0.0094 [-0.5964, -0.0014]` | `-0.0688 [-0.5990, 0.0400]` | `+0.2940` |
| baseline | strict125 | `-0.1305 [-0.2161, -0.0379]` | `+0.0289 [-0.0418, 0.0750]` | `-0.0062 [-0.0214, 0.0009]` | `-0.1494 [-0.2642, -0.0382]` | `-0.1180` |
| candidate | default | `-0.0190 [-0.1898, 0.1491]` | `+0.0081 [-0.0242, 0.0509]` | `+0.0051 [-0.5306, 0.3927]` | `+0.0308 [-0.5447, 0.4736]` | `+0.0972` |
| candidate | strict125 | `-0.1151 [-0.1749, -0.0286]` | `-0.0039 [-0.0248, 0.0400]` | `-0.0051 [-0.1897, 0.0258]` | `-0.2757 [-0.4537, 0.0807]` | `-0.0186` |

strict125 的 heading tracking 确实显著改善：baseline `-0.1305`、candidate
`-0.1151`，相对改善都超过 `10%`。但 terminal distance 的区间并不一致：
baseline strict125 的 p_nav 区间 `[-0.0214, 0.0009]` 跨零、eta 区间
`[-0.2642, -0.0382]` 不跨零；candidate strict125 的 p_nav/eta 区间都跨零。
true diff 仍为负（`-0.1180` / `-0.0186`），因此 strict125 存在“tracking
改善没有转化为 terminal capture”的次级信号，但不能概括为两个 terminal 指标
的区间都跨零。

然而预注册 H83-C 明确要求 H83-A/B 都不支持，才允许把 terminal chain loss 作为
主判定；本轮 H83-B 已支持，因此 overall 仍判 H83-C `no`。这不是否认 strict125
的 terminal-chain 信号，而是按预注册优先级先处理 capture frame。

表中 `true diff` 是在 reference-true seed 子集上 policy 与 zero 的 true-rate
差；baseline/candidate strict125 的 true diff 为负，和 heading 改善同时出现，
与“tracking 改善未转化为 outcome”一致。H83-C 仍由 tracking 与 terminal
distance 的联合条件判定，不能用单一 true-rate 差替代。

## 6. 对“神经网络打不过传统方法”的含义

这轮没有发现 residual 映射或 NoisyNet 主导的证据：

- base timing、scale、rate、projection、terminal replay 全部通过；
- residual 不是通过限幅、饱和或时间错位造成失败；
- 失败仍然集中在 terminal capture frame 和 terminal approach，而不是网络没有
  产生控制量。

更准确的表述是：当前 residual policy 的终末 success 仍受 `p_nav` 与 true `eta`
的帧差异、以及 terminal 阶段的几何/估计误差限制。传统 ALOS 基座有强先验，
residual 只在一个很窄的终末窗口里学习；在 capture frame 还没有对齐之前，
直接用 SAC/REDQ/DroQ 替换算法会混淆变量。

## 7. 决策与下一步

正式状态：`CAPTURE_FRAME_AMBIGUITY`。

- 不修改 reward、动作参数化、controller、checkpoint、seed 或 held-out；
- 不启动 SAC/REDQ/DroQ；
- 下一个预注册 goal 只做 eval-only capture-frame 单因素审计：
  1. 固定 true-eta oracle frame 与 p_nav formal frame 的差异；
  2. 按 group 报告 true recovery、additive false-success 和 strict125 的外推风险；
  3. 只有在 frame 规则可接受后，才讨论可观测估计器或 terminal approach；
  4. 如果 frame 规则不可接受，写 blocker，进入 autoresearch loop，不直接换算法。
