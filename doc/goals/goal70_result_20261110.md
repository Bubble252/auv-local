# Goal70 结果：command rate 需求超限，phase lag 与 NoisyNet 不是判别因素

**日期**：2026-11-10<br>
**状态**：`COMMAND_RATE_INFEASIBLE`<br>
**预注册**：`doc/goals/goal70_command_feasibility_phase_lead_20261110.md`<br>
**上游**：Goal69 `PRECROSSING_MULTICHANNEL_TRACKING_LAG`

## 1. 结论

Goal70 只读复用 Goal67 的 10 条 rich trace，在 crossing 前 1 s 检查 command
rate、actual rate、phase lag、执行器 limit 和 terminal guidance。正式判定：

```text
default   -> COMMAND_RATE_INFEASIBLE
strict125 -> COMMAND_RATE_INFEASIBLE
overall   -> COMMAND_RATE_INFEASIBLE
```

- **H70-A 支持**：default 和 strict125 的 lost 都出现 heading command rate
  P90 超过配置 envelope，且显著高于 retained。default 的 heading P90 为
  `1.457 vs 0.677 rad/s`，exceed fraction 为 `0.961 vs 0.196`；strict125 为
  `3.489 vs 0.677 rad/s`，`0.667 vs 0.176`。
- **H70-B 正式不支持**：heading phase correlation 只有 `0.235/0.328`，低于
  冻结的 `0.50`；pitch 虽有部分相位证据，但 lost 的 gain/lag 并不比 retained
  更差。控制器存在全局幅值衰减，但这不是本次 lost/retained 的判别因素。
- **H70-C 正式不支持（default）**：terminal phase fraction 在两组都是 `1.0`，
  late-minus-early heading 需求在 lost 为 `+0.348 rad/s`，retained 反而为
  `+0.371 rad/s`。strict125 有更大的 late heading demand，但 C 预注册只覆盖
  default，不能追认或外推。
- **speed 负控通过**：speed error gap 为 `-0.005/-0.111 m/s`，lost 并不更差。
- **不是执行器饱和**：`fin_rate_at_limit_fraction = 0`，command reachability
  infeasible fraction 为 `0`，material saturation 在 lost 反而更低。
- **NoisyNet/residual 仍不是主导**：Goal69 已排除；本 Goal 没有新增反例。

因此，当前最便宜、最可证伪的下一步不是换 RL 算法，而是预注册一个
**单因素 command-rate-limit / command-shaping 闭环 arm**，检查按现有配置恢复
heading/pitch rate limiter 后 tracking error 和 true retention 是否改善。

## 2. 协议与完整性

| 项目 | 固定值 |

| trace | Goal67 的 10 个 rich candidate |
| candidate | 4 个 Goal59 checkpoint × default/strict125 policy + 2 个 zero-residual |
| baseline/reference | Goal60 / Goal65 相同 dev 结果 |
| seeds | dev `20–59`，40 seeds/run |
| eval | CPU/float64、`endpoint_stop`、dwell=50、`r_tight = r0 - 0.25 m` |
| 主窗口 | crossing 前 1 s；2 s 只作一致性检查 |
| new rollout / 训练 | 无 |
| held-out | `100–149` 关闭 |

完整性检查全部通过：summary/trace finite；`device=cpu`、`dtype=float64`；
`residual_scale_multiplier=1.0`；dwell 与 goal/guard radius 一致；checkpoint SHA
在 baseline/candidate/reference 之间一致；Goal65 逐 seed 等价性通过；trace seed
范围恰好 `20–59`；rich 字段完整。没有触发 `INVALID_DIAGNOSTIC`。

配置复核：

```text
heading_rate_limit_rad_s = 0.5236
pitch_rate_limit_rad_s   = 0.2618
speed_rate_limit_mps2    = 0.25
plant fin rate limit     = 150 deg/s = 2.618 rad/s
command_rate_limit_enabled = false
```

`pc_env._limit_guidance_command` 在 `command_rate_limit_enabled=None` 时回退到
`saturation_governor_enabled`；当前后者为 `false`，所以 guidance command rate
limiter 实际关闭。Goal70 的 `exceed_fraction` 衡量的是 command 需求超过这个
已配置但未启用的 shaping envelope，不是执行器饱和。

## 3. H70-A：command rate / feasibility 支持

crossing 前 1 s 的主结果：

| scenario | group | n | heading cmd p90 | heading exceed | pitch cmd p90 | pitch exceed | reach infeasible |
|---|---|---:|---:|---:|---:|---:|---:|
| default | lost | 9 | `1.457` | `0.961` | `0.441` | `0.529` | `0.000` |
| default | retained | 61 | `0.677` | `0.196` | `0.416` | `0.333` | `0.000` |
| strict125 | lost | 7 | `3.489` | `0.667` | `0.900` | `0.902` | `0.000` |
| strict125 | retained | 23 | `0.677` | `0.176` | `0.585` | `0.471` | `0.000` |

正式 Gate：

- default：heading P90 `1.457 >= 1.25 × 0.5236 = 0.6545`，exceed `0.961`，
  lost-retained gap `0.780 rad/s`，支持；
- strict125：heading P90 `3.489`、exceed `0.667`、gap `2.812 rad/s`，支持；
  pitch 也支持：P90 `0.900`、exceed `0.902`、gap `0.315 rad/s`；
- default 的 pitch gap 只有 `0.025 rad/s`，低于 `0.05`，pitch 单独不支持；
- translational reachability 没有触发：两组 infeasible fraction 都是 `0`。

2 s 一致性检查没有推翻主结果：lost 的 2 s heading command rate P90 为
`1.343/2.969 rad/s`，retained 为 `0.516/0.502 rad/s`；2 s 比 1 s 低
`0.114/0.520 rad/s`，说明最后 1 s 的需求更高，但 2 s 内仍明显高于 retained，
不是窗口边缘的孤立采样。

限制：这是观测性归因。H70-A 支持说明 command demand 超出 shaping envelope，
不能单独证明只要限速就一定能救回闭环；因果验证必须另开预注册 arm。

## 4. H70-B：phase lag / bandwidth 正式不支持

| scenario | group | heading gain | heading lag | heading corr | pitch gain | pitch lag | pitch corr |
|---|---|---:|---:|---:|---:|---:|---:|
| default | lost | `0.003` | `0.300` | `0.235` | `0.025` | `-0.000` | `0.584` |
| default | retained | `0.020` | `0.180` | `0.300` | `0.035` | `0.120` | `0.281` |
| strict125 | lost | `0.007` | `0.300` | `0.328` | `0.008` | `-0.000` | `0.691` |
| strict125 | retained | `0.018` | `0.220` | `0.307` | `0.026` | `0.040` | `0.352` |

读法：

- heading 的 lag 估计在 `0.30 s` 搜索边界且 correlation 低，正式 Gate 要求
  `corr >= 0.50`，因此不能把 `0.300 s` 当作可靠相位滞后；
- pitch 的 correlation 在 default lost 为 `0.584`，但 lag 约为 `0`，且
  lost gain `0.025` 并不低于 retained `0.035`；strict125 同样不满足
  lost-vs-retained 的 `0.15` gain gap 或 `0.03 s` lag gap；
- 两个 scenario 的 lost/retained 都有很强的 command-to-actual 幅值衰减，说明
  controller 全局响应幅度有限；但 H70-B 问的是“它是否是这次失败的判别因素”，
  目前答案是否定的。

因此不能写成“phase lead/带宽已经修复”或“controller 无带宽问题”，只能写
“在本协议下，phase/bandwidth 不区分 lost 与 retained，正式不追认”。

## 5. H70-C：terminal guidance 额外需求不支持

`guidance_terminal_phase` 在 lost/retained 都是 `1.0`，这个字段本身不能区分
两组。default 的 late-minus-early heading demand 为 `+0.348 rad/s`，retained
为 `+0.371 rad/s`；pitch 为 `-0.035 vs +0.118 rad/s`。因此 default 的正向
上升不是 lost 特有，C=false。

strict125 的 late heading demand 为 `+2.870 rad/s`，retained 为 `+0.382 rad/s`，
但预注册明确规定 C 只在 default 正式判定，strict125 只作描述，不能把这条
观察追认为 terminal guidance 结论。

## 6. 执行器、NoisyNet 与负控

| 检查 | default lost/retained | strict125 lost/retained | 判读 |
|---|---:|---:|---|
| material saturation | `0.118/0.235` | `0.176/0.353` | lost 更低，不是主因 |
| fin rate at limit | `0.000/0.000` | `0.000/0.000` | 没有 fin rate 饱和 |
| reachability infeasible | `0.000/0.000` | `0.000/0.000` | 没有 translational infeasible |
| speed error gap | `-0.005 m/s` | `-0.111 m/s` | speed 负控通过 |

NoisyNet/residual 复核沿用 Goal69 的确定性 eval 和 zero-residual 反例：

- eval 使用 deterministic mean weights，不采样 NoisyNet 噪声；
- residual/base 在 default lost 为 `0.109`、retained 为 `0.200`，strict125 为
  `0.181/0.176`，lost 不更高；
- zero-residual 仍丢 default 4 个、strict125 1 个 true episode；
- 本 Goal 的 residual scale/rate clip 仍为 0。

所以“残差大是不是被 NoisyNet 主导”在当前证据下仍然是否定的。更准确的描述是：
raw residual 数值看起来不小，但它相对 base command 不占主导，且 deterministic
闭环在关闭 residual 后仍复现失败。

## 8. 假设裁决与下一步

| hypothesis | 裁决 | 证据 |
|---|---|---|
| H70-A：command rate/feasibility 是主因 | **SUPPORTED** | heading P90/exceed/gap 在两个 scenario 都过门槛；strict125 pitch 也过 |
| H70-B：controller phase/bandwidth 是主因 | **NOT SUPPORTED** | lost 的 corr/gain/lag 没有稳定优于 retained；全局衰减存在但不判别失败 |
| H70-C：terminal guidance 增加额外需求 | **NOT SUPPORTED (default)** | terminal fraction 两组都是 1；default late heading 在 retained 也上升 |
| speed 负控 | **PASS** | speed error gap 为负 |
| 执行器 rate saturation | **REJECTED** | fin at limit 为 0，material saturation lost 更低 |
| NoisyNet/residual 主导 | **REJECTED** | deterministic eval；zero-residual 仍失败；residual/base lost 不更高 |

决策：`continue`。不换 RL 算法，不启动 SAC/REDQ/DroQ。下一步预注册 Goal71：

1. 保持 frozen checkpoint、dev `20–59`、`endpoint_stop`、CPU/float64、held-out
   关闭；
2. 只启用现有 `heading_rate_limit_rad_s=0.5236`、`pitch_rate_limit_rad_s=0.2618`、
   `speed_rate_limit_mps2=0.25` 的 command rate limiter，作为单一因素 arm；
3. 与当前关闭 limiter 的 Goal67 baseline 做逐 seed 对照；
4. 主指标仍是 true retention、plane miss、tracking error，不扫 reward/gamma/seed；
5. 只有该 arm 失败且明确是优化/探索问题，才另开 SAC；只有出现样本效率证据，
   才考虑 REDQ/DroQ。
