# Goal27 最终结果：命令残差、接口对照与信用分配诊断

日期：2026-11-09<br>
总体裁决：**FAIL / PIVOT**（停止命令残差主线）

## 1. 结论

Goal27 的核心候选是在 ALOS 的 `[psi_d, theta_d, u_d]` 命令空间上加 PPO 残差。
在固定的 40-seed dev 矩阵上，C1、R1、H1、G1 四个臂都没有产生可用的路径跟踪收益：

- 残差始终坍缩到近零，命令残差均值约 `0.0026–0.0032`，远小于 heading scale；
- 相对 B0 的 pre-goal 3D RMSE 变化均小于 `0.011 m`，远低于 `0.10 m` 效果门禁；
- success 与 B0 相同或低一个 seed，没有达到 `+0.03`；
- safety、timeout、plane-miss 护栏没有恶化，失败点是“没有效果”，不是“牺牲成功换指标”。

因此不能把命令残差写成有效方案。C1p 的表面提升来自 privileged controller，而不是
residual；A1（frozen D3 action residual + reward-v2）相对合适的 Goal26-P2 基线也只
改善约 `0.02 m`，且 success 在 default/strict125 间各移动一个/两个 seed，不能算通过。

本 Goal 停止继续扫命令残差 reward 权重、GAE 参数或训练 seed。下一步应进入新的
预注册 goal，先处理任务级 terminal capture/plane miss，再测试 supervised 或
off-policy residual；不能把本报告解释成“继续加 PPO 预算会有效”。

## 5. 逐臂归因

### C1：接口等价但残差塌缩

- default RMSE 比 B0 差 `0.0091 m`，strict125 差 `0.0097 m`；
- success `-0.025/0.000`，plane miss 增加 `0.025/0.000`；
- 命令残差只有 `0.00289`，scale/rate clipping 为 `0.0`；
- 结论：zero-residual 机制 PASS，接口效果 FAIL。策略把残差压到近零，而不是用来修路径。

### R1：reward-v2 没有改变残差幅度

- success 与 B0 相同（`0.725/0.500`）；RMSE 改善仅 `0.00395/0.00393 m`；
- 命令残差仍为 `0.00264`；terminal/goal 项进入了 return，但没有进入确定性残差策略；
- 结论：reward-v2 单项 FAIL。

### H1：命令跟踪惩罚不是主因

- 把 `w_cmd_yaw/w_cmd_pitch/w_cmd_speed` 全部置零后，残差只升到 `0.00324`；
- RMSE `4.9625/4.9482 m`，相对 B0 改善 `0.0088 m`；success 不变；
- 结论：H1（command tracking 压过路径梯度）被证伪。继续降命令权重不是主线。

### G1：GAE 视野不是主因

- `gamma=0.999, lam=0.99, num_steps=256`；
- success `0.725/0.500`，RMSE `4.9687/4.9543 m`，残差 `0.00307`；
- 相对 B0 的配对 RMSE 差分别为 `+0.0023 m` 和 `+0.0023 m`（G1 略低，CI 跨零），
  residual 只比 R1 增加约 `16%`；
- 结论：H2（horizon 不足）被证伪。延长信用窗口没有把残差从零附近拉出来。

### A1：reward-v2 对 action residual 只有弱信号

- 相对 G26-P2，RMSE 改善约 `0.02 m`，但 success 为 `-0.025/+0.050`，plane miss 为
  `+0.025/-0.050`，residual/base L2 从约 `1.8%` 升到 `3.0%`；
- 这不是效果门禁通过，而是“残差变活跃但没有转化为稳定路径收益”；
- 不能拿 B0 的 `4.97 m` 作为 A1 的对照来夸大 A1；A1 的 base 已经是 D3。

## 10. 限制

- 每个 PPO 臂只使用一个训练 seed；C1/R1/H1/A1/G1 的训练 seed 不同，不能把极小的
  arm 间差异解释成稳定训练效应。
- 40-seed dev 的门禁统计只能说明 dev 上的效果；held-out 仍未打开。
- `command_residual_abs_mean` 是命令空间幅度，不是执行器 residual；A1 使用
  `residual_action_l2_mean`/`residual_to_base_l2_ratio_mean`。
- C1p 是 privileged upper bound，不是可部署策略；C1p zero 更好，禁止将其收益归因给
  residual。

## 11. Goal38 provenance correction

Goal38 定位到 `BatchedPCCommandResidualEnv` 在构造时缓存了 `env.path`，而底层
`reset()` 会把 `env.path` 重新绑定到 `path_bank[seed % 32]`。因此，经过
command-residual wrapper 的评估使用 stale path 0 计算 goal、goal tangent、
route tangent、path progress 和 path RMSE。

对本报告的影响：

- C1/R1 等 command-residual arm 的 path-derived metrics 不能作为 provenance
  一致的路径证据；若继续引用，必须先按相同 config/seed 重算或明确标注该限制。
- Goal38 的 fresh Goal31 重评证明 wrapper 修复不改变控制字段，但也没有把任何
  residual arm 提升为 PASS；本报告“停止命令残差主线”的总体裁决不因此改变。
- H3-SR 使用 `command_residual.enabled=false` 的 action-residual 路径，不受此
  wrapper stale path 影响，其 `H3_SR_FAIL` 结论保留。
- held-out `100-149` 仍未打开；本说明不授权重扫 reward、gamma/lambda、seed、
  terminal window、authority、pitch gain 或 lookahead。

详见 `doc/goals/goal38_result_20261109.md`。
