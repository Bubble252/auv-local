# Goal90 结果：PPO-only gate 消除 path 退化，但 PPO 增量仍弱

**日期**：2026-11-11<br>
**状态**：`PASS_RL_GAIN_WEAK / PG10_3_PREFERRED / NOT_FORMAL`<br>
**上游**：Goal90 protocol、Goal89 gate-scope 审计、Goal88 S1.25<br>
**性质**：1M screen；3 seeds；dev40；未打开 held-out，未换算法族。

## 1. 结论

Goal90 修正了 gate scope：

```text
ALOS + 1.25 * (r_BC + gate * r_PPO)
```

结果：

- default `31/31/31`，与 BC1.25 完全相同；
- strict125 `20/20/19`，相对 BC1.25 `19/19/19` 净 `+2/0`；
- path 相对 BC1.25 约 `0.000 m`（PG10_3 为 `-0.0004 m`），
  Goal88 无 gate 的 `+0.0213 m` 退化消失；
- strict125 plane-miss 在两个 gain seed 上 `0.525→0.500`；
- timeout `0`。

因此 Goal89 的 success 崩坏确认由 gate scope 造成；corrected gate 恢复了
BC 水平并保留了弱正的 PPO 增量。PPO 的贡献仍然只有 `+2/120`，
与 Goal88 无 gate 时相同；Goal90 的主要价值是**不再付出 path 代价**。

## 3. 与 Goal88 的对照

同为 `scale=1.25`、同一 BC checkpoint、同一 dev40：

| arm | strict125 | path Δ vs BC1.25 |
|---|---:|---:|
| Goal88 S1.25 no gate | 20/20/19 | +0.0213 m |
| Goal90 PG20_5 | 20/20/19 | +0.0019 m |
| Goal90 PG10_3 | 20/20/19 | -0.0004 m |

PPO 的 success 增量没有变，但 path 代价被 gate 隔离掉了。这说明 Goal89
的正确修复方向是 **gate only PPO increment**，不是换算法。
