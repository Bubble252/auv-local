# Goal75 结果：deadband bias correction 有强信号，但 strict125 正式 Gate 差 3 个样本

**日期**：2026-11-10<br>
**状态**：`PARTIAL_SUPPORT`<br>

## 1. 结论

```text
H75-A full oracle correction -> NOT SUPPORTED
H75-B deadband correction    -> default SUPPORTED, strict125 FAIL
overall                      -> PARTIAL_SUPPORT
decision                     -> continue to label-semantics audit
```

- full 修正能在两个 scenario 消掉全部 false-success，但会误伤大量
  true-success：default 只剩 `53/97`，strict125 只剩 `15/44`。full 修正过强。
- deadband `b0=0.25 m` 在两个 scenario 都把 false-success 降到 `0`，true
  retention 分别为 default `0.9588`、strict125 `0.9318`。default 通过
  `>=95%` Gate；strict125 差 3 个 true 样本，正式判 FAIL。
- 这不是“deadband 几乎没有效果”：strict125 只差 `3/44`，但预注册阈值不能
  事后放宽，所以整体只能记 `PARTIAL_SUPPORT`。
- 二次诊断（不是 Gate）发现：strict125 被误伤的 3 个 true 中，只有 1 个的
  true `eta` 在 tight radius 内；另外 2 个只在 protocol radius 内。也就是说，
  当前 `true_success` 标签把“协议半径内”误当成了“完美估计器在 tight 半径
  也会成功”。这需要在下一 Goal 单独审计，不能直接改本轮 Gate。

## 5. 二次诊断：标签语义混淆（不是 Gate）

Goal74/75 的 `true_capture` 使用 protocol radius（`2.00/1.25 m`），但
success 使用的是 tight radius（`1.75/1.00 m`）。因此一个 episode 可以同时
满足：

```text
success_none = True          # p_nav 在 tight radius 内
true_capture = True          # true eta 在 protocol radius 内
perfect_tight = False        # 但 true eta 在 tight radius 外
```

对现有 200 + 200 个 episode 做只读诊断：

| scenario | base true-success | 其中 eta 在 tight 内 | deadband 误伤 | 其中真正 tight loss |
|---|---:|---:|---:|---:|
| default | 97 | 59 | 4 | 0 |
| strict125 | 44 | 25 | 3 | 1 |

解释：

- default 的 4 个 deadband 误伤全部是“protocol 内、tight 外”；完美估计器
  本来也不会把它们判成 tight success；
- strict125 的 3 个误伤中，2 个是 protocol-only，1 个是真正的 tight
  success（seed 57，`d_e≈0.956 m`）；
- 因此当前 `true_success` 标签系统性偏宽：default 的 97 个里有 38 个、
  strict125 的 44 个里有 19 个只在 protocol radius 内。

这个诊断不改变 H75-A/H75-B 的正式裁决，但说明下一 Goal 不应继续调
deadband 阈值，而应先固定“成功标签到底用 tight 还是 protocol”。

## 6. 为什么不是 NoisyNet 或优化问题

- 正式评估使用 deterministic mean weights；NoisyNet 不采样；
- Goal59/63/70 已证明 mean-weight 饱和、zero-residual 仍复现 terminal 失败；
- 本轮 full/deadband 的效果完全来自 terminal `p_nav-eta` 的几何修正，不是
  exploration 或算法更新；
- 没有证据支持 SAC/REDQ/DroQ；GPUs 空闲不是换算法的理由。
