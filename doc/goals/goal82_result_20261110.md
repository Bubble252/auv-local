## 1. 结论

```text
H82-A  -> SUPPORTED
H82-B  -> NOT SUPPORTED
H82-C  -> SUPPORTED
H82-D  -> SUPPORTED
H82-E  -> NOT SUPPORTED
overall -> CHANNEL_GAIN_WITHOUT_OUTCOME
decision -> pivot to mapping / capture frame / terminal capture
```

最重要的三条事实：

1. `H82-A` 的支持来自 **command tracking error**，不是 residual 三通道的幅度。
   candidate 的 `tracking_error_heading` 在 default 和 strict125 都区分
   lost/retained；strict125 还包含 `tracking_error_pitch`。residual 的
   heading/pitch/speed `abs_mean` 几乎完全相同，不能区分 lost/retained。
2. `H82-B` 不支持。scale clip、rate clip 在四个 group 都是 `0`；
   material saturation 和 residual 方向 cosine 没有稳定的 lost/retained
   方向，且 baseline default 只有一个 lost，不能据此推广。
3. `H82-C` 支持，但机制是 **terminal outcome 只在 done 行激活**，而不是
   “terminal reward 在所有窗口都被 command tracking 淹没”。`reward_terminal`
   和 `reward_goal_plane_miss` 在 `100%` episode 中只在 done 行首次非零；
   preterminal 的 terminal_progress 仍然活跃。candidate 的 lost 在
   `terminal_progress` 上低于 retained，这与“到终端前已经失去捕获机会”一致。

因此，当前失败不能归因于“residual 幅度不够大”“NoisyNet 太强”或
“优化器不够好”。更准确的表述是：**policy 改善了对基座命令的跟踪，但该改善
没有转化为 terminal capture；当前证据指向动作/映射或捕获口径，而不是先换 reward
或算法。**

## 3. trace 对齐修正

实现审计发现：Goal71/Goal80 trace 中

```text
command_physical[t] == base_command[t+1]
```

但 `base_command[t]` 才是 residual[t] 施加前的当前步 ALOS 基座；
`command_physical[t]` 是执行动作后下一步观测到的命令。正确重建为：

```text
corrected_command[t] = base_command[t] + residual[t]
```

heading 使用 `wrap_pi`。原始分析器把 `command_physical[t]` 当作当前基座，
这是一个字段时序错误；修正后重跑同一 20 runs / 800 episodes。

修正前后主结论没有翻转：

| group | 指标 | 修正前 diff | 修正后 diff | 结论 |
|---|---|---:|---:|---|
| candidate/default | `tracking_error_heading` | `+0.436` | `+0.430` | 仍支持 |
| candidate/strict125 | `tracking_error_heading` | `+0.338` | `+0.330` | 仍支持 |
| candidate/strict125 | `tracking_error_pitch` | `+0.305` | `+0.302` | 仍支持 |

这是分析器字段选择的修正，不改变 H82-A/B/C/D/E、窗口、阈值、seed 或 eval
split。原始结果保留为 `goal82_pre_alignment_fix.json/md`；正式结果使用修正版。

## 4. H82-A：跟踪通道区分 lost/retained，但 residual 幅度不区分

### 4.1 residual 三通道幅度

`pre2s` 窗口的 residual `abs_mean` 中位数：

| root | scenario | heading lost | heading retained | pitch lost | pitch retained | speed lost | speed retained |
|---|---|---:|---:|---:|---:|---:|---:|
| baseline | default | 0.170 | 0.171 | 0.013 | 0.084 | 0.036 | 0.297 |
| baseline | strict125 | 0.171 | 0.171 | 0.083 | 0.084 | 0.296 | 0.297 |
| candidate | default | 0.170 | 0.171 | 0.084 | 0.084 | 0.297 | 0.296 |
| candidate | strict125 | 0.171 | 0.171 | 0.081 | 0.084 | 0.295 | 0.297 |

三通道幅度几乎没有差异。baseline default 的差别来自单个 lost episode，
不能作为机制证据。这与 Goal81 的结论一致：residual 幅度不是 lost 的稳定判别因素。

### 4.2 command tracking error

| default | `tracking_error_pitch` | 0.494 | 0.177 | +0.317 | +1.785 | [-0.064, 0.412] | no |
| default | `tracking_error_speed` | 1.118 | 0.512 | +0.606 | +1.183 | [-0.138, 0.743] | no |

| strict125 | `tracking_error_speed` | 0.395 | 0.480 | -0.085 | -0.177 | [-0.963, 0.629] | no |

关键 nuance：

## 8. 判定与下一步

### 8.1 假设裁决

| 假设 | 结果 | 理由 |
|---|---|---|
| H82-A：至少一个 action channel 区分 lost/retained | 支持 | candidate heading tracking 在两个 scenario 支持；strict125 pitch 也支持；但 residual 幅度不支持 |
| H82-B：residual 饱和/限幅/方向不一致 | 不支持 | clip 全为 0；material 和 direction 无稳定方向 |
| H82-C：terminal reward 太弱/太晚或被淹没 | 支持 | outcome 只在 done 激活；dominant group 仍是 command tracking；terminal_progress 在 lost 更低 |
| H82-D：policy 改善通道但不改善 outcome | 支持 | strict125 的 heading tracking 改善但 true success 更差；default 无通道改善 |
| H82-E：action 与 reward 都没有区分度 | 不支持 | H82-A/C/D 至少一个方向有证据 |

### 8.2 决策

```text
decision = pivot
```

下一步不是 reward arm，也不是 SAC：

1. 先查 mapping：residual 的基座、时序、符号、尺度、rate limit 和
   command→actuator 响应；
2. 再查 capture frame：guidance/reward/termination/success 是否使用同一个
   `p_nav`/`eta`、goal-tangent 或 path-local frame；
3. 最后查 terminal capture 的状态链路：actuator→state→p_nav/eta→capture 哪一环
   把 tracking 改善丢掉了；
4. 只有在 mapping/capture frame 已被证明一致后，才设计单因素 reward 或
   terminal objective arm；
5. 只有出现“residual 方向正确、但探索/样本效率不足”的直接证据，才开 SAC 对照；
   REDQ/DroQ 仍要求独立的样本效率证据。

训练型 arm 的前置条件不变：先做
`num_envs 128/256/512 × batch_size 256/512` 单卡吞吐基准，再按 seed 分 8 卡；
扩大采样/批量必须独立预注册。

## 9. 为什么神经网络没有打过传统方法

这不是“网络能力不够”这么简单。Goal82 的证据支持以下解释：

1. 传统 ALOS + PD/PI 已经是强基座。residual 只是有界修正；zero-residual
   仍能完成大部分 episode，学习模块的边际收益必须非常精确；
2. policy 改善的是 command tracking，而不是 terminal capture。strict125 的
   heading tracking 改善伴随 true success 下降，说明 proxy 与任务目标错位；
3. residual 的幅度和方向都不是 lost 的稳定判别因素，NoisyNet 也不是主因；
4. terminal outcome 在 done 行才激活，terminal_progress 虽然存在，但 lost
   的 terminal_progress 更低，说明失败更像是“到终端前已经失去捕获机会”；
5. 目前没有 optimization/exploration 或 sample-efficiency 证据。开 SAC 会把
   mapping/capture 问题与算法问题混在一起。

因此，当前最合理的结论是：**learned residual 尚未证明出超过 zero-residual
的 terminal 边际价值；瓶颈更可能在动作/捕获语义和 terminal approach，而不是
“神经网络不够大”。**
