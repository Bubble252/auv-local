# Goal128 结果：SAC 残差损伤来自动作参数化与近区几何，不是 reward farming

**日期**：2026-11-11<br>
**状态**：`COMPLETED_EVAL_ONLY / ACTION_PARAMETERIZATION / GEOMETRY_LIMITED / HELDOUT_CLOSED`<br>
**预注册**：`doc/goals/goal128_reward_terminal_credit_audit_20261111.md`<br>
**上游**：Goal126 `SAC_PA_HARM`；Goal127 `SAC_PA_SCALE_INSUFFICIENT`<br>
**性质**：只读 trace 审计；未训练、未换算法、未改 reward/terminal/success/goal radius。

## 1. 结论

Goal128 用同一批 8 个 1M checkpoint 跑了 34 条确定性 trace（zero 2 条、0.125 与 1.0
各 8 seed × 2 scenario），得到：

```text
失败不是 dense reward 被刷高，而是策略在近区把几何和 terminal capture 弄差了。
失败模式几乎全是 GOAL_PLANE_MISS，不是 TIME_LIMIT。
1.0 倍率下 learner 残差已经大于 frozen BC，raw policy 在近区 25%–82% 的步数贴 tanh 边界。
0.125 倍率把 learner 压到 BC 的 21%–27%，伤害变小但方向仍不反转。
只有 86201 在 1.0 获益（strict 24→30），它的近区饱和率最低（24.8%）。
```

因此本 Goal 的裁决是：

```text
primary   = ACTION_PARAMETERIZATION
secondary = GEOMETRY_LIMITED / TERMINAL_CAPTURE
reward    = 不是 SAC 相对 zero 退化的原因；terminal credit 只作为次级设计问题
```

按用户预注册规则，“残差方向对、只是探索/样本效率不足”没有被证明。相反，7/8 个
seed 的残差方向会把近区几何推坏。因此**不扩 SAC formal，不开 REDQ/DroQ，也不继续
扫 SAC 超参数**；下一步应做动作参数化与 terminal capture 的 eval-only 门控实验。

## 3. 网络结构对照

在解释 reward 前，先把当前 SAC 与历史 PPO/DDPG/BC 代码和 checkpoint 逐项对照。

| 谱系 | 实际特征布局 | 初始化 / 训练边界 | 结论 |
|---|---|---|---|
| Goal58/59 DDPG | NoisyLinear actor/critic | 评价 `sample_noise=False` | 旧线，不是当前 BC→PPO/SAC |
| Goal86 T2 SAC | `[z_t64, zero-DADE64, command3]` | path12 随机；无 BC encoder | 早期弱正向信号，不是 P-A |
| Goal86 P-A SAC | `[z_t64, zero-DADE64, command3]` | path8 BC encoder + endpoint4；`mu=0` | BC encoder/trunk 先验；无 action-level BC prior |
| Goal108 PPO residual | `[z_t64, command3, c_hat64]` | frozen BC + 可训练 path8/endpoint4；末层零初始化 | 特征列顺序与 SAC 不同 |
| Goal108 SAC | `[z_t64, zero-DADE64, command3]` | path12 随机、无 endpoint 分支 | 不能作为 SAC 算法对照 |
| Goal126/128 SAC | `[z_t64, zero-DADE64, command3]` | D3 `actor_command_dim=0` 的 state/path encoder + trunk；`mu=0` | 复现 Goal86 P-A，仍是 encoder/trunk prior |

代码事实：

1. `_actor_features_with_dade()` 实际返回 `[z_t, command, c_hat]`；PPO actor 第一层是
   `256×131`。SAC `PCStatePathFeatureExtractor.forward()` 返回
   `[z_t, zero_dade_slot, command]`，同样是 131 维。
2. D3 BC checkpoint 是 `actor_command_dim=0`、`actor_top_level_input_dim=128`，即 BC
   实际输入是 `[z_t64, DADE64]`。Goal126 初始化把 D3 第一层 128 列映射到
   `[z_t, zero_dade]`，新增的 3 个 command 列置零。
3. 因此 Goal126 的初始化 parity 成立；但这只说明“接线没接错”，不说明 PPO 与 SAC
   训练后的第一层权重可以按列语义逐元素比较。
4. 这不是 NoisyNet：当前 SAC 没有 `rho/sigma/noise` 参数，`mu=0`、`log_std=-3.0`；
   Goal59 的旧 DDPG NoisyNet 已由历史审计排除。
5. 近区饱和不是当前 SAC 独有：Goal58/59 DDPG 和 Goal108 PPO 都出现过动作贴界。
   这支持“动作参数化/优化 regime 是反复出现的问题”，而不是某次网络结构回归。

### 4.4 reward / terminal 分解

成功终点的 `reward_terminal = +300`；`GOAL_PLANE_MISS` 终点的
`reward_terminal = 0`，另有一次性的 `reward_goal_plane_miss ≈ -100`；safety 为 0。

这带来两个直接判读：

1. **没有 dense reward farming**。策略的 dense/step 比 zero 更负：
   0.125 为 -0.582、1.0 为 -0.632，zero 为 -0.577。按结果分层也一样：
   1.0 的 failure dense/step 为 -0.778、success 为 -0.497。策略不是靠 dense
   正项换取 terminal 失败，而是连 dense 回报也更差。
2. **失败不是 timeout 拖死**。zero strict 的 16 个失败全部是 plane-miss；
   0.125 的 138 个失败全部是 plane-miss；1.0 的 162 个失败中 160 个 plane-miss，
   只有 86204 的 2 个 timeout。`GOAL_PLANE_MISS` 的 terminal 为 0，miss penalty
   走独立的 `reward_goal_plane_miss`，因此“terminal 分量在失败时缺失”是事实，
   但它不是 SAC 相对 zero 退化的原因。

分析器的 provisional verdict 在这两组数据上都输出
`TERMINAL_CREDIT_MISSING`；这是启发式规则只检查 `terminal_share_failure < terminal_share_success`
造成的误报。成功有 +300、失败为 0，任何数据集都会满足这个不等式。正式判读以
逐 seed 配对和 dense/terminal 绝对值为主，不采用该 provisional 标签。

**eta / p_nav 对照**：每个 run 的 `success_count_eta_tight_at_done` 与
`success_count_pnav_tight` 完全相同，`success_frame_gap_eta_minus_pnav = 0.000`；
terminal eta 与 p_nav 距离通常只差 0.02–0.10 m。也就是说，本协议下成功/失败
不是由 p_nav 估计器单独造成的，eta 与 p_nav 给出同一判断。SAC 的问题不能归因于
“p_nav 比 eta 差很多”。

### 4.5 近区动作参数化（关键证据）

`goal_distance_eta <= 10 m` 内，把 trace 的 `action` 除以 eval multiplier 还原成
归一化 policy 输出；统计任一通道 `|u| > 0.95` 的步数比例。`‖L‖/‖B‖` 是纯 learner
残差与 frozen BC 残差的范数比（去掉 bias 和 gate 后）。

| train seed | 0.125 饱和率 | 1.0 饱和率 | 1.0 ‖L‖/‖B‖ | 1.0 eta_min | 1.0 strict success |
|---:|---:|---:|---:|---:|---:|
| 86201 | 37.4% | **24.8%** | 1.68 | **1.599** | **30** |
| 86202 | 55.2% | 60.1% | 1.88 | 2.021 | 21 |
| 86203 | 45.4% | 51.1% | 2.04 | 1.980 | 14 |
| 86204 | 63.8% | 78.0% | 2.00 | 2.057 | 17 |
| 86205 | 79.6% | 82.0% | 1.89 | 1.911 | 19 |
| 86206 | 64.9% | 72.2% | 1.98 | 2.171 | 19 |
| 86207 | 51.8% | 56.5% | 1.80 | 1.916 | 19 |
| 86208 | 70.6% | 72.5% | 2.07 | 1.972 | 19 |
| zero | — | — | — | 1.736 | 24 |

三点非常重要：

1. 0.125 的 applied action 很小，但 raw policy 输出仍然在近区 37%–80% 的步数贴
   tanh 边界；它不是“学会了温和修正”，而是“学会了 bang-bang 残差，只是被
   multiplier 压小”。
2. 1.0 的纯 learner 范数是 BC 的 1.5–2.3 倍，已经主导动作；pre64 eta 平均变差
   +0.317 m，terminal horizontal/vertical offset 也从 zero 的 `0.773/-0.127 m`
   退化为最多 `1.853/-0.786 m`。
3. 86201 是唯一在 1.0 同时做到“最低饱和率、近区 eta_min 最小（1.599 m）、
   vertical offset 接近 0（-0.039 m）”的 seed，因此它从 24 提升到 30。其他 seed
   的残差方向把 horizontal/vertical 推坏，属于方向与幅值同时有问题，而不是
   “方向对但样本不够”。

### 4.6 0.125 为什么也略伤

0.125 的纯 learner 只有 BC 的 21%–27%，但 5 个 seed 仍各丢 1–4 个 episode。
zero 的成功/失败边界非常窄：smoke 中 `success_margin_m_mean` 只有
`0.0088–0.0241 m`，zero strict 的 `eta_min` 均值也只有 1.736 m。厘米级扰动就足以
把个别 episode 从 GOAL 翻成 GOAL_PLANE_MISS，所以 0.125 的小幅负向是
“近区捕获过于刀口”的放大效应，而不是大幅动作饱和。

## 5. 假设裁决

| 假设 | 裁决 | 证据 |
|---|---|---|
| H128-A：失败被 dense reward 支配 | `FALSIFIED` | 策略 dense/step 更负；failure/success 分层后也没有 dense 正收益 |
| H128-B：terminal credit 只在成功时出现 | `PARTIAL / NOT_CAUSAL` | miss terminal=0、one-shot -100；但失败不是 timeout，且策略连 dense 都更差 |
| H128-C：terminal 前几何已决定失败 | `SUPPORTED_AT_1.0 / MIXED_AT_0.125` | 1.0 pre64 eta +0.317 m（CI 排除 0）；0.125 +0.053 m（CI 含 0） |
| H128-D：动作参数化/残差饱和是主因 | `SUPPORTED` | 近区饱和 24.8%–82.0%；1.0 learner/BC=1.5–2.3×；86201 饱和最低且唯一获益 |
| H128-E：没有稳定的 reward/terminal 缺陷 | `FALSIFIED_AT_1.0 / PARTIAL_AT_0.125` | 1.0 有稳定方向；0.125 效应小但 0 升/5 降 |

最终归因：

```text
ACTION_PARAMETERIZATION > GEOMETRY_LIMITED > TERMINAL_CREDIT_DESIGN > REWARD_SHAPING
```

## 6. 对 Goal126 的勘误

Goal126 结果 §3/§6 写“失败几乎都是 TIME_LIMIT”。Goal128 直接读取
`terminal_kind` 后确认：zero strict 的 16 个失败全部是 `GOAL_PLANE_MISS`；
1.0 只有 86204 的 2 个 strict episode 是 `TIME_LIMIT`。

这不改变 Goal126 的 success 计数或 `SAC_PA_HARM` 结论，只更正失败模式描述。
已在 `scripts/evaluate_pc_sac.py` 的 summary 中加入 `terminal_kind_counts`，
后续 run 不再需要靠 `timeout` 字段猜 terminal 原因。

## 7. 决策与下一步

```text
不扩 SAC 5M formal
不换 REDQ/DroQ
不继续扫 SAC lr/UTD/entropy/scale
不改 reward/terminal/success/goal radius
不打开 held-out
```

下一步是 eval-only 的**动作参数化 screen**，仍复用这 8 个 checkpoint：

1. `inverse terminal gate`：learner 残差在 10 m 外为 1、3 m 内为 0，把近区捕获交回
   frozen BC；fixed bias 保持不变。
2. `norm cap`：限制 `||L|| <= α ||B||`，先测 `α = 0.25`。
3. 两者组合。
4. 对照：zero、0.125、1.0 unmodified。

预注册判读：

| 观察 | 判读 | 下一步 |
|---|---|---|
| 1.0 + gate/cap 的 strict 均值 ≥25.5、default ≥33，且 ≥4/8 seed 提升 | `ACTION_PARAM_GAIN` | 用该参数化开 1M 训练型 Goal |
| strict ≥24、default ≥33，且没有 seed 丢超过 1 个 episode | `ACTION_PARAM_SAFE_PARITY` | 只允许用该参数化做训练 screen，不扩 formal |
| 仍低于 zero 或无稳定变化 | `ACTION_PARAM_NO_EFFECT` | 转 terminal capture/approach geometry，不改 reward |

只有在参数化 gate 通过后，才讨论是否用 SAC 训练同一协议；当前证据不支持
“残差方向对、只是探索/样本效率不足”，因此不满足开 SAC 对照的条件。
