# Goal112 结果：pre-entry 失败主要受 tracking 限制，且以 pitch 跟踪为主

**日期**：2026-11-11<br>
**状态**：`COMPLETED_AUDIT_ONLY / TRACKING_LIMITED / HELDOUT_CLOSED`<br>
**上游**：Goal111 `PREENTRY_GEOMETRY_BAD_MAJORITY`；Goal110 terminal event censoring；Goal108/89 网络 parity 审计<br>
**性质**：只读 Goal107 dev40 trace；未训练、未改 reward/terminal/success/goal radius，未打开 held-out。

## 1. 结论

按 Goal112 冻结 Gate，正式判读为：

```text
TRACKING_LIMITED
reason = frozen_50pct_reference_tracking_gate
```

strict125 C0 的 11 个 `PREENTRY_GEOMETRY_BAD` failure 中：

| 类别 | 数量 | 比例 | 含义 |
|---|---:|---:|---|
| `REFERENCE_BAD_ONLY` | 1 | 9.1% | command 已偏离 goal LOS，tracking 尚可 |
| `TRACKING_BAD_ONLY` | 6 | 54.5% | command 对 goal 合理，但实际 eta 跟不上 |
| `MIXED_REFERENCE_AND_TRACKING` | 2 | 18.2% | reference 与 tracking 都坏 |
| `ALIGNED_CONTROL_POSITION_OFFSET` | 2 | 18.2% | 控制方向基本对齐，但位置偏移已形成 |

合并后：

```text
reference involved = 3/11 = 27.3%
tracking involved  = 8/11 = 72.7%
```

因此 H112-B 成立，H112-A/H112-C/H112-D 不成立。当前 pre-entry 失败**不是主要由
guidance/reference 指错方向造成**，而是多数 failure 的实际姿态没有跟上 command。
但 3/11 仍涉及 reference，2/11 是 aligned-control position offset，所以不能写成
“所有 failure 都是纯 tracking 问题”。

## 3. 分通道证据

在 11 个主分析 failure 的 entry 2 m 窗口中：

| 通道 | 越界数 | 阈值 | 说明 |
|---|---:|---:|---|
| `tracking_pitch` | 7/11 | `0.45 rad` | 最强单一信号 |
| `tracking_heading` | 3/11 | `0.35 rad` | 部分样本同时 heading lag |
| `reference_heading` | 3/11 | `0.35 rad` | command heading 对 LOS 偏离 |
| `reference_pitch` | 0/11 | `0.45 rad` | command pitch 对 LOS 没有单独越界 |

因此“tracking involved = 8/11”并不是一个均匀的姿态问题：

```text
tracking pitch bad   = 7/11
tracking heading bad = 3/11
两者同时 bad          = 2/11
```

tracking pitch 是主导通道，但仍有 3 个样本的 failure 与 reference heading 或
aligned-control position offset 有关。

|---|---:|

## 5. 与历史网络结构/代码的对照

用户要求把网络结构问题与之前的代码和历史实验比对。Goal112 复核后确认：

```text
network_wiring_bug        = false
noisenet_dominant         = false
ppo_zero_increment_parity = true
frozen_bc_tensor_parity   = true (Goal89/104: 22/22 torch.equal)
```

具体对照：

| 项目 | 历史/当前证据 | 对 Goal112 的含义 |
|---|---|---|
| NoisyNet | Goal108 扫描当前 PPO/SAC checkpoint，无 `rho/sigma/noise` 参数；Goal59 的旧 DDPG NoisyNet 不是当前谱系 | 不能把 tracking pitch 失败归因 NoisyNet |
| PPO state encoder | Goal108 中 PPO 与 SAC 的 `actor_encoder` 3/3 层 `torch.equal` | state encoder 没有随机种子错位 |
| frozen BC | Goal89/104 的 22 个 `frozen_bc_*` tensor 与 Goal86 P-A BC `max_abs_diff=0.0` | 不是 BC 接线或隐藏层宽度错位 |
| Goal108 SAC path | SAC 使用 `bc_path_dim=12` + 随机 path encoder + `bc_checkpoint=null`；Goal86 P-A SAC 是 `path8 + endpoint4 + BC encoder` | SAC 与 PPO 并非完全同构，不能把 Goal108 的 SAC 退化写成纯优化器差异 |
| Goal89 gate scope | 旧训练的 gate 错误地同时关掉 `r_BC` 与 `r_PPO`，评估器只 gate `r_PPO` | 该问题已在 Goal89 修复；Goal112 的 trace 来自 Goal95/Goal107 的冻结 checkpoint，不继承旧 gate bug |

因此，Goal112 的 `TRACKING_LIMITED` 不能被解释为“网络没接对”或“NoisyNet 在主导”。
如果后续要重新开 SAC 对照，必须先固定 `bc_path_dim=8 + endpoint4`，并明确是否加载
BC encoder；否则优化器比较仍然混入 path 参数化和初始化差异。

## 6. 判读边界

- `reference` 是 command heading/pitch 对 direct goal LOS，不是对 ALOS 内部参考的完整复现；
- `tracking` 是 command 对实际 eta yaw/pitch，不包含执行器到 eta 的完整动力学分解；
- 本 Goal 只做 entry 窗口的 5 帧统计，不把相关性写成因果；
- onset shell 只作描述，不改变主分类；
- strict U050 的 9 个 pre-entry bad failure 中 reference/tracking 各参与 5/9，只作重复性描述，
  不参与主 Gate 改判；
- 不打开 held-out，不修改 success/goal radius/terminal/reward。

## 7. 决策

`decision = pivot`

不是因为算法族需要更换，而是因为失败机制已经从“terminal capture / reward credit”
推进到“pre-entry pitch tracking”：

```text
下一步 = Goal113 eval-only pitch tracking / authority / rate 归因审计
```

Goal113 仍然只读，不训练、不改动作参数化、不改 reward/terminal/success、不打开
held-out。只有在 Goal113 明确证明“残差方向正确，但探索或样本效率不足”后，才值得
新开预注册的 SAC 同协议对照；如果 Goal113 指向 authority/rate 或动力学耦合，则优先
修 controller/参数化/plant mismatch，而不是换 RL 算法。
