# Goal66 结果：terminal command 与速度不能区分 capture 丢失

**日期**：2026-11-10<br>
**状态**：`TERMINAL_GEOMETRY_UNRESOLVED`<br>
**预注册**：`doc/goals/goal66_terminal_estimator_command_audit_20261110.md`<br>
**上游**：Goal27 `H3_SR_FAIL_STOP`、Goal64 `GEOMETRY_SUPPORTED`、Goal65 `DWELL_NOT_SUFFICIENT`

## 1. 协议与完整性

Goal66 是只读审计，没有训练、没有新增 rollout，也没有改变 controller、reward、
checkpoint、GOAL 半径、plane guard 或 dwell。直接复用：

- baseline：Goal60 的 10 个 dev trace，seeds `20–59`；
- candidate：Goal65 的 4 个 checkpoint × `default/strict125` × policy，加 2 个
  forced zero-residual；
- window：每个 candidate episode 最后 51 行，对应 dwell=50 的完整窗口；
- 最近点：窗口内 true `eta` 到 goal 距离最小的 step；
- 精度 / 终止：CPU / float64 / `endpoint_stop`；
- held-out `100–149` 关闭。

分析器同时校验 baseline/candidate 的 checkpoint SHA、seed 列表、finite、eval
半径、plane-guard 半径、dwell、trace metadata、action mode 和 command 有限性。
`dwell=0` 等价性已由 Goal65 单独验证，本 Goal 没有重复 rollout。

## 2. 主结果

### 2.1 H66-A：`p_nav` 估计器单独截断 true capture

预注册支持条件：lost true 中 `p_nav-only` fraction `>= 0.50`。

| scenario | lost true | eta entered tight | p_nav entered tight | p_nav-only | 判定 |
|---|---:|---:|---:|---:|---|
| default | 9 | 2 | 0 | `2/9 = 0.222` | 不支持 |
| strict125 | 7 | 3 | 0 | `3/7 = 0.429` | 不支持 |

strict125 最接近阈值，但在预注册 pooled 口径下没有过线。若只看 policy、排除
zero-residual，strict125 是 `3/6 = 0.500`；这是事后敏感性，不改变 Gate 判定。
它说明“估计器进入限制”只能解释一部分 policy lost episode，不是统一机制。

### 2.2 H66-B：terminal command 没有朝向真实 goal

预注册支持条件：lost LOS cosine median `< 0.95`，且 retained - lost `>= 0.05`。

| scenario | lost LOS cos | retained LOS cos | retained - lost | lost heading err | 判定 |
|---|---:|---:|---:|---:|---|
| default | `0.977` | `0.975` | `-0.002` | `0.244 rad` | 不支持 |
| strict125 | `0.982` | `0.948` | `-0.033` | `0.185 rad` | 不支持 |

丢失组的 corrected command 已经高度朝向真实 goal，而且两组差异方向相反。
strict125 有一个 `s1008/seed23` 的 LOS cosine `0.768`、heading error `1.366 rad`
反例，但它是 `p_nav-only` episode，且中位数不由它主导。

### 2.3 H66-C：terminal speed command 没有收敛

预注册支持条件：lost speed-command ratio median `>= 0.75`，且 lost - retained
`>= 0.10`。ratio 是 corrected speed command 除以 episode 初始 base speed command。

| scenario | lost speed ratio | retained speed ratio | lost - retained | 判定 |
|---|---:|---:|---:|---|
| default | `1.000` | `1.090` | `-0.090` | 不支持 |
| strict125 | `1.095` | `1.127` | `-0.031` | 不支持 |

lost 与 retained 都没有明显的 terminal speed decay，retained 甚至更高。因此
“速度指令没下降”是两组共有的现象，不能解释为什么只有一组丢失 capture；它也不是
当前 Gate 下的充分原因。

### 2.4 总判定

```text
default   -> TERMINAL_GEOMETRY_UNRESOLVED
strict125 -> TERMINAL_GEOMETRY_UNRESOLVED
overall   -> TERMINAL_GEOMETRY_UNRESOLVED
```

A/B/C 均未按预注册阈值支持。继续在 `p_nav` 校准、command 方向或速度指令上做
单因素补救，缺乏当前证据；下一步应转向执行器/动力学可达性和终局几何。

## 4. 对“residual 是否被 NoisyNet 主导”的回答

当前证据不支持 NoisyNet/residual 主导：

1. 正式评估使用 `agent.act_batch(..., evaluate=True)`，该路径设置
   `sample_noise=False`，NoisyNet 噪声不会在评估轨迹中采样；
2. Goal64 已显示 strict125 lost/retained 的 residual L2 中位数几乎相同，
   `0.351` 对 `0.352`，scale/rate clip 均为 0；
3. Goal66 的 lost 组 corrected command LOS cosine 为 `0.977/0.982`，没有出现
   噪声把动作推离 goal 的特征；
4. forced zero-residual 仍有 `4` 个 default、`1` 个 strict125 true-loss，且
   terminal `p_nav` 同样停在球外；
5. 丢失与保留的主要差异仍是 true `eta` / `p_nav` 的终端距离和 plane-crossing
   几何，而不是 residual 幅度、command 方向或速度指令分布。

因此，加大/缩小 residual、关闭 NoisyNet、换 SAC/REDQ/DroQ 都不是当前失败的直接
修复。若后续出现明确的 optimization/exploration 或 sample-efficiency 证据，才按
预注册另开对照。

## 5. Reward 复核

reward 只做描述性复核，不单独设 Gate：

| scenario | group | plane-miss sum median | plane-miss nonzero steps | plane-miss last share | terminal bonus median |
|---|---|---:|---:|---:|---:|
| default | lost | `-109.48` | `1` | `1.000` | `0` |
| default | retained | `0` | `0` | `0` | `300` |
| strict125 | lost | `-112.97` | `1` | `1.000` | `0` |
| strict125 | retained | `0` | `0` | `0` | `300` |

lost 组的 plane-miss penalty 仍然只在最后一帧出现；terminal bonus 只在 retained
最后一帧触发。`terminal_progress` 在 51 帧内都有值，但 lost 组最后一帧的中位数为
负（default `-0.049`、strict125 `-0.069`），retained 为正（`0.066/0.082`）。

这与“终局事件捕获滞后、接近过程最后仍在远离”一致，但 reward 是结果的一部分，
不能仅凭该相关性宣称 reward 是因果主因。下一步的可达性审计会把它作为约束，而不
通过扫 reward 权重来救 Gate。

## 6. 决策与下一步

`decision = pivot`：停止 terminal estimator/command 的单因素轴，不扫 calibration、
heading gain、speed profile 或 reward 权重。按预注册规则，A/B/C 均不支持时转向
执行器/动力学 reachability。

下一步只提议一个新预注册 Goal67，优先做只读/低成本反事实：

1. 在最近 true-`eta` 点估计剩余横向/垂直修正量与可用转向、俯仰、深度速度包络；
2. 检查 command 已在可行包络内但实际状态跟不上时的 controller lag/rate limit；
3. 若可达性充足但仍错过，再检查 capture-region 几何和 terminal target 选择。

不启动 SAC/REDQ/DroQ；不重开 Goal27 的 residual/reward/gamma/seed 搜索；held-out
`100–149` 保持关闭。
