# Goal99 结果：距离调度失败，terminal 退化发生在 2 m 之前

**日期**：2026-11-11<br>
**状态**：`SCHEDULE_NOT_SUPPORTED / TERMINAL_DEGRADATION_PRECEDES_2M / NO_SAC`<br>
**上游**：Goal98 `SCALE_PARTIAL / TERMINAL_DIRECTION_REMAINS_BOTTLENECK / NO_SAC`<br>
**性质**：eval-only、冻结 Gate；未训练、未改 reward/terminal/success/goal radius，未打开 held-out。

## 1. 结论

Goal99 预注册的三个距离调度全部失败：

```text
S20       near 1.50 / far 2.00 / switch 2.0 m
S25       near 1.50 / far 2.00 / switch 2.5 m
S20-N175  near 1.75 / far 2.00 / switch 2.0 m

Gate = SCHEDULE_NOT_SUPPORTED
```

三个 schedule 的成功率与 constant 2.00 **逐 seed 完全一致**：

- default：D3 `31/40`、BC15 `32/40`；
- strict125：两臂都 `18/40`；
- strict 仍低于 frozen `20/40`；
- 相对 constant 2.00，四个 group 的 gained/lost 都是 `0/0`；
- path 3D RMSE 相对 constant 1.50 约 `1.014×`，timeout/safety 为 `0`；
- trace 边界错配为 `0`，所有 schedule 字段和 seed 集合有效。

因此：**在 2 m 内把 scale 退回 1.50 或 1.75 不能修复 strict capture**。2.00 造成
的 strict 退化已经在更早的接近段形成；只在最后 2 m 改幅度太晚。

- dev seeds：`20–59`，每个 run 40 episodes；

- checkpoint SHA 与 Goal95 final 一致；
- success frame 固定 `both`；
- held-out `100–149` 未打开；
- 12 个 run 全部有 `summary.json` 和 `trace.npz`；

  逐 step 满足冻结边界；
- 调度距离是 step 前距离，避免用 step 后位置误判跨线样本。

## 4. 终端闭合机制

### 4.1 逐 seed 翻转

相对 constant 1.50：

| group | gained | lost |
|---|---|---|
| D3 default | 27, 49 | 59 |
| BC15 default | 27, 49 | — |
| D3 strict125 | 44 | 22, 29 |
| BC15 strict125 | 44 | 22, 29 |

相对 constant 2.00：

```text
所有 group: gained = [], lost = []
```

这说明 schedule 没有产生新的闭环行为，只是复现了 constant 2.00。

### 4.2 strict 边界 seed 的 closure

从 trace 计算 radial closure，单位 `m/s`：

| group/seed | 1.50 `2–1.25` | 2.00 `2–1.25` | S20 `2–1.25` | 结果 |
|---|---:|---:|---:|---|
| D3 22 | 1.022 | 0.662 | 0.668 | success → miss，未恢复 |
| D3 29 | 0.992 | 0.419 | 0.420 | success → miss，未恢复 |
| D3 44 | 0.305 | 2.034 | 2.035 | miss → success，保持 |
| BC15 22 | 1.052 | 0.681 | 0.693 | success → miss，未恢复 |
| BC15 29 | 1.345 | 0.564 | 0.590 | success → miss，未恢复 |
| BC15 44 | 0.210 | 2.042 | 2.043 | miss → success，保持 |

final distance 也一致：

| group/seed | 1.50 final | 2.00 final | S20 final |
|---|---:|---:|---:|
| D3 strict 22 | 1.237 | 1.344 | 1.338 |
| D3 strict 29 | 1.249 | 1.702 | 1.702 |
| BC15 strict 22 | 1.237 | 1.337 | 1.340 |
| BC15 strict 29 | 1.242 | 1.588 | 1.583 |

所以 S20 在 2 m 内虽然已经切到 1.50，却几乎完全保留了 2.00 的失败轨迹。
strict seed 22/29 的损失不是“最后 1 m 的幅度过大”，而是**进入 2 m 前的
terminal residual/轨迹已经把后续 capture 几何破坏**。

### 4.3 为什么切换距离不是主因

- S25 比 S20 更晚切换，strict 仍 18/40；
- S20-N175 的近场幅度更大，strict 仍 18/40；
- 三者与 constant 2.00 的逐 seed 结果完全相同；
- far fraction 高达 `96.8%–99.9%`，说明大部分控制步本来就在远场。

继续扫 1.5/2.5/3.0 m 的 switch 没有证据支持，不应继续做。

## 6. 裁决

| 维度 | 结果 | 依据 |
|---|---|---|
| Schedule | `SCHEDULE_NOT_SUPPORTED` | 三个 schedule 全部等同 constant 2.00 |
| Capture | strict 仍 18/40 | 低于 frozen 20/40 |
| 机制 | failure precedes 2 m | near 切回 1.50 无法恢复 22/29 |
| 算法 | `NO_SAC` | 没有“方向正确、样本效率不足”的证据 |
| 下一步 | terminal direction / prior preservation | 不再扫 switch 或 scale |

## 7. 下一步

不换算法，不继续扫 scale/switch。下一步应预注册一个只读或最小干预的
**terminal PPO prior-preservation** 实验：

1. 用 Goal95 final checkpoint，评价“近场关闭 PPO 增量、保留 frozen BC”
   的配对反事实；
2. 对比 PPO 全开、PPO 在 3/2/1.25 m 内关闭三种 profile；
3. 检查 strict 22/29 是否能恢复到 frozen 的 20/40，default 是否保持 31/32；
4. 若近场关闭 PPO 能恢复 BC，下一步训练只加 terminal PPO attenuation /
   prior-preservation 约束；
5. 若仍不能恢复，则问题在 BC/ALOS 的 capture 几何或终末观测，不在 PPO 算法。

只有出现“PPO 方向正确但样本效率不足”的证据时，才重新评估 SAC/REDQ/DroQ。
