# Goal102 结果：PPO 剂量从第一步起就伤害 BC 先验

**日期**：2026-11-11<br>
**状态**：`PPO_DOSE_HARM / EVAL_ONLY / NO_TRAINING`<br>
**上游**：Goal101 `BC_PRIOR_BEATS_ALOS`<br>
**性质**：冻结 Gate 的 eval-only 剂量-反应；未训练、未改 reward/terminal/success/
goal radius，未打开 held-out。

## 1. 结论

Goal95 训练轨迹上，五个 checkpoint 的 dev40 结果：

| dose | checkpoint | P_D3 default | P_D3 strict | P_BC15 default | P_BC15 strict |
|---|---|---:|---:|---:|---:|
| `I0` | `model_initial` | 32 | 20 | 32 | 20 |
| `D25` | `model_10` | 32 | 19 | 32 | 19 |
| `D50` | `model_20` | 32 | 18 | 31 | 18 |
| `D75` | `model_30` | 32 | 18 | 32 | 18 |
| `D100` | `final` | 31 | 18 | 32 | 18 |

B20 为两臂 `33/20`。Gate 判：

```text
PPO_DOSE_HARM
```

没有任何 checkpoint 同时满足 default `>=33`、strict `>=21`。更关键的是：

- `I0` 已经只有 `32/20`，比 B20 少 default seed 26；
- `D25`（约 250k PPO transitions）strict 从 20 降到 19，丢 seed 24；
- `D50/D75` strict 降到 18，丢 seed 22/24；
- `D100` default 再丢 seed 26/59，strict 仍是 18。

因此不是“训练不够久”或“最终 checkpoint 选错”。**当前 PPO 更新从最小剂量
开始就在破坏先验**。

## 2. 协议与有效性

- dev seeds `20–59`，每 run 40 episodes；
- two arms × two scenarios × five checkpoints = 20 个新 eval run；
- `action_mode=policy`，完整 PPO 增量；
- residual scale 固定 `2.00`；
- success frame `both`；
- checkpoint SHA 全部与 Goal95 冻结值一致；
- B20 复现 `33/20`，ALOS 复现 `27/14`；
- 所有 run 有 `summary.json` 与 `trace.npz`；
- timeout/safety 全 0；
- held-out `100–149` 未打开。

## 5. 判读

1. **不是样本效率问题**：最小 PPO 剂量已经伤害 strict，继续训练只会更差。
2. **不是 checkpoint 选择问题**：五个剂量里没有可用窗口。
3. **不是 path tracking 主因**：path 只变化 0.2–0.3%，success 却下降 1–2 个。
4. **是终端 capture / credit assignment 问题**：同样的轨迹质量下，PPO
   增量改变了 goal-plane 附近的离散成败。
5. **supervised residual prior 也不优于 B20**：`I0` 是 32/20，B20 是 33/20；
   当前 PPO 训练起点本身没有贡献，真正强的是 frozen BC + scale 2.00。
6. 因此不能把“再训练久一点”或“选早期 checkpoint”作为下一步；必须先做
   B20 strict 失败审计，再决定是否存在可控的 bounded PPO 方向。

## 6. 裁决

| 维度 | 结果 | 依据 |
|---|---|---|
| Gate | `PPO_DOSE_HARM` | 无 checkpoint 达到 `33/21` |
| 样本效率 | `NOT_SUPPORTED` | 最小剂量 D25 已从 20 降到 19 |
| checkpoint 选择 | `NO_WINDOW` | I0/D25/D50/D75/D100 全部低于 B20 |
| path | `NEAR_CONSTANT` | ratio 约 1.003 |
| Safety | `PASS` | timeout/safety 全 0 |
| 算法 | `NO_SAC` | 不是探索不足；先验保持才是主线 |

`decision = pivot`

## 7. 下一步

先做 **Goal103：B20 strict 失败的动作参数化与 terminal capture 审计**，
不立即训练新算法：

- 对 B20 的 20 个 strict 失败 seed，检查是否进入 goal radius 邻域、
  goal-plane miss 的横向/纵向分量、final distance 壳层；
- 检查 actuator saturation、rate clip、terminal gate 是否吞掉有效修正；
- 检查失败是否集中在少数几何模式，以及 ALOS/BC 的分工是否导致终端过冲；
- 只有在审计证明“存在可用动作方向，但当前 PPO 目标/约束无法表达”时，
  才预注册硬约束的 prior-preserving PPO；
- 不打开 held-out，不改 success/terminal/goal radius；
- 不开 SAC/REDQ/DroQ。
