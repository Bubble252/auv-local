# Goal159 结果：训练协议无效，旧 1M checkpoint 作废

**日期**：2026-11-12<br>
**状态**：`INVALID_TRAIN_DIRECT_COMMAND / SUPERSEDED_BY_GOAL159C / HELDOUT_CLOSED`<br>
**结论**：旧 Goal159 的 3 个 1M SAC checkpoint **不能作为 H3 + current07–10 的残差 screen 证据**。训练实际走的是 C0 direct-command 脚手架，不是 ALOS 路径跟踪；旧 eval 和 scale 剂量结果全部降级为 `INVALID`，不改写成 FAIL，也不据此判断算法或 reward。

## 1. 无效证据

旧训练 manifest 显示：

| 项目 | 旧值 |
|---|---|
| 环境配置 SHA | `cdc2718bbc81a3c9934314ff5fd16ed313164765b7d797b45890eec701322c6d` |
| `pc_stage` | `C0` |
| `curriculum.enabled` | `false` |
| `curriculum_direct_commands_enabled` | `true` |
| `reward.hold_bonus` | `true` |

`BatchedPCLowLevelEnv` 的运行时定义是：

```python
direct_commands = (
    stage in {"C0", "C1"}
    and pc_control_mode == "alos"
    and curriculum_direct_commands_enabled
)
```

因此旧三批训练的 `direct_commands_active` 实际为 `true`。训练完成的 episode
success 只有 `26 / 27 / 23`（分别约 `712 / 718 / 686` episodes），也与
“随机 direct command + C0 hold bonus”一致，而不是沿参考路径学习。

旧训练结果：

| seed | transitions | completed episodes | success episodes |
|---|---:|---:|---:|
| `86201` | `1,000,192` | `712` | `26` |
| `86202` | `1,000,192` | `718` | `27` |
| `86203` | `1,000,192` | `686` | `23` |

旧 eval 表（current07 `108/120` 等）虽然评测入口关闭了 direct command，但
checkpoint 是在错误训练分布上得到的，不能归因于“残差学到了路径修正”。旧 scale
剂量同样建立在错误 checkpoint 上，不能用来判断幅度是否是瓶颈。

## 2. 正确修复

新增 `Goal159c` 修正版：

- `pc_stage=C3`，使用 ALOS 路径跟随；
- `hold_bonus=false`，与 C2–C6 的固定路径训练语义一致；
- `curriculum.enabled=false`，不启用 C0/C1 训练脚手架；
- H3 控制器、current `[0.275, 0.55] m/s`、near10_2 gate、goal radius `2.0 m`
  保持 Goal159 原意；
- 训练 manifest 新增 `direct_commands_active`，smoke 已验证为 `false`。

修正配置与训练入口：

- `configs/lowlevel/goal159/env_h3_current07_10_train_c3.json`
- `configs/lowlevel/goal159/train_c3_seed86201.json`
- `configs/lowlevel/goal159/train_c3_seed86202.json`
- `configs/lowlevel/goal159/train_c3_seed86203.json`
- `scripts/build_goal159c_configs.py`
