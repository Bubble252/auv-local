## 1. 结论

```text
H81-A guard not preemptive    -> SUPPORTED: guard 不是抢跑
H81-B deployable capture rule -> NOT SUPPORTED: 没有可推广的 policy 规则
H81-C p_nav/eta capture frame -> SUPPORTED in default; strict125 mixed

overall                       -> MIXED_ACROSS_SCENARIOS
mainline decision             -> pivot to action parameterization / reward audit
```

最重要的三条事实：

1. 所有 lost 都是 `GOAL_PLANE_MISS`，100% 从未进入 `r_tight`；
2. lost 在终止前约 `0.88–1.36 s` 已经过最近点，随后外离
   `0.60–1.25 m`，最后一秒斜率仍为正；`dwell=50` 已经等满，guard 不是
   “刚到平面就终止”；
3. lost/retained 的 deterministic residual L2 比值只有 `1.10–1.32`，且
   zero-residual 仍有 `14` 个 lost，crossing geometry 100% 同向；残差幅度和
   NoisyNet 不是主因。

因此当前不应改 plane-miss guard、dwell 或 capture radius；下一步应查动作参数化、
reward 和 pre-crossing approach。SAC 仍不启动：没有“残差方向对但探索/样本效率
不足”的证据。

### 3.1 H81-A：guard 不是抢跑

四个 group 全部满足预注册支持条件：

- `GOAL_PLANE_MISS` 占 lost 的 `100%`；
- `p_nav` 进入 tight radius 的比例为 `0%`；
- receding 比例 `0.905–1.000`，没有 closing/near-miss 到被终止的 episode；
- `dwell_observed` 中位数都是 `51` 步，说明终止发生在连续满足 plane-miss
  条件 50 步之后，不是 crossing 当步。

最近的 lost episode 确实会非常接近 `r_tight`：candidate default 有 `42.9%`
的 lost 最小余量 `<=0.10 m`，baseline default 为 `16.7%`。但它们不是“停在门口
等待捕获”，而是过最近点后继续外离：

| root | scenario | min-to-done median | d_done - min p_nav | last-1s slope |
|---|---|---:|---:|---:|
| baseline | default | 1.16 s | 0.998 m | +0.890 m/s |
| baseline | strict125 | 1.24 s | 0.861 m | +0.844 m/s |
| candidate | default | 1.36 s | 1.247 m | +1.134 m/s |
| candidate | strict125 | 0.88 s | 0.595 m | +0.583 m/s |

所以 `dwell=50` 不是不够长：在终止前最后一秒，轨迹仍以 `0.58–1.13 m/s`
外离。继续等、放宽 guard 或改 capture radius 不会把已经外离的轨迹变成闭环捕获；
只会把“掠过时离目标多远”写进 success 定义。

### 3.2 H81-B：没有可推广的 policy capture 规则

`R_cross_tight` 在四个 group 都是 `0` 恢复：lost 在 crossing 时已经全部
`d_cross > r_tight`。这是对“crossing 当步用 tight radius 捕获”的直接否定。

`R_cross_guard` 的增量结果：

| root | scenario | recovered lost | policy recovered | zero recovered | new false | additive false delta | precision | recall | usable |
|---|---|---:|---:|---:|---:|---:|---:|---:|---:|
| baseline | default | 3/6 | 0/1 | 3/5 | 0 | 0.000 | 0.857 | 0.171 | yes* |
| baseline | strict125 | 5/7 | 4/6 | 1/1 | 13 | 0.065 | 0.350 | 0.233 | no |
| candidate | default | 6/21 | 4/15 | 2/6 | 4 | 0.020 | 0.750 | 0.171 | no |
| candidate | strict125 | 2/9 | 1/7 | 1/2 | 6 | 0.030 | 0.357 | 0.167 | no |

`*` baseline default 的“usable”只恢复 zero-residual 的 `3/5`，没有恢复唯一的
policy lost；它的 recall 只有 `0.171`，不能当作 policy 修复。baseline strict125
虽然恢复 `5/7`，但新增 `13` 个 false，超过预注册 `+0.05` 的门槛。

candidate 两个 scenario 的恢复率只有 `28.6%` 和 `22.2%`，低于 `40%`。因此
**没有可推广到 policy 的 crossing-capture 规则**；放宽半径只是在 true/false
之间重新分配标签，和 Goal74 的 margin 结论一致。

`R_eta_tight_ever` 作为 oracle upper bound 可以恢复 baseline default `4/6`、
strict125 `2/7`、candidate default `9/21`、candidate strict125 `1/9`，但它需要
true `eta`，不可部署，不能写成 capture 规则的结果。

### 3.3 H81-C：default 的 p_nav/eta 捕获帧差异是真实次级因素

| scenario | root | pooled eta tight | policy eta tight | policy eta tight before cross | cross gap |
|---|---|---:|---:|---:|---:|
| default | baseline | 0.667 | 1.000 (1/1) | 1.000 | 0.324 m |
| default | candidate | 0.429 | 0.533 (8/15) | 0.238 | 0.257 m |
| strict125 | baseline | 0.286 | 0.333 (2/6) | 0.143 | 0.139 m |
| strict125 | candidate | 0.111 | 0.143 (1/7) | 0.000 | 0.200 m |

default 的 `p_nav-eta` 差异稳定存在：不少 policy lost 的 true `eta` 曾进入
`r_tight`，但 `p_nav` 没有，直到 plane-miss 终止。strict125 是混合结果：
baseline `2/6`、gap `0.139 m` 刚过预注册阈值，candidate 只有 `1/7`、不过阈值；
不能把 default 的捕获帧问题直接外推到 strict125。

这与 Goal69/74/78/79 一致：失败的一部分是 terminal 估计/捕获帧问题，不是
载具完全没有到达。但 Goal77/79 已证明离线 geometry gate 和 observable bias
predictor 都不可用；因此不能靠改 radius 或再扫 deadband 解决，除非有新的
可观测估计器预注册。

### 3.4 H81-D：残差幅度/NoisyNet 不是 lost 的判别因素

policy lost vs retained：

| root | scenario | L2 ratio lost/retained | abs ratio lost/retained | action saturation lost/retained |
|---|---|---:|---:|---:|
| baseline | default | 0.705 | 0.500 | 0.333 / 1.000 |
| baseline | strict125 | 1.155 | 1.191 | 1.000 / 1.000 |
| candidate | default | 1.319 | 1.157 | 1.000 / 1.000 |
| candidate | strict125 | 1.099 | 1.153 | 0.999 / 1.000 |

全局 lost/retained 比值为 `1.170`（L2）和 `1.161`（abs），没有稳定方向；
baseline default 的 lost 残差反而更低。`zero-residual` 仍有 `14` 个 lost，
且 `14/14` 的 crossing geometry 都是 tight 外通过。正式评估使用 deterministic
mean（`sample_noise=False`），训练日志里的 stochastic `residual_abs_mean` 不能
当作评估残差。

所以“残差看起来很大”不是 NoisyNet 采样主导，也不是 lost 的判别因素。关闭/
缩小 NoisyNet、重扫 residual scale 或重开 Goal27 都没有证据支持。

## 4. 为什么神经网络没有打过传统方法

这不是“神经网络能力不够”这么简单，而是当前系统的比较方式决定了 residual
很难体现优势：

1. **传统 ALOS + PD/PI 已经是强基座。** 神经网络不是端到端替代控制器，而是在
   基座命令上学习有界残差；zero-residual 仍然能完成大部分 episode，residual
   的边际收益必须非常精确才能超过基座。
2. **优化目标与真正成功指标错位。** 训练主要优化路径/命令跟踪，但正式 success
   由 terminal capture 决定。Goal80 已经出现“heading tracking 改善、plane miss
   增加、true 变差”；本轮又看到 lost 在最近点后外离，说明 proxy reward 变好
   不等于 terminal 成功。
3. **动作参数化限制了修正方向。** REMUS100 没有侧向推进器，residual 只能通过
   heading/pitch/speed 间接修正；terminal 阶段还有 command rate limit、舵效和
   速度约束。残差可能学会了补偿/抖动，而不是在正确时刻产生横向修正。
4. **terminal 奖励稀疏且捕获帧有偏差。** Goal27 Step 1 已记录 path 项只占约
   `3.7%` 奖励方差、terminal 项接近零；同时 `p_nav` 与 true `eta` 在 default
   存在稳定差异。网络在 proxy 上学好之后，仍可能在 `p_nav` 捕获边界附近翻错
   标签。
5. **样本效率/探索不是已证明的瓶颈。** zero-residual 也失败，H3-SR 监督残差
   非零但闭环只改善约 `0.023 m`，本轮 residual 也不区分 lost/retained。没有
   证据支持“残差方向对，只是探索不够”，所以现在开 SAC 对照会混淆变量。
6. **评估协议本身有 true/false 权衡。** 为了压 false success 把半径收紧
   `0.25 m`，会把一部分 true 变成“厘米级近失”；这既不是网络独有的问题，也
   不能靠放宽半径同时解决 true 和 false。

更准确的表述是：**当前 learned residual 没有证明出超过 zero-residual 的边际
价值；失败主要发生在 terminal 几何、捕获帧和动作参数化，而不是网络优化器
不够强。** 下一步应先把这些可解释因素审计清楚，再决定是否值得训练更大的模型
或换 off-policy 算法。

## 5. 判定与下一步

```text
decision = pivot
```

- 停止 plane-miss guard / dwell / capture radius 的继续扫描；
- 不改 extension，不重跑 Goal27 失败臂；
- 不启动 SAC；没有 optimization/exploration 或 sample-efficiency 证据；
- 下一 Goal 预注册只读 `action parameterization + reward` 审计：
  - terminal 前后 heading/pitch/speed command 与 actual 的通道分解；
  - residual 三个通道的幅度、方向、rate clip、material saturation；
  - reward 各分量在 terminal 前窗口的占比，以及 success/plane-miss 项的激活；
  - 只在审计显示明确的可修正通道后，才设计单因素训练 arm。
- 若后续出现“残差方向正确但探索/样本效率不足”的直接证据，再新开预注册 Goal，
  用 SAC 做同协议对照；REDQ/DroQ 只在样本效率证据明确时考虑；
- 训练型 arm 的前置条件仍是 `num_envs 128/256/512 × batch 256/512` 单卡吞吐
  基准，再按 seed 分 8 卡；不得把扩采样混进正式 Gate；
- dev `20–59` 保持，held-out `100–149` 继续关闭。
