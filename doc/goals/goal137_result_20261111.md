# Goal137 结果：纵向信息仍在 `z_t`，BC 残差头也确有响应；最后一层不是主瓶颈

**日期**：2026-11-11<br>
**状态**：`DIAGNOSTIC_COMPLETE / LATENT_RETAINED / BC_HEAD_RESPONSIVE / LAST_LAYER_NOT_PRIMARY / P_D3_UNAVAILABLE`<br>
**上游**：Goal95、Goal117、Goal121、Goal125<br>
**性质**：离线探针 + 1-seed 监督适配小实验；未训练 PPO/SAC，未打开正式 held-out，未改 reward/terminal/success。

## 1. 结论

三项检查都指向同一个方向：**在这个 Goal86 P-A residual BC checkpoint 上，纵向/俯仰信息没有丢在编码器里，BC 残差头也不是“完全不响应”**。

```text
z_t probe              = retained
BC residual Jacobian   = responsive to vertical/pitch
last-layer adaptation  = only 0.66% RMSE gain / 0.73% sensitivity gain
```

因此，对这份 BC residual head，最不支持的解释是“编码器没预训练好/冻结了，所以纵向信息进不来”，也不是“BC 头完全不看纵向输入”。真正需要继续区分的是：

1. Goal95 `P_D3` 的 **PPO final head** 是否与 BC head 行为不同；
2. 若 PPO head 也响应，则问题更偏向动作 authority、俯仰 handoff 时序和终端信用分配；
3. 若 PPO head 不响应，再查 PPO 训练是否把先验头覆盖掉，而不是继续讨论是否冻结 BC encoder。

限制：本机没有 `P_D3` final checkpoint；本文的“head responsive”严格指 Goal86 P-A residual BC head，不能直接写成 PPO head 的结论。

## 2. Latent probe

数据与拆分：

- 数据：`artifacts/goal86/pa_residual_labels_20261110/pa_residual_labels.npz`，25,600 条；
- 拆分：按 `episode_id`，26 train episodes / 6 validation episodes；
- 验证 episode：`[5, 11, 13, 15, 19, 25]`；
- 拟合：固定 ridge `alpha=1.0`，训练集标准化，验证集不参与拟合或选参。

`z_t` 的结果：

| target | R² | Pearson | RMSE |
|---|---:|---:|---:|
| `vertical_error_m` | 0.9984 | 0.9993 | 0.0153 m |
| `pitch_error_rad` | 0.9981 | 0.9990 | 0.0085 rad |
| `q_rad_s` | 0.9989 | 0.9995 | 0.0073 rad/s |
| `w_mps` | 0.9979 | 0.9990 | 0.0062 m/s |

分解：

- `vertical_error`、`pitch_error` 主要来自 path branch：`path_z` R² 分别为 `0.9990/0.9985`，`state_z` 为 `0.079/0.789`；
- `q`、`w` 主要来自 state branch：`state_z` R² 为 `0.9991/0.9983`，`path_z` 仅 `0.132/0.303`。

这说明：

```text
纵向误差和俯仰误差没有丢；
q/w 的动力学状态也仍在 state latent 中；
z_t 同时保留了 path-relative 与 body-dynamics 两类信息。
```

高 R² 有一部分是结构性的：`actor_path` 显式含 `vertical_error/pitch_error`，经过 path encoder 后自然容易线性解码。这里验证的是“信息是否还在”，不是“编码器是否学会了新的抽象”。

## 3. Residual Jacobian

中心差分在 2,048 个验证样本上计算；`response/std` 表示输入变化 1σ 时，残差动作向量变化占典型残差 L2 的比例。

| input | response/std | Jacobian L2 (normalized) | physical action 敏感度 `[rudder, stern, rpm]` |
|---|---:|---:|---|
| `vertical_error` | 0.4747 | 1.1446 | `[0.0384 rad/m, 0.3879 rad/m, 84.26 rpm/m]` |
| `tangent_pitch_error` | 0.5740 | 2.7422 | `[0.0960 rad/rad, 0.9216 rad/rad, 265.69 rpm/rad]` |
| `q` | 0.5661 | 2.3197 | `[0.1496, 0.7532, 465.54]` |
| `w` | 0.1700 | 1.1289 | `[0.1262, 0.3285, 378.00]` |
| `theta` | 0.1692 | 0.7610 | `[0.0877, 0.1751, 468.22]` |

参照输入：

| input | response/std |
|---|---:|
| `cross_track` | 1.5619 |
| `heading_error` | 0.1739 |
| `phi` | 0.0116 |
| `r` | 0.1550 |

纵向/俯仰 5 个输入的 response 中位数为 `0.4746`，参照输入中位数为 `0.1644`，比值 `2.89×`。BC 残差头不仅对纵向输入有响应，而且响应强度高于这几个横向/航向参照的中位数。

这直接反驳了“BC 头没有真正使用已有纵向表征”的版本。但它仍是局部 Jacobian，不说明闭环中响应出现得够早或 authority 足够。

## 4. 冻结编码器 vs 微调最后一层

两臂都从同一 BC checkpoint 加载，然后使用同一个 seed 重新随机初始化 actor MLP：

- `head_only`：冻结 state/path/current encoder，只训练 actor head；
- `last_layer`：额外解冻 `actor_encoder.network[-1]` 和 `path_encoder` 最后一个 Linear。

| arm | best epoch | val residual RMSE (normalized) | physical RMSE `[rudder, stern, rpm]` |
|---|---:|---:|---|
| `head_only` | 119 | 0.15277 | `[0.0677, 0.0572, 113.5]` |
| `last_layer` | 116 | 0.15176 | `[0.0673, 0.0557, 123.2]` |

对比：

- 相对 RMSE 改善：`0.66%`；
- 纵向/俯仰 key sensitivity 变化：`+0.73%`；
- `head_only` 的 encoder drift：`0`；
- `last_layer` 的 encoder drift：state encoder `0.1807`、path encoder `0.3193`（max abs）。

因此：

```text
last_layer_effect = weak
frozen_encoder_is_primary_bottleneck = false
```

补充：两个“新 head”臂的验证 RMSE 都高于原始 BC head（`0.1220`）。这说明 120 epoch、26 个训练 episode 的监督小实验只能用来比较“固定表征 vs 可适配末层”，不能写成“重新训练能超过 BC”。原始 BC head 已经是这组标签上的更强拟合。

## 5. 判读与下一步

### 被支持

- H137-A：`z_t` 保留纵向/俯仰信息，`4/4` targets `R²>=0.50` 且 `r>=0.70`。
- H137-B 的 BC 版本失败：BC residual head 对纵向输入不是低响应；key/reference ratio `2.89`。
- H137-C：最后一层适配没有带来 >=5% 的 RMSE 改善，也没有 >=50% 的敏感度提升；冻结编码器不是主瓶颈。

### 仍未被回答

- `P_D3` PPO final head 是否保持同一敏感度；
- BC head 在离线 Jacobian 上响应，但闭环中动作是否因为 gate、scale、rate limit 或 credit assignment 没有转化为有效 pitch/vertical 修正；
- 当前失败链是否主要是“响应存在，但出现太晚/幅值或方向被终端几何吃掉”。

### 下一步优先级

1. 若能取回 Goal95 `P_D3/final.pt`，直接用本脚本的同一接口跑 `P_D3` 的 `z_t` probe 和 Jacobian；
2. 若不能取回，先复用 Goal95/117 trace 做 action timing 归因，而不是再改 encoder/freeze；
3. 只有在 PPO final head 的 probe 或 Jacobian 也差时，才重新考虑预训练目标、显式纵向 skip 或 DADE history。
