# Goal93 结果：PPO 增量被速率限制截断，增益主要来自总残差 scale

**日期**：2026-11-11<br>
**状态**：`RESULT_RECORDED / ACTION_PARAMETERIZATION_CLIPPING / NO_SAC / HELDOUT_CLOSED`<br>
**上游**：Goal92 `FAIL_NO_UPDATE_SCHEDULE_EFFECT`、Goal90 `PASS_RL_GAIN_WEAK`、Goal87 H87-O4<br>
**性质**：eval-only 40-seed scale sweep + trace；不训练、不改 reward/terminal/success/goal radius。

## 1. 结论

Goal93 的预注册判据给出：

| 判据 | 结果 |
|---|---|
| `AUTHORITY_NOT_BINDING` | `False` |
| `AUTHORITY_BINDING_BENEFICIAL` | `True` |
| `PPO_EFFECTIVE_SURVIVAL_LOW` | `True` |
| `DIRECTION_POSITIVE` | `False` |
| `TERMINAL_SHELL_SENSITIVE` | `True` |

按预注册优先级，路线是：

```text
ACTION_PARAMETERIZATION_CLIPPING
```

直接结论：

1. **不换 SAC。** PPO 的鳍面增量在 gate-active 区域大部分被速率限制截断，
   换 off-policy 算法不会让被截掉的增量重新出现。
2. **总残差 scale 是有效杠杆。** eval-only scale=1.5 把 strict125 从 17/40
   （scale=1.0）提到 21/40，default 保持 31/40；scale=2.0 继续提高 success
   但 path 退化更明显，scale=2.5 开始回落。
3. **PPO head 目前对闭环结果贡献约为 0。** `C10` 与 `PG10_3` 在 6 个 scale、
   2 个场景上的 success/path 曲线几乎完全重合；C10 多出的 35% PPO residual
   没有变成有效的转向/俯仰动作。
4. **“残差很大”不是 NoisyNet。** 配置没有 NoisyNet；大数值主要来自
   `r_BC` 相对 ALOS 的基座差和 RPM 通道。PPO 的鳍面物理权限只有 BC 的
   `4–6%`，rudder 在 gate-active 区域的有效生存率约为 `0`。
5. **终端捕获仍是毫米级壳层。** 成功终止余量中位数约 `12.6 mm`（default）
   和 `8.3 mm`（strict125）；policy 与 frozen-base 的 done 距离差只有
   `0.6 mm / 0.3 mm`；strict125 的 1 个 success 翻转发生在半径外
   `13.5 mm` 的壳层。success 增益主要是壳层翻转，不是轨迹大幅改善。

## 3. PPO 与 BC 的物理权限

gate-active 区域（`gate > 0.05`）：

| arm / scenario / scale | PPO fin L2 | BC fin L2 | PPO/BC | PPO rpm | BC rpm | rudder survival | stern survival | fin clip |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| `PG10_3` strict125 1.25 | 0.0106 | 0.2527 | 0.042 | 15.1 | 216.7 | 0.000 | 1.000 | 0.804 |
| `C10` strict125 1.25 | 0.0152 | 0.2497 | 0.061 | 31.0 | 215.9 | 0.000 | 1.000 | 0.803 |
| `PG10_3` default 1.25 | 0.0100 | 0.2569 | 0.039 | 14.3 | 206.9 | 0.000 | 1.000 | 0.809 |
| `C10` default 1.25 | 0.0146 | 0.2538 | 0.057 | 29.4 | 206.8 | 0.000 | 1.000 | 0.808 |

解释：

- `actuator_residual_applied` 的总 L2 约 `220–247`，几乎全部由 RPM 通道贡献；
  总 L2 生存率约为 `1.0`，会掩盖鳍面截断，所以必须看逐通道。
- rudder 的 effective/applied 中位数在 gate-active 区域为 `0`；
  stern 约为 `1.0`；任一鳍面通道被截断的 step 占 `80%` 左右。
- PPO 的鳍面物理权限只有 BC 的 `4–6%`；即使完全不被截断，也很难改变
  终端转向/俯仰捕获。
- C10 把 PPO residual 放大 35%，主要放大的是 RPM（15→31 rpm），
  鳍面只从 `0.0106` 增到 `0.0152`，仍远小于 BC 的 `0.25`。

## 4. 方向审计

预注册的 `cos(r_PPO, r_BC)` 结果：

| arm / scenario / scale | success cos | failure cos | success − failure [95% CI] |
|---|---:|---:|---:|
| `PG10_3` strict125 1.25 | -0.226 | 0.254 | -0.481 [-0.975, 0.191] |
| `C10` strict125 1.25 | -0.004 | 0.416 | -0.420 [-0.964, -0.022] |
| `PG10_3` default 1.25 | -0.247 | 0.806 | -1.052 [-1.218, 0.131] |
| `C10` default 1.25 | 0.073 | 0.909 | -0.836 [-1.091, -0.155] |

`DIRECTION_POSITIVE` 为 `False`，但不能直接写成“PPO 方向错”：

- 成功 episode 的 cos 更负，可能是 PPO 在终端抵消 BC 的过冲；
- 失败 episode 的 cos 更正，可能是因为失败轨迹更早/更久地处于 gate-active，
  仍跟随 BC；
- `cos(r_PPO, r_BC)` 不是因果最优方向，且对轨迹阶段敏感。

因此本 Goal 只能确认：**“与 BC 对齐”不是有效的方向判据**。方向问题仍未定论，
但动作权限/速率限制已经足以解释“C10 放大 35% 却零移动”，所以不需要用 SAC
去检验一个还没定义清楚的信用分配假设。

## 6. 对用户问题的直接回答

### 6.1 残差大是不是 NoisyNet 主导？

不是。Goal86/90/92 的 PC 配置没有 NoisyNet。训练随机性来自 PPO Gaussian
`init_noise_std≈0.10`；Goal91 已证伪“降低噪声能改善结果”。这里的“大残差”
主要是：

```text
r_BC = normalize(D3_actuator - ALOS_actuator)
```

它本身就把 D3 相对 ALOS 的差完整编码进去；RPM 通道的物理单位又是 rpm，
所以 L2/abs_mean 看起来很大。PPO 的增量只有 BC 的 `4–6%`，而且 rudder
增量在 gate-active 区域几乎全部被速率限制截掉。

### 6.2 为什么 C10 放大 35% 还是不动？

因为 C10 放大的主要是 RPM，而 terminal capture 需要的是转向/俯仰；
rudder survival≈0，鳍面截断率≈80%。requested residual 变大，但 effective
转向动作没有变大。

### 6.3 为什么不换 SAC？

SAC 改善的是样本效率/信用分配，不会改变执行器速率限制。当前证据是
`ACTION_PARAMETERIZATION_CLIPPING`，不是 `CREDIT_ASSIGNMENT_SAMPLE_INEFFICIENT`。
先修动作参数化，再用同一套 trace 判断是否需要 SAC。

## 7. 下一步（Goal94 预注册方向）

Goal94 只做动作参数化，不换算法、不改 reward/terminal/success/goal radius：

1. **Rate-aware residual**：先对 BC residual 做速率限制，再把 PPO residual
   加到剩余 headroom；或把 PPO 参数化为 rate residual，避免被位置残差的
   rate limiter 截断。
2. **Fin-specific authority**：给 rudder/stern 单独的 PPO gain，RPM 保持原 gain；
   目标是让 PPO fin L2 从 BC 的 `4–6%` 提到可辨识的 `15–25%`，同时监控
   `fin_clip_step_fraction` 不超过 `0.5`。
3. **Scale 1.5 screen**：在修正 rate-aware 参数化之前，先跑一个 `scale=1.5`
   的 3-seed 训练型 screen，确认 eval-only 的 `+4/0` 能否在训练后保留；
   这是最便宜的“总残差增益是否可部署”检验。
4. **评价扩展**：每个 arm 必须报告 shell 指标（`eta_min`、near-miss shell、
   annulus entry、conditional capture、radius sensitivity），不能只看 success。
5. **SAC 启动条件**：只有 rate-aware/fin-gain 修正后，PPO fin survival 达到
   `>=0.5`、方向指标有明确成功/失败分离，但 success 仍不改善，才开 SAC 同协议对照。
