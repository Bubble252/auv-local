**上游**：Goal92 protocol、Goal90 `PASS_RL_GAIN_WEAK`、Goal91 `NOISE_NOT_PRIMARY_BOTTLENECK`<br>

## 1. 结论

6 个更新调度 arm 全部没有达到预注册晋级阈值：

- default 全部 `31/40`；
- strict125 除 `W0` 为 `19/40` 外全部 `20/40`；
- 逐 episode 配对相对 `PG10_3`，`E4/C10/C20/AN/E4_C10_AN` 的 gain/loss 均为
  `0/0`；`W0` 只有 `0/1`（seed 59 从成功变失败）；
- `C10/C20` 确实把 deterministic PPO residual 放大了约 `35%/29%`
  （`0.0263/0.0251` vs `0.0195`），但 success、path、plane-miss 几乎完全不变。

因此：

```text
H92_A = falsified
H92_B = falsified_for_outcome
H92_C = falsified
H92_D = falsified
UPDATE_SCHEDULE = not_sufficient
CREDIT_ASSIGNMENT = still_primary_suspect
```

这次结果不是“再多个 epoch 就会好”：`E4` 反而把 residual 压到 `0.0133`；
也不是“clip 太紧”：放宽 clip 后残差变大，但闭环不动。

## 3. 机制判读

`C10/C20` 提供了最有价值的反证：

```text
residual magnitude +35% / +29%
but success flips = 0/0
and path change < 0.002 m
```

如果瓶颈只是“PPO 更新太小”，放宽 clip 应该产生至少一个 episode 翻转；实际没有。
这说明 PPO 的 deterministic 增量虽然变大，但仍没有指向能改变终止结果的终端动作。
结合 Goal87 terminal audit：

- terminal/capture 在 40 个 seed 上是毫米级移动；
- reward 改善只有千分之几；
- NoisyNet 不参与；
- 网络主干已与 Goal26/Goal80 对照，无接线错误。

当前最合理的归因是 **on-policy credit assignment / 样本效率**，不是更新调度、
探索噪声、gate scope 或网络结构。

## 4. Gate 裁决
