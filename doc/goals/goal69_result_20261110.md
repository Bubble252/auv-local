# Goal69 结果：heading+pitch 多通道 tracking lag，residual/NoisyNet 不是主导

**日期**：2026-11-10<br>
**状态**：`PRECROSSING_MULTICHANNEL_TRACKING_LAG`<br>
**预注册**：`doc/goals/goal69_precrossing_tracking_channels_20261110.md`<br>
**上游**：Goal67 `TERMINAL_AUTHORITY_LIMITED`、Goal68 `PRECROSSING_TRACKING_LAG`

## 1. 结论

Goal69 只读复用 Goal67 的 10 个 rich trace，把 Goal68 的 command-to-velocity
tracking lag 拆成 heading、pitch、surge 三条通道。主窗口为 plane crossing 前 1 s，
2 s 只作持续性检查，窗口严格截止第一个 `signed_offset >= 0` 的 crossing 行。

正式判定：

```text
default   -> PRECROSSING_MULTICHANNEL_TRACKING_LAG (B pitch, C p_nav)
strict125 -> PRECROSSING_MULTICHANNEL_TRACKING_LAG (B pitch)
overall   -> PRECROSSING_MULTICHANNEL_TRACKING_LAG
```

- **H69-A 正式不支持**，但原因是预注册的 2 s 持续性守卫，不是 heading 误差小：
  lost 的 1 s heading error 为 `0.930/0.364 rad`，retained 为 `0.219/0.165 rad`；
  2 s/1 s 比值为 `0.605/0.295`，低于冻结的 `0.75`。
- **H69-B 支持**，且由 **pitch** 独立触发：default lost 的 `abs(pitch_error)`
  中位数 `0.618 rad`，retained `0.213 rad`，gap `0.405 rad`；strict125 为
  `0.596/0.154 rad`，gap `0.442 rad`。speed 通道不支持。
- **H69-C 仅在 default 支持**：`4/9 = 0.444` 的 lost 在 crossing 前进入
  `r_tight`，但 p_nav 进入比例为 `0`，first-entry 的 `p_nav - eta` 距离中位数
  `0.240 m`。strict125 只有 `2/7 = 0.286`，低于 `0.40`，按预注册不外推。
- **NoisyNet / residual 主导被拒绝**：eval 使用 deterministic mean weights；
  applied residual/base 在 default lost 为 `0.109`、retained 为 `0.200`，
  strict125 为 `0.181/0.176`，lost 并不更高；zero-residual 仍丢 default 4、
  strict125 1。residual 不是这次跟踪失败的判别因素。

因此当前证据仍然指向 frozen controller 的 command-to-velocity tracking，而不是
优化/探索失败或样本效率失败。**不启动 SAC/REDQ/DroQ，不重开 Goal27。**

H69-B 的正式判定依赖上述“差距幅度”解释。

## 4. H69-A：heading 原始证据强，但正式持续性守卫失败

| scenario | lost 1 s heading err | lost 2 s heading err | 2s/1s | retained 1 s | gap lost-retained | lost command-goal cos | lost actual-command cos |
|---|---:|---:|---:|---:|---:|---:|---:|
| default | `0.930` | `0.562` | `0.605` | `0.219` | `0.711` | `0.980` | `0.294` |
| strict125 | `0.364` | `0.107` | `0.295` | `0.165` | `0.199` | `0.983` | `0.659` |

H69-A 的四个 1 s 条件都满足：`abs(heading_error) >= 0.20`、lost-retained gap
`>= 0.10`、command-goal cosine `>= 0.95`、actual-command cosine `< 0.90`。
但 2 s/1 s 持续性比值只有 `0.605/0.295`，低于冻结的 `0.75`，所以正式判
**A=false**。

需要区分“守卫失败”和“单帧抖动”：1 s 窗口有约 50 行，heading error 的中位数
已经是 `0.930/0.364`，不是最后一帧的尖峰；2 s 误差更低是因为误差在最后 1 s
快速增大。按预注册不能追认 A，也不能改阈值；这个现象作为描述性证据保留，供
Goal70 的 command feasibility/phase-lead 诊断使用。

## 5. H69-B：pitch 独立支持，speed 不支持

| scenario | lost abs pitch err | retained abs pitch err | gap | lost cmd pitch | lost act pitch | pitch sign agreement | lost abs speed err | retained abs speed err |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| default | `0.618` | `0.213` | `0.405` | `0.875` | `0.229` | `1.000` | `0.493` | `0.498` |
| strict125 | `0.596` | `0.154` | `0.442` | `1.061` | `0.394` | `1.000` | `0.169` | `0.280` |

pitch 在两个 scenario 都超过 `0.10 rad` 的误差门槛和 `0.05 rad` 的 gap 门槛。
同时 command pitch 与 actual pitch 同号，说明不是符号约定错误，而是实际 pitch
幅度明显跟不上 command。

speed 不支持：default lost/retained 的 `abs(speed_error)` 几乎相同
(`0.493/0.498`)，strict125 lost 还低于 retained (`0.169/0.280`)；actual ground
speed 约 `1.9–2.0 m/s`，不是低速卡死。因此 surge 不是这次 lost 的判别通道。

一个重要的描述性限制：lost 的 command pitch 本身很大
(`0.875/1.061 rad`)，command pitch rate 中位数 `0.277/0.521 rad/s`，actual pitch
rate 只有 `0.164/0.199 rad/s`。material saturation 在 lost 反而低于 retained
(`0.118/0.176` vs `0.235/0.353`)，scale/rate clip 均为 `0`。所以这更像
command shaping / rate feasibility 与 tracking 的组合，而不是“执行器已经饱和”。
本 Goal 不能把它写成硬件绝对上限，也不能据此直接改 controller gain。

## 6. H69-C：default 的 p_nav/capture timing 仍是独立分支

default lost 中，`4/9 = 0.444` 的 episode 在 crossing 前 true eta 进入
`r_tight`，但 p_nav 进入比例为 `0`；first-entry 的 `p_nav - eta` 距离中位数
`0.240 m`，超过 `0.15 m` 门槛。H69-C 在 default 支持。

这 4 个 episode 集中在 default `policy_s1008`（1 个）和 `zero`（3 个），不是
所有 checkpoint 均匀分布。strict125 的 eta-tight fraction 只有
`2/7 = 0.286`，低于 `0.40`，按预注册 **C 不评估、不外推**。因此 default 的
p_nav 分支是叠加机制，不能解释 strict125 的多数失败。

## 7. NoisyNet / residual 复核

用户的疑问是“残差这么大是否被 NoisyNet 主导”。现有证据不支持这个解释：

1. **eval 不采样噪声**：当前评估走 deterministic mean weights
   (`sample_noise=False`)，不是训练时的 NoisyNet 采样策略。
2. **Goal59 的 deterministic probe**：8/8 个 seed 在 mean weights 下
   action saturation 都是 `1.0`；`noise/det` 中位数 `0.0193`，只有 seed `1008`
   达到 `1.0325`，但它的 deterministic saturation 仍是 `1.0`，闭环没有改善。
3. **本 Goal 的 residual/base**：default lost `0.109`、retained `0.200`；
   strict125 lost `0.181`、retained `0.176`。lost 的残差占比并不更高；
   residual scale/rate clip 都是 `0`，gate 均值为 `1.0`。
4. **zero-residual 反例**：完全关闭 residual 后，default 仍丢 4 个、strict125
   仍丢 1 个 true episode；如果 residual/NoisyNet 是必要条件，zero-residual
   不应复现这些丢失。

所以“残差看起来大”更可能是 raw/last-second 数值，不是相对 base command 的主导
分量。当前没有依据通过关闭 NoisyNet、缩小 sigma、换 seed 或重开 Goal27 来修复
主线问题。

## 9. 假设裁决与下一步

| hypothesis | 裁决 | 证据 |
|---|---|---|
| H69-A：heading/yaw 是主通道 | **正式 NOT SUPPORTED** | 1 s 误差和 gap 都强，但 2s/1s `0.605/0.295 < 0.75`；按预注册不追认 |
| H69-B：pitch 或 surge 有独立 tracking 缺口 | **SUPPORTED via pitch** | pitch gap `0.405/0.442 rad`；speed 不支持 |
| H69-C：default 的 p_nav/capture timing 独立 | **SUPPORTED（仅 default）** | `4/9` eta-tight、p_nav `0`、gap `0.240 m`；strict125 低于门槛且不评估 |
| NoisyNet/residual 主导 | **REJECTED** | deterministic eval；residual/base lost 不高于 retained；zero-residual 仍丢失 |

决策：`pivot`。停止把 residual/NoisyNet 作为当前失败线的解释，进入
**command feasibility / phase-lead** 诊断。下一步预注册 Goal70：

1. 只读检查 crossing 前 heading/pitch command rate 与 actuator rate limit、
   command shaping、phase lead 和 terminal guidance；
2. 把 speed 作为负控，确认它不是 lost 的判别通道；
3. 保持 frozen checkpoint、dev `20–59`、CPU/float64、`endpoint_stop` 和
   held-out 关闭；
4. 不训练、不启动 SAC/REDQ/DroQ、不改 reward/gamma/seed/controller。
