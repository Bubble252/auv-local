  default 的 97 个 protocol true 中只有 59 个是 tight true；strict125 的
  44 个中只有 25 个。protocol-only 分别为 38 / 19。

  少 1 个样本；不能事后放宽阈值。
- deadband 之后剩余的 tight false 主要停在 goal plane 前，而不是横向偏差：
  default 剩余 34 个，`signed≈-1.22 m`、`lateral≈0.34 m`、`b≈0.13 m`；
  strict125 剩余 17 个，`signed≈-0.62 m`、`lateral≈0.00 m`、`b≈0.15 m`。
- 因此沿 goal 方向的 bias correction 已经接近它的能力上限；下一步应审计
  terminal plane crossing 与 capture/termination 时序，而不是继续降 deadband。

对 deadband 后仍为 tight false 的样本做只读分解：

| scenario | n | b median (m) | p_nav-eta error (m) | signed offset (m) | lateral (goal frame, m) | vertical (goal frame, m) |

| strict125 | 17 | 0.1456 | 0.2925 | -0.6194 | -0.0021 | 0.0225 |

这些样本的特征不是“沿 goal 方向乐观”，而是：

- signed offset 明显为负：`p_nav` 在 goal plane 前 `0.62–1.22 m` 就停止；
- proper goal-frame lateral 只有 `0.34 m`（default）和约 `0 m`（strict125）；
- `p_nav-eta` 误差只有 `0.29–0.33 m`，与 plane shortfall 同量级。

注意：早先表中的 `1.2364/0.7618 m` 是世界坐标 `terminal_horizontal_offset`，
它重复计入了 signed offset，不能当作 goal 局部 lateral。Goal77 已用 goal
tangent 正交基重新分解并纠正该口径。

所以继续降低 deadband 只会把低 `b` 样本也修正掉，无法解决 terminal plane
shortfall 与球面 `endpoint_stop` 的时序问题。

## 7. 残差是否被 NoisyNet 主导

结论：**不是 NoisyNet 主导，也不是“残差必须有非零值才会失败”**。正式评估
使用 deterministic mean，`sample_noise=False`；下面再按 checkpoint 分解
deadband 之后剩余的 tight false。

| checkpoint | default 剩余 tight false | strict125 剩余 tight false | residual L2 中位 (m) | action L2 中位 (m) | residual/action 中位 |
|---|---:|---:|---:|---:|---:|
| s240 | 11 | 3 | 0.3521 | 0.8506 | 0.4140 |
| s752 | 6 | 3 | 0.3505 | 0.8421 | 0.4163 |
| s880 | 5 | 4 | 0.3560 | 0.8628 | 0.4126 |
| s1008 | 7 | 1 | 0.1735 | 0.5009 | 0.3477 |
| zero-residual | **5** | **6** | **0.0000** | **0.0000** | — |
| 合计 | 34 | 17 | 0.3506 / 0.3505 | 0.8425 / 0.8418 | 0.4140 / 0.4140 |

关键判读：

- 有 `5/34`（default）和 `6/17`（strict125）剩余 tight false 来自 forced
  zero-residual，`residual_l2` 严格为 `0`；没有 residual 仍然失败，说明
  residual 不是必要条件。
- `s240/s752/s880` 的 NoisyNet noise/deterministic L2 中位数只有
  `0.0049–0.0083`，却贡献了 default `22/34`、strict125 `10/17` 的剩余
  false；噪声与这些失败没有对应关系。
- 只有 `s1008` 的 noise/det 接近动作量级（Goal72 probe 中位约 `1.056`），
  但它的 deterministic mean 仍饱和，且只贡献 default `7/34`、strict125
  `1/17`。若 NoisyNet 主导，失败应集中在这个 checkpoint，而不是分布在
  zero 和低噪声 checkpoint。
- 表中的 residual L2 `0.35 m` 是 deterministic applied residual，不是
  NoisyNet 随机噪声；它占 action L2 约 `41%`。但 zero-residual 仍失败，
  所以“残差看起来大”不能升级成“噪声或算法主导”。
- `b` 中位只有 `0.13–0.15 m`，而剩余 false 的 lateral offset 中位为
  `1.24 / 0.76 m`。残余误差主要不在沿 goal 方向的 residual 修正量，
  而在横向/纵向进入几何和 capture 口径。

相关历史证据：

|---|---:|---:|
| s240 | 0.0049 | 1.0 |

补充分解只读复用现有服务器 trace：`--jobs 10`、每进程单线程 BLAS，墙钟约

## 8. 为什么不是换算法

- 正式评估 deterministic mean，NoisyNet 不采样；
- forced zero-residual 仍复现 terminal 失败；
- residual 不是必要条件，失败集中在 lateral/vertical 与 entry geometry；
- 本轮没有 optimization/exploration 或 sample-efficiency 证据；
- 8×4090 空闲不是启动 SAC/REDQ/DroQ 的理由。下一步是 terminal geometry
  和 entry-direction gate，而不是新 RL 算法。
