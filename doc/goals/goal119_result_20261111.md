这不是“reward 方向完全无效”：C1/C2/C3 的 terminal share 有单调改善

reward 组成，而是 **PPO 没有把 reward 差异转化为有效的闭环策略**。

## 2. 先记录一个执行协议错误

第一次 eval 使用 `--action-mode frozen-base`。代码中该模式实际是
**zero-residual paired baseline**：

```python
if action_mode in {"zero-residual", "frozen-base"}:
    held_action = torch.zeros_like(held_action)
    residual_action = held_action
```

因此第一次 8 个 checkpoint 的 dev40 全部精确 20/40，5 个不可达 seed 的
2 m margin 连小数位都相同。这是 `INVALID` 的 eval 协议，不是算法结果。

已保留旧目录 `eval/` 作为 zero-residual baseline，并用
`--action-mode policy` 重跑到 `eval_policy/`。本文件的 Gate 只使用
`eval_policy/` 结果。

## 4. 训练动力学

以 `C0_s86201` 最后一个 iteration 为例：

```text
approx_kl        = 1.12e-4   (desired_kl = 5e-3)

```

`approx_kl` 只有目标值的约 1/45，`surrogate` 接近 0，说明策略更新几乎被
锁死。actor 输出层虽然每步都有更新（`actor.4.weight` update norm `0.0197`），
但权重范数只有 `0.060`，实际行为变化很小。

## 7. 与历史 PPO 的关系

PPO 仍然无法把 reward 改动转成 success 提升。两条证据合起来指向：

```text

```
