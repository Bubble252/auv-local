## 1. 结论

Goal115 的预注册 Gate 判为：

```text
REFERENCE_FILTER_LIMITED
```

strict C0 的 11 个 `PREENTRY_GEOMETRY_BAD` failure 全部可评估：

```text
REFERENCE_FILTER_LIMITED   = 8/11
PLANT_RESPONSE_LIMITED     = 3/11
RESIDUAL_DIRECTION_LIMITED = 0/11
MIXED_HANDOFF_CONTINUE     = 0/11

```

8 个 Goal114 mixed 子集：

```text
REFERENCE_FILTER_LIMITED = 6/8
PLANT_RESPONSE_LIMITED   = 2/8
```

因此当前证据支持“2 m 前的 pitch 恶化首先经过 guidance command rate limiter”，
但**不支持**把它写成“只要提高 15 deg/s 限幅就能修好”。success control 本身也有
很高的 clip fraction，且 3 个 failure 在 filter 之后仍明显受 plant response 限制。
下一步必须是 eval-only 的 filter 因果对照，不是换 PPO/SAC，也不是直接抬限幅。

## 4. failure 与 success control 的对照

| 指标（2 m 锚定窗） | failure 中位 | success control 中位 |
|---|---:|---:|
| `clip_fraction` | 0.963 | 0.931 |
| `limited_at_limit_fraction` | 0.853 | 0.495 |
| `median_target_excess_rate` | 1.074 | 0.992 |
| `median_tracking_deficit` | 0.135 | 0.027 |
| `pitch_error_abs_median` | 0.480 | 0.200 |
| `target_rate_p95` | 3.832 | 3.815 |
| `actual_rate_p95` | 0.139 | 0.191 |
| `stern_norm_p95` | 1.000 | 1.000 |

关键读法：

- 原始 target 的高频抖动不是 failure 独有；success 的 `clip_fraction` 和
  `target_rate_p95` 也很高。因此不能把 `clip_fraction` 单独解释成 failure 原因。
- failure 更明显的是“limiter 输出长期贴着 15 deg/s 上限”
  （`0.853` vs `0.495`），以及 filter 后 plant 仍跟不上
  （`0.135` vs `0.027` rad/s）。
- filter、plant 和 stern saturation 在高频 reference 下是耦合的。Goal115 只能
  证明失效链路经过 filter，不能单独证明提高或降低限幅会改善闭环。

## 5. 关于 NoisyNet 与残差

Goal108 网络审计已固定以下事实：

- NoisyNet 的 `rho/sigma/noise` 参数数为 `0`；
- Goal86 frozen BC → Goal108 PPO 为 `22/22` `torch.equal`，
  `max_abs_diff=0.0`；
- PPO/SAC state encoder 为 `8/8` equal；
- Goal108 SAC 的问题是 path encoder 没有沿用 Goal86 P-A 的
  `path8 + endpoint4 + BC encoder`，不能写成“SAC 优化器天然不如 PPO”。

Goal115 的 `action_mode=frozen-base`，PPO 增量严格为零。trace 里的
`actuator_residual_applied` 是冻结 BC 残差，不是 NoisyNet 噪声，也不是 PPO
学习增量。11 个 failure 中没有 `RESIDUAL_DIRECTION_LIMITED`，且 BC residual 与
pitch error 的相关符号不一致（中位 `+0.257`，但逐 seed 从 `-0.991` 到
`+0.893`），所以本 Goal 不能把问题归因给“残差被 NoisyNet 主导”。

## 6. 决策

```text
不换 PPO/SAC/REDQ/DroQ。
不改 reward/terminal/success/goal radius。
不打开 held-out。
```

进入 Goal116：同一 checkpoint、同 dev seeds、strict C0 的 eval-only
guidance rate-limit sweep，先做因果筛选：

```text

ROFF command rate limit disabled
```

预注册判读：

- R200/ROFF 显著改善：filter 是因果瓶颈，下一步查 reference/limit 设定；
- R050 显著改善：原始 target 高频噪声主导，下一步做 reference smoothing；
- 四臂在 seed 噪声内：filter 非因果主因，回到 plant/action/reward；
- 任一臂增加 timeout/safety：该方向淘汰，不许用 success 换安全。
