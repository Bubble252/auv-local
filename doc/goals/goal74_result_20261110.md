## 1. 结论

```text
H74-A margin 收紧 -> NOT SUPPORTED / MARGIN_UNUSABLE
H74-B 方向性 bias  -> SUPPORTED (default 与 strict125 同向)
H74-C 动作/奖励退化 -> 暂不触发；先做 bias correction 单因素审计
decision -> pivot
```

- post-hoc margin 重分类可以消掉全部 false-success，但也会消掉全部
  true-success；`margin=0.10 m` 时 true retention 已经是 `0`。
- 原因是 `endpoint_stop` 在 `p_nav` 到达 tight radius 时立即终止，所有
  success 的 terminal `p_nav` 余量都只有约 `0.01–0.02 m`。因此离线
  margin 不是一个可部署的 capture 策略；它只是把边界样本整体删掉。
- false-success 的 `p_nav-eta` 方向投影中位在 default/strict125 分别为
  `+0.5591 / +0.5513 m`，true-success 组只有 `-0.0155 / +0.0760 m`；
  gap 为 `+0.5745 / +0.4753 m`。这是稳定、跨 scenario 同向的乐观偏差。
- 当前证据不支持“换 SAC/REDQ/DroQ”，也不支持继续加控制 authority。
  下一步应预注册 `p_nav` terminal bias correction 的单因素审计。

同时用于 `terminal_eta_capture`，导致 true-success 被低估、false-success
被高估。正式重跑前已修正并归档旧结果：

```text
r_tight    = summary["eval_goal_radius_m"]                    # 1.75 / 1.00
r_protocol = environment_config.plant.goal_radius_m           # 2.00 / 1.25
success    = d_p <= r_tight - margin
```

`summary["eval_goal_plane_miss_guard_radius_m"]` 已校验与
`plant.goal_radius_m` 一致。`signed_offset >= 0` 只作 plane 诊断，不参与
success。修正后 `success` 与 evaluator 的 `PCTerminalKind.GOAL` 重分类
mismatch 为 `0/200`（两个 scenario）。

旧 provisional JSON/MD 保存在
`artifacts/lowlevel/goal74_capture_margin_audit_20261110/analysis_provisional_invalid_radius/`，

## 4. Margin 重分类

| scenario | margin (m) | success | true success | false-success | true retention |
|---|---:|---:|---:|---:|---:|
| default | 0.00 | 128 | 97 | 31 | 1.0000 |
| default | 0.10 | 0 | 0 | 0 | 0.0000 |
| default | 0.25 | 0 | 0 | 0 | 0.0000 |
| default | 0.50 | 0 | 0 | 0 | 0.0000 |
| strict125 | 0.00 | 58 | 44 | 14 | 1.0000 |
| strict125 | 0.10 | 0 | 0 | 0 | 0.0000 |
| strict125 | 0.25 | 0 | 0 | 0 | 0.0000 |
| strict125 | 0.50 | 0 | 0 | 0 | 0.0000 |

在 margin=0 时：

| scenario | false-success / success | false-success 占比 |
|---|---:|---:|
| default | `31 / 128` | `24.2%` |
| strict125 | `14 / 58` | `24.1%` |

结论：margin 只能把 false-success 和 true-success 一起清零，不能作为
单因素修正。若未来要使用 capture margin，必须把它写进闭环 termination，
重新 rollout；不能拿 terminal snapshot 的离线重分类代替。

## 5. Bias 证据

| scenario | group | n | bias projection (m) | p_nav-eta error (m) | p_nav margin to tight (m) | eta outside protocol (m) |
|---|---|---:|---:|---:|---:|---:|
| default | false-success | 31 | +0.5591 | 0.7360 | 0.0135 | 0.1789 |
| default | true-success | 97 | -0.0155 | 0.3751 | 0.0126 | -0.3199 |
| strict125 | false-success | 14 | +0.5513 | 0.7292 | 0.0116 | 0.2194 |
| strict125 | true-success | 44 | +0.0760 | 0.3789 | 0.0176 | -0.2730 |

两个 scenario 的 false-success 组都表现为：

- `p_nav` 沿 goal 方向系统性比 true `eta` 更乐观；
- `p_nav-eta` 误差约 `0.73 m`，几乎是 true-success 组 `0.38 m` 的两倍；
- `p_nav` 到 tight radius 的余量只有 `0.012–0.018 m`，远小于估计误差。

这不是零均值噪声在边界上的对称翻转，而是与 outcome 相关的方向性偏差。

## 6. NoisyNet 复核

NoisyNet 不是本次残差/偏差的主导解释：

- 正式评估使用 deterministic mean weights，`sample_noise=False`；
- Goal59 已证明 mean-weight 本身可以饱和，NoisyNet sigma 未膨胀；
- Goal63/70 的 zero-residual 反例仍复现 terminal capture 失败；
- 本次偏差是跨 scenario 同向的 `+0.55 m` 结构化投影，不是零均值探索噪声。

更准确的表述是：residual 可能“看起来大”，但当前问题是 `p_nav` 终端
估计的乐观偏差和 capture 边界，而不是 NoisyNet 在评估时注入了随机性。

## 7. Gate 判读

`decision = pivot`：不采用 margin 收紧，不换 SAC/REDQ/DroQ，不加控制
authority；下一步预注册 bias correction 单因素审计。

## 8. 下一步

Goal75 候选协议（尚未执行）：

1. 先用 oracle bias correction 做因果上界：从 `p_nav` 沿 goal 方向减去
   `p_nav-eta` 的投影，重算 true/false-success，确认偏差是否可解释
   false-success；
2. 如果 oracle 能保留大部分 true-success 并消除 false-success，再预注册
   learnable bias predictor（只使用可观测特征）或 conservative terminal
   correction；
3. 如果 oracle 也破坏 true-success，则回到动作参数化/reward/terminal
   reference point，不启动新 RL 算法；
4. 继续关闭 held-out `100–149`，不改冻结 checkpoint、seed、eval split。
