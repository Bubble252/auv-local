## 8. 稳健性与限制

### 8.1 描述性稳健性（不是 Gate）

对 heading error 做 leave-one-seed-out 与 5,000 次 seed bootstrap（固定 RNG
`20261156`，仅用于描述）：

```text
strict125/baseline:  partial rho = 0.508972
  LOO range        = [0.470845, 0.567456]
  bootstrap 95% CI = [0.243821, 0.728898]
strict125/candidate: partial rho = 0.442978
  LOO range        = [0.392153, 0.537759]
  bootstrap 95% CI = [0.101783, 0.713407]
```

控制 `first_terminal_phase_s` 后，partial rho 仍为
`0.495877/0.425694`；关联不是由 terminal timing 直接解释。

独立校验：从 `strict125/baseline` trace 手工重算 seed 150 的
`early_tracking_heading_error_abs_mean_rad` 为 `0.16329782426305983`，
与 per-seed CSV 完全一致（300 个 window rows）；另用独立的
rank-residual 实现复算 heading partial rho，得到
`0.508971851909 / 0.442978150443 / 0.469156117531 / 0.259689061310`
（strict125 baseline/candidate、default baseline/candidate），与 analyzer
输出逐位一致。

### 8.2 关键限制：baseline/candidate 不是独立 predictor

13 个 early 特征在 baseline 与 candidate 之间逐 seed 完全相同：

```text
strict125: max abs diff = 0.0, exact 40/40 for all 13 features
default:   max abs diff = 0.0, exact 40/40 for all 13 features
```

因此 `min(|rho_baseline|, |rho_candidate|)` 使用的是同一个 predictor 向量，
只是 endpoint 不同。两 block 同号几乎是同一 predictor 的自然结果，不能算两次
独立特征复现。Family/global permutation 仍然控制特征选择，但不能修复这个
共享 predictor 问题。

### 8.3 关键限制：strict125/default 差异是边界性的

strict125 baseline `0.508972` 与 default baseline `0.469156` 的差异很小；
strict125 candidate `0.442978` 与 default candidate `0.259689` 的差异更大，
但两者都是 n=40，未做预注册的差异检验。描述性 Fisher z 约为 `0.904`
（双侧 p 约 `0.37`），不能声称 strict125 与 default 的关联强度有统计显著差异。
Default H1 family score `0.259689` 也接近 `0.30`。因此“strict125-specific”
只是本 Gate 的阈值判定，不是强机制证据。

### 8.4 其他边界

- 单一 checkpoint、单一训练 seed、单一 sensor seed、dev-style 新 seed block；
- 6.0 s 比 Goal54 的 8.0 s 少 2.0 s 数据，统计功效更低；6.0 s null 不能外推成
  “所有 early warning 都无效”；
- 这是 association audit，不是因果 mediation，也不是在线 detector；没有
  calibration、alarm threshold 或部署级 false-alarm rate；
- 第一次 `default/candidate` 尝试误用了整份 Goal31 environment config，被
  evaluator 以 reward-contract mismatch 拒绝，没有生成 block；随后按冻结协议
  改用 `--guidance-config` 重新生成 candidate。该修正只改 CLI，不改 config
  内容或统计定义；
- `default/baseline` 的 evaluator stdout 曾打印 aggregate metrics（包括
  `success_rate=0.725`）；没有用任何 per-seed outcome 选择 cutoff、seed 或
  阈值，cutoff 在运行前已经冻结。provenance-only smoke 只读 terminal timing。

或 held-out 访问。下一步应优先解决本轮暴露的两个问题：

1. **独立 predictor 验证**：在全新 seed block（例如 `190-229`）上只预注册
   heading-error 单特征、单 primary block、固定 effect/CI Gate；不要再把
   baseline/candidate 当作两个独立特征样本。
2. **controlled early-heading intervention**：在固定 checkpoint/seed 下显式
   扰动 early heading error 或 initial heading geometry，检验 terminal true miss
   是否随之改变；这比再加 feature 更接近机制。
3. **instrumentation**：若要做在线预警，必须先记录早期 controller/estimator
   内部状态，并冻结 lead-time、alarm threshold 和 false-alarm 预算。

不能在本 Goal 内追加特征、改 6.0 s 窗口、改阈值、换 RNG、换 seed 或打开
held-out。
