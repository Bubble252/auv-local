## 1. 结论

本 screen 的人工裁决是 **`SCREEN_FAIL`**。`audit_summary.json` 自动分析器给出的
`SCREEN_INCONCLUSIVE` 只是其规则标签，不是通过；所有学习臂都没有达到预注册的
`+2/40` success 或 `0.02 m` eta_done 改善，而且 PPO 还稳定损失了 2 个 seed。

核心结论：

- PPO 三档 entropy（`1e-4/1e-3/1e-2`）结果几乎完全相同，都是 `35/40`，zero 为
  `37/40`；提高探索强度 100 倍没有改变动作或闭环结果，排除“PPO 只是探索不足”。
- PPO 固定丢失 seed `36/49`，没有新增成功 seed；残差主要是 `+0.015 m/s` 的速度
  偏置，幅度很小但仍足以破坏 current07 的 terminal capture。
- SAC 学到接近满幅的 learner action（RMS `0.79–0.90`），实际 command residual
  为 heading `-0.092 rad`、pitch `+0.044 rad`、speed `+0.013 m/s`；闭环从
  `37/40` 掉到 `9/40`，31 个失败全部是 `GOAL_PLANE_MISS`，不是 timeout/safety。
- SAC 的迁移同样崩溃：current05 policy/zero `10/40 vs 39/40`，current10
  policy/zero `11/40 vs 29/40`。这不是统计噪声，也
  不是“需要更多样本”可以掩盖的单 seed 波动，而是残差权限/动作参数化/terminal
  approach 被大 heading/pitch 残差直接改写。
- NoisyNet 不是主因：PPO/SAC checkpoint 没有 `rho/sigma/noise` 噪声参数；评估是
  deterministic policy。PPO 三档 entropy 完全无分化也进一步排除探索噪声主导。
- 纵向奖励不触发：PPO policy 的 vertical RMSE 反而比 zero 低 `0.0028 m`，却仍然
  loss success；SAC 的主要失败是 31 个 plane miss，不是“纵向误差方向正确但幅度不降”。
  因此本轮 **不启动** Goal140 的 `F_z/F_zdot/F_predz` reward pilot。

### PPO

PPO 的残差不是零，方向也稳定：主要是在速度通道加约 `+0.015 m/s`，heading 有小幅
正向偏置。它没有把 success 推上去，反而固定损失两个 seed。速度残差虽然小，但已经
足以改变 goal-plane entry 的终端几何。

### SAC

| 证据 | 结果 | 判读 |

| PPO horizontal RMSE | policy 比 zero 高约 `0.04 m` | 更像横向/终端几何扰动 |

| SAC horizontal RMSE | 恶化约 `0.16 m` | terminal approach 被大 residual 改写 |


## 9. 决策与下一步

```text
decision = pivot
next = Goal151 residual authority / reward credit / terminal capture 只读审计
```

不换算法：本轮没有证据支持 REDQ/DroQ 或 SAC 替代 PPO。SAC 的失败是 action
authority 与 terminal approach 的直接伤害，不是样本效率不足。也不启动 Goal140
reward pilot，不扩 seed，不打开 held-out。

下一步先做低成本、只读、可复现的审计：

1. 用现有 PPO/SAC checkpoint 在 current07 做 residual scale `0 / 0.25 / 0.5 / 1.0`
   的 eval-only 剂量曲线；验证“低 scale 是否恢复 parity、full scale 是否单调有害”。
2. 对 SAC 做 channel-restricted eval：分别限制 heading、pitch、speed 通道，确认
   31 个 plane miss 是否由 heading/pitch 大残差直接解释。
3. 将失败 episode 的 residual 时间序列与 `reward_command_yaw/pitch/speed`、
   `reward_path_*`、`reward_terminal*`、`reward_goal_plane_miss` 对齐，检查是否存在
   reward 与实际 terminal capture 不一致。
4. 比较 terminal 前 32/64 步的 residual 幅度、pitch/heading error、goal-plane entry
   几何和最终 miss 距离；先证明机制，再预注册任何新的训练 arm。

只有剂量曲线证明“低 scale 可恢复，full scale 有害”，并且 channel cap 能保留收益，
才允许新开训练型 Goal；届时仍固定 PPO/SAC 两种算法，不在同一个 Gate 内换算法或
改 reward。
