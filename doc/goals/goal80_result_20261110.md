# Goal80 结果：goal-tangent 前移终端参考点会显著增加 plane miss

**日期**：2026-11-10<br>
**状态**：`TERMINAL_REFERENCE_HURTS`<br>
**预注册**：`doc/goals/goal80_terminal_reference_extension_20261110.md`<br>
**上游**：Goal27 `H3_SR_FAIL_STOP`、Goal64 `GEOMETRY_SUPPORTED`、Goal67 `TERMINAL_TRACKING_LAG`、Goal71 `TRACKING_IMPROVES_OUTCOME_UNCHANGED`、Goal79 `OBSERVABLE_FULL_VECTOR_PREDICTOR_NOT_SUPPORTED`

## 1. 结论

正式判定：

```text
default   -> TERMINAL_REFERENCE_HURTS
strict125 -> TERMINAL_REFERENCE_HURTS
overall   -> TERMINAL_REFERENCE_HURTS
```

把 terminal reference 沿 goal tangent 前移 `1.0 m` 是有效扰动，但不是有效的
terminal 修复：

- default true 从 `97/200` 降到 `80/200`，`true_success_delta=-17`；
- strict125 true 从 `44/200` 降到 `38/200`，`true_success_delta=-6`；
- plane-miss rate 分别增加 `+0.120` 和 `+0.060`；
- default 新增丢失的 18 个 baseline-true 中，`17` 个是 `GOAL_PLANE_MISS`；
  strict125 新增丢失的 10 个中，`8` 个也是 `GOAL_PLANE_MISS`；
- timeout 和 safety 都没有增加；pre-goal RMSE 只恶化 `1.23%/1.33%`；
- heading tracking error 反而改善 `0.186/0.207 rad`，但 outcome 显著变差。

因此 H80-A 被证伪，H80-B 和 H80-C 成立，H80-D 通过。当前问题不是“参考方向
不够朝前”，而是前移后载具更早、更靠外地穿过 goal plane，plane-miss guard
先于 tight capture 触发。

按预注册失败裁决，停止 goal-tangent 前移线，不扫 `0.5/2/4 m`、terminal window
或 seed；不启动 SAC/REDQ/DroQ。下一步应做只读的 termination/capture 审计，
先查 plane-miss guard、capture radius 和 terminal 状态估计，而不是换算法。

## 3. 主结果

pooled over 4 policy checkpoints + zero-residual：

| scenario | baseline true | candidate true | original lost | recovered | threshold | newly lost | true delta | false delta | plane miss delta | timeout delta | safety delta | RMSE rel delta |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| default | 97 | 80 | 6 | 0 | 3 | 18 | -17 | -7 | +0.120 | +0.000 | +0.000 | +1.23% |
| strict125 | 44 | 38 | 7 | 0 | 3 | 10 | -6 | -6 | +0.060 | +0.000 | +0.000 | +1.33% |

`original_lost = Goal60 true and not Goal71 limiter-on true`。预注册公式给出
default `ceil(0.40×6)=3`、strict125 `ceil(0.40×7)=3`；两个 scenario 的恢复数
都是 `0`，远低于门槛。

terminal 几何：

| scenario | horizontal offset paired median delta | vertical offset paired median delta | material saturation paired median delta | at least one offset improved |
|---|---:|---:|---:|---:|
| default | `-0.006 m` | `+0.045 m` | `-0.002` | false |
| strict125 | `+0.023 m` | `+0.054 m` | `-0.005` | false |

default 的 vertical offset 只差一点越过 `+0.05 m` 门限；strict125 则明确恶化
`+0.054 m`，plane miss 也增加。两个 scenario 都没有达到“至少一个 offset 改善
`>=0.05 m`”的机制门槛。

## 4. 机制：前移参考点导致更早穿过 goal plane

把 baseline-true episode 按 candidate 的 terminal 结果分类：

| scenario | retained true | lost as plane miss | lost as false success | lost as timeout/safety |
|---|---:|---:|---:|---:|
| default | 79 | 17 | 1 | 0 |
| strict125 | 34 | 8 | 2 | 0 |

新增丢失几乎全部是 plane miss，不是 timeout、safety 或单纯 false-success 增加。
这与 Goal64 的观察一致：tight capture 前先触发了 goal-plane guard。

extension 确实改变了 terminal command：

| scenario | original-lost extension angle median | terminal command changed seeds | candidate heading rate P90 | heading exceed | heading error improvement | pitch error improvement |
|---|---:|---:|---:|---:|---:|---:|
| default | `6.60°` | `1.000` | `0.524 rad/s` | `0.000` | `0.186 rad` | `0.028 rad` |
| strict125 | `7.62°` | `1.000` | `0.524 rad/s` | `0.000` | `0.207 rad` | `0.037 rad` |

heading tracking 改善、command limiter 仍有效，但 plane miss 和 true success 同时
变差。这说明“tracking 变好”不能替代 terminal capture；前移目标改变了接近
几何，使载具在横向/纵向误差尚未进入 tight radius 时先穿过 goal plane。

## 5. Policy vs zero-residual：仍不是 NoisyNet 主导

| scenario | arm | baseline true | candidate true | original lost | recovered | newly lost | true delta | false delta | plane miss delta |
|---|---|---:|---:|---:|---:|---:|---:|---:|---:|
| default | policy | 80 | 64 | 1 | 0 | 17 | -16 | -5 | +0.131 |
| default | zero | 17 | 16 | 5 | 0 | 1 | -1 | -2 | +0.075 |
| strict125 | policy | 33 | 27 | 6 | 0 | 8 | -6 | -3 | +0.056 |
| strict125 | zero | 11 | 11 | 1 | 0 | 2 | 0 | -3 | +0.075 |

这是对“大残差是不是被 NoisyNet 主导”的直接负控：

- 完全 zero-residual 时，1 m 前移仍使 default true 少 1、strict125 plane miss
  增加 `+0.075`；
- policy 和 zero 两个 arm 都朝同一方向变差，失败不是某个 noisy checkpoint 的
  采样偶然；
- 正式评估使用 deterministic mean，`sample_noise=False`；训练日志中的
  stochastic `residual_abs_mean` 不能当作评估残差；
- 此前 Goal59/67/79 已显示 deterministic saturation、低噪声 checkpoint 和
  zero-residual 仍然失败，当前结果没有推翻该归因。

所以现在不能通过关闭/缩小 NoisyNet 或重扫 residual scale 救这个 Gate。残余问题
在 terminal capture / plane-miss termination，而不是噪声幅度。

## 6. 假设裁决

| 假设 | 结果 | 理由 |
|---|---|---|
| H80-A：1 m 前移转化为 true retention | 不支持 | 恢复 `0/6`、`0/7`；newly lost `18/10`；true delta `-17/-6` |
| H80-B：extension 改变几何但 outcome 不变或变差 | 支持 | 几何扰动 `6.60°/7.62°`、tracking 改善，但 plane miss 和 true 同时变差 |
| H80-C：重复 Goal31 的“tracking 改善但 terminal 变差” | 支持 | plane miss `+0.120/+0.060`；strict vertical offset `+0.054 m`；true delta 为负 |
| H80-D：零扩展与 baseline 严格等价 | 支持 | episodes/trace 全等，extension-on 至少 37 个 trace field 改变 |

总体分类只能是 `TERMINAL_REFERENCE_HURTS`，不能写成 helps、no effect 或
optimization failure。

## 7. 预注册记录的一个数字偏差

Goal80 文档在 Gate 示例里写了 default `original_lost=9 -> threshold=4`，但同一份
预注册又明确 baseline 是 Goal71 limiter-on；按该定义重新读取 true-reference 后，
default 实际 `original_lost=6`，strict125 为 `7`。本分析使用预注册公式
`ceil(0.40×实际 original_lost)`，得到两个 scenario 的 threshold 都是 `3`。

这不是事后改阈值：无论用示例 `4/3` 还是按公式得到的 `3/3`，恢复数都是 `0`，
Gate 都失败；记录此偏差是为了避免后续把该 Gate 的 baseline 误写成 limiter-off。

## 8. 算力与完整性记录

- 远端 `384` CPU，10 个 run 并行，每进程单线程 BLAS；
- 从第一个 summary 到最后一个 summary 的墙钟约 `3.79 s`，输出约 `166 MB`；
- 0 张 GPU；8×RTX 4090 未用于本 CPU/float64 评估；
- 10/10 run 完成，无失败、无重试；
- analyzer `--jobs 10`，纯 CPU 读取已完成的 trace，未重新训练或 rollout。

这不是“只增加 batch 就能解决”的样本效率问题；增加 `num_envs`/batch 必须另开
训练型预注册 arm，且当前应先查 plane-miss termination，而不是扩大预算。

## 9. 下一步

按 H80-C 和 AGENTS 的失败升级规则：

1. 停止 goal-tangent 前移，不扫 `0.5/2/4 m`、terminal window、seed 或
   residual scale；
2. 新开预注册只读 Goal81：在 Goal80 原始 trace 上检查 plane-miss guard 是否在
   tight capture 前终止、terminal `p_nav/eta` 最小距离和 crossing signed offset；
3. 若确认是 terminal capture/termination 语义问题，再设计单因素 termination
   arm；不先换 reward/算法；
4. 不启动 SAC/REDQ/DroQ；没有 optimization/exploration 或 sample-efficiency
   证据；
5. 正式训练前才做 `num_envs 128/256/512 × batch 256/512` 的单卡吞吐基准，
   再按 seed 分 8 卡；扩采样/批量必须独立预注册。
