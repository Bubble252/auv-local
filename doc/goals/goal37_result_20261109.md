这说明不是单一 goal 字段的日志 typo：`route_tangent_ned` 在检查行与 path 0
投影切向一致，而与 seed 对应路径不一致。起状态和控制器/记录使用的路径在同一
episode 内不是同一条。

## 4. 为什么判为 INVALID

Goal37 在读取聚合结果前冻结了以下 invalidation 条件：

- trace goal/goal tangent 必须与 `path_bank[seed % 32]` 一致；
- start projection 必须在 start jitter 内；
- local projection tangent 必须在 crossing 行与 trace route tangent 一致。

当前数据满足 start 条件，但违反 goal/tangent/route 条件。若改用 trace 的 path 0
局部坐标系，起状态又会落在 start jitter 外；若改用 seed 对应路径，route/goal
又不是该路径。两种解释都无法构成一个一致的 path-local diagnostic。

因此不能把 JSON 中的 H 字段当作机制证据。它们只是沿冻结公式对不一致数据算出的
数值；例如 raw `H_FRAME` 字段看似支持，但这是“起状态在 expected path、goal 在
path 0”这一混合状态造成的，不是 goal-tangent 投影伪差的有效测量。

## 6. 对 Goal35/36 的影响

Goal35/36 的“初始垂直偏置”仍然是对 trace 记录的 `goal_ned_m`
（实际为 path 0）的描述，但它不能被当作同一路径上的真实初始状态偏置。Goal37
没有证明该偏置是 goal-tangent 投影伪差；它表明当前 Goal31 formal trace 的
start/path/goal provenance 不足以回答该问题。

保留的描述性事实：

- Goal35/36 的 goal-frame 数值可复现；
- 但对应 trace 的起状态来自另一条 seed 路径；
- 因此不能把这些数值用于局部 path-frame 机制裁决或控制器设计。
