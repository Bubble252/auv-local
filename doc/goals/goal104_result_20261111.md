# Goal104 结果：通道参数化有弱信号，但 R075/R125 只是单 seed 边界翻转

**日期**：2026-11-11<br>
**状态**：`CHANNEL_SIGNAL_WEAK / EVAL_ONLY / NO_TRAINING / NETWORK_PARITY_OK / NO_SAC`<br>
**上游**：Goal103 `CONTROL_AUTHORITY_LIMITED / PARAMETERIZATION_NOT_CAUSALLY_ISOLATED`<br>
**性质**：只读评估；未训练、未改 reward/terminal/success/goal radius，未打开 held-out。

## 1. 结论

Goal104 的 26 个 eval run 全部通过完整性校验，C0 精确复现 B20：

```text
default   33/40
strict125 20/40
timeout   0
safety    0
```

按冻结 Gate，存在两个合格 profile：

| profile | rudder gain | default | strict125 | default path ratio | strict path ratio |
|---|---:|---:|---:|---:|---:|
| `R075` | 0.75 | 33/40 | 21/40 | 0.9946 | 0.9947 |
| `R125` | 1.25 | 33/40 | 21/40 | 1.0064 | 1.0066 |

因此正式裁决为：

```text
CHANNEL_SIGNAL
```

但这个信号很弱：

- `R075` 只新增 strict seed `33`，无丢失，McNemar exact `p=1.0`；
- `R125` 只新增 strict seed `56`，无丢失，McNemar exact `p=1.0`；
- 两个方向相反的 rudder gain 都只增加 1 个 success，且增益不是单调剂量关系；
- 这不是“rudder authority 越大越好”或“越小越好”。

所以正确表述是：

```text
channel_parameterization_signal = present
rudder_direction_effect        = weak / non-monotonic
robust_success_improvement     = not established
sample_efficiency_blocker      = absent
sac_justification              = absent
```

## 3. 假设判定

### H104-A：stern 限制垂直捕获

`FALSIFIED`。

- `S125` strict 从 20 降到 18；
- `S150` strict 仍为 20，且新增 `25/27/50/51`、丢失 `37/40/44/46`；
- `S050/S075` strict 都是 19；
- 提高 stern 只把 default 拉到 35，没有把 strict 推过 20。

因此当前 strict 失败不是简单“stern authority 不够”。

### H104-B：rudder 限制水平/复合捕获

`PARTIAL_WEAK`。

- `R075` 和 `R125` 各自只增加 1 个 strict seed；
- 方向相反却同分，不是单调 authority；
- `R050` strict 不翻转，`R150` 是 `+1/-1` 净 0；
- 没有复现预注册中提到的 `32/47/52/58` 定向翻转。

所以测试到了 “rudder 改变会移动边界 seed”，但没有得到可复用的方向规律。

### H104-C：rpm/速度通道限制终端闭合

`POSTHOC_DIRECTIONAL_NOT_GATE_QUALIFIED`。

`U050` 是最强的方向性信号：

```text
strict125: 23/40
gained: 25, 51, 56, 59
lost:   24
McNemar exact p = 0.375
default: 32/40 (-1)
path ratio: 0.9737 / 0.9733
```

`U075` 也把 strict 提到 22，但 default 仍是 32。降低 rpm 似乎更有利于 strict 终端闭合，
代价是 default 不满足冻结 Gate 的 33。该现象只能作为 Goal105 的机制候选，不能写成
Goal104 的正式成功。

### H104-D：任何单通道都无信号

`FALSIFIED`。`R075/R125` 确实通过了冻结 Gate。

### H104-E：评估链/checkpoint 无效

`FALSIFIED`。C0 复现、SHA、seed、trace、有限值全部通过。

## 4. 终端边界解释

两个 Gate-qualified 的 strict 增益都非常贴边：

| profile | seed | C0 final distance | profile final distance | C0 plane miss | profile plane miss |
|---|---:|---:|---:|---|---|
| `R075` | 33 | 1.365 m | 1.236 m | true | false |
| `R125` | 56 | 1.265 m | 1.249 m | true | false |

两者都是 C0 在 goal plane 上 miss、改通道增益后刚好进入 1.25 m 半径；不是全轨迹明显
改善。`R125` 的 seed 56 单 episode path RMSE 仍为 3.683 m，说明这次 success 更像
“边界翻转”，不是“路径质量整体变好”。

因此：

```text
R075/R125_gain = terminal_boundary_flip
not            = robust_capture_mechanism
```

## 6. 统计与风险

- `R075`：strict `+1/-0`，exact McNemar `p=1.0`；
- `R125`：strict `+1/-0`，exact McNemar `p=1.0`；
- `U050`：strict `+4/-1`，exact McNemar `p=0.375`；
- 没有任何单 profile 在逐场景 5% 水平上显著；
- Gate 通过是预注册计数阈值，不等于统计显著；
- 所有 profile 的 `timeout/safety` 都是 0，path ratio 最大 `1.0181`。

## 7. 判读与决策

Goal104 证明：

1. C0 评估链有效，P_D3 没有被错误接线或 NoisyNet 替换；
2. 单通道参数化确实能移动 strict 边界，但当前最强信号只有 `+1`，且 rudder 方向不单调；
3. `U050` 的 `+4/-1` strict 方向更值得做机制确认，但它牺牲 default，未通过冻结 Gate；
4. 没有“方向正确但探索/样本效率不足”的证据，因此不开 SAC/REDQ/DroQ；
5. 不打开 held-out，不把单 seed 边界翻转写成稳定提升。

`decision = continue`

下一 Goal 应继续在 eval-only 参数化线，而不是训练新算法。建议预注册：

```text
Goal105:
  fixed: P_D3, scale 2.0, Goal85 unbiased, dev 20-59
  arms: C0, U075, U050, U050+R075, U050+R125
  focus: rpm lowering + rudder interaction
  required:
    default >= 33
    strict125 >= 23
    path <= 1.05 * C0
    timeout = 0
    safety = 0
  then:
    only after this dev gate passes, pre-register one held-out confirmation
```

该阈值把 `U050` 的 strict 方向与冻结 default 约束放在一起，避免只追 strict 而牺牲 default。
