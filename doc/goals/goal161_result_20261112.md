pitch-only 是当前最干净的 mask：

- current10 default `91/120`，3/3 seeds 非负；relative to C `+5`，但 relative to
  zero 仍只有 `+1`；
- current10 strict `53/120`，3/3 seeds 非负；relative to zero 仍为 `-4`；
- current15 与 C 完全相同，没有额外收益。

因此 channel restriction **能把 command residual 的危害压小，但仍不能超过
zero-residual H3**。H161-B 只得到“减少副作用”这一半支持，没有得到“产生净增益”。

## 4. 机制证据

1. zero 基线与 Phase A 完全一致：current10 default B/C zero 均为 `90/120`，
   strict 均为 `57/120`，评估口径没有漂移。
2. C 的 gate-active residual L2 ratio 在 current10/current15 约 `0.008`，pitch 在
   近端约 25–45% 步数达到 cap 的 95%；residual 不是零，也不是 NoisyNet 探索。
3. near-goal residual 与 goal distance 的 episode 内相关中位数约为
   heading `+0.90`、pitch `-0.85`、speed `-0.86`；与 signed 横向/纵向误差的相关性
   弱且跨层变号。它主要学成了终端距离 schedule，而不是状态反馈纠错。
4. C current15 把 `2–3 m` final-distance bin 减少 8 个，但 `>3 m` 仍为 21 个，
   entry/path/terminal 几何基本不变；current10 反而把 `2–3 m` bin 从 9 增加到 15。
   这是 success 边界翻转，不是系统性的终端几何修复。
5. 训练与评估风险全部通过：6/6 训练为 `1,000,192` transitions、cap 0.25、
   `direct_commands_active=false`、`speed_contract.ok=true`；评估 timeout/safety=0，
   无 NaN/Inf。C 的真实 terminal gate 位于 `command_residual.terminal_gate_enabled`
   （10→2 m），manifest 顶层 `residual_terminal_gate_enabled` 是 actuator 旧字段。

## 5. 归因

Goal160/161 合起来排除了以下解释：

| 解释 | 证据 | 结论 |
|---|---|---|
| residual 没打开 | 近端 residual 活跃，pitch 局部饱和 | 排除 |
| 权限太大 | deploy cap 0.25、训练 cap 0.25 仍无净增益 | 排除“仅幅度” |
| 需要 terminal-only | C 有 gate，但 current10 仍为负 | 不充分 |
| 需要 channel restriction | pitch-only 仍不超过 zero | 不充分 |
| NoisyNet/探索噪声 | deterministic 评估，动作来自确定性 actor | 排除 |
| 样本效率/优化不足 | 1M 有更新，5M 历史 run 无稳定增益；失败随 level 反向 | 不支持换 REDQ/DroQ |
| 加性 command 参数化 | residual 与距离强相关、与 signed error 弱相关；静态 H3 也呈现 level trade-off | 当前主因 |

结论：继续在 command residual 上扫 scale/channel 不是高信息量实验。下一步应预注册
**H3 + bounded heading/pitch controller-parameter residual**，学习低维增益修正，
而不是继续输出 heading/pitch/speed 的加性偏置。
