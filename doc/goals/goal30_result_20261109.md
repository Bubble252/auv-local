# Goal30 结果：可执行链上的 30 m 终端窗口 FAIL

日期：2026-11-09<br>
总体裁决：**FAIL / H1 FALSIFIED**（停止 ALOS terminal alignment window 主线）

## 1. 结论

在真正执行的 `ALOS -> PD/PI -> actuator` 链路上，把终端对准窗口从 `20 m` 前移到
`30 m` 没有改善 true-state terminal capture，反而稳定变差：

- default：`success_protocol` 从 `0.725` 降到 `0.600`（-0.125），plane miss 从
  `0.275` 升到 `0.400`（+0.125）；
- strict125：`success_protocol` 从 `0.500` 降到 `0.400`（-0.100），plane miss 从
  `0.500` 升到 `0.600`（+0.100）；
- `terminal_eta_capture` 在 default 从 `0.125` 降到 `0.100`，在 strict125 从
  `0.075` 降到 `0.025`；
- paired terminal horizontal-normal offset 在两个 scenario 都升高约 `0.0065 m`
  （default）和 `0.0501 m`（strict125）；terminal yaw error 也小幅升高；
- timeout、safety 都是 0，terminal speed ratio 基本不变，material saturation
  没有升高。

因此这不是“用安全/速度换指标”，而是更早直接对准目标改变了路径几何并降低了捕获。
Goal30 不继续扫 alignment window、不换 seed、不调 gain/reward，也不打开 held-out。

## 2. 协议

- baseline：B0，`ALOS -> PD/PI -> actuator`，`zero-command-residual`；
- candidate：同一 B0，只把 `terminal_alignment_min_m/max_m` 从 `20.0` 改为 `30.0`；
- checkpoint：Goal27 C1 `final.pt`，SHA256
  `0851496b15ffebbc0a19bafa5bf40c0493c0d9a3f485267b75fde5f811dde5d9`；
- dev seeds：`20–59`，default 与 strict125 各 40 个 paired episodes；
- held-out：`100–149` 未打开；
- 评估：`endpoint_stop`、`realistic_calibrated`、CPU/float64、`path_dim=8`；
- 无训练、无 validation 调参、无 best-iteration 选择。

判读：

- **H1 支持**：30 m 窗口相对约 `35 m` 的参考路径过长，terminal phase 占轨迹约
  `82%`，把大部分路径跟踪变成直接指向目标；vertical RMSE 和 terminal offset 同时
  变差。
- **H2 证伪**：终端 saturation 没有升高，反而下降；不是“横向权限不足/饱和”导致
  的失败。
- **H3 不支持**：terminal yaw error 与 terminal eta offset 的相关系数只有
  `0.02–0.16`，航向误差本身不能解释横向 miss。

## 7. 指标口径修正

screen 发现 `goal_capture_eta` 是“曾经进入半径”，不是“终止时仍在半径内”。
default candidate 曾在 step `1146` 进入 `1.81 m`，但 termination 距离为 `2.06 m`
且仍是 plane miss。因此本 Goal 的 formal 主指标使用 `terminal_eta_capture`，
`success_eta` 只作 ever-capture 诊断。该修正在 formal 数据产生之前记录；它移除了
screen 表面上唯一的 `success_eta +1` 假收益。
