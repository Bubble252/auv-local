## 2. PPO residual 的真实幅度

这是本 Goal 最重要的发现。以 reachable failure 的 `d < 3 m` 窗口为例：

| arm/seed | PPO residual 均值 `(rudder, stern, rpm)` | BC base 均值 `(rudder, stern, rpm)` |
|---|---|---|
| P0/25 | `(0.008, 0.014, 0.016)` | `(0.108, 0.292, -0.209)` |
| P0/27 | `(0.009, 0.013, 0.016)` | `(0.220, 0.275, -0.209)` |
| P0/31 | `(0.007, 0.008, 0.013)` | `(-0.131, 0.878, -0.170)` |
| P0/50 | `(0.007, 0.007, 0.013)` | `(-0.076, 0.163, -0.063)` |
| P0/51 | `(0.008, 0.014, 0.016)` | `(0.222, 0.569, -0.111)` |

PPO residual 的每个通道只有约 `0.007–0.016` 归一化单位；BC base 是
`0.06–1.36`。PPO 增量约为 BC base 的 **3%**，远不是“残差很大”。

Goal119/120 之前记录的 `83 RPM` / `200–250 RPM` 是
`actuator_residual_applied`，它包含 **BC base + PPO**。PPO 自己的贡献只有约
`0.01 × 1525 ≈ 15 RPM` 量级。因此：

```text
residual_applied_mean = 83 RPM
不等于
PPO_residual_mean = 83 RPM
```

PPO 策略实际上几乎没有离开零残差初始化。

## 3. 与历史 NoisyNet 问题的关系

用户之前怀疑“是不是被 NoisyNet 主导”。本 Goal 再次确认：

- 当前 PPO checkpoint 没有 NoisyNet / `rho` / `sigma` 参数；
- 评价是 deterministic mean；
- 训练噪声 std 固定为 `0.1`，但 deterministic PPO residual 只有 `0.01`；
- 所以不是 NoisyNet 主导，而是 **确定性 residual 头没有长大**。

这与 Goal7 的历史 NoisyNet 问题是不同机制：Goal7 是训练期隐藏层 sigma 主导，
本次是 actor 输出层在 10M PPO 后仍接近零初始化。

## 4. 假设判读

| 假设 | 结果 | 证据 |
|---|---|---|
| H121-A：动作权限存在，但 PPO 方向错误 | `PARTIAL` | 权限存在（rpm- Δeta 0.334 m；stern- 22/40）；PPO 方向本身只有 0.02 m 效果 |
| H121-B：residual 通道惰性 | `FALSIFIED` | 常量 stern-/rpm- 能改变 success 和终态 eta |
| H121-C：放大权限会改善 success | `NOT SUPPORTED` | ppo-2x/4x 仍 20/40；4x 只有 0.085 m |
| H121-D：取反 PPO 反而更好 | `WEAK` | neg-ppo 21/40，只多 seed 56；不是稳健增益 |

`stern-` 的 22/40 是一个方向性信号，但它只是常量手写 bias，不是学习策略；
不能把它当作正式 success 提升，也不能用它替代 SAC/PPO 对照。

## 5. 解释

当前失败链更准确地写成：

```text
action authority exists
-> PPO residual stays ~0.01 (near zero initialization)
-> closed-loop trajectory unchanged
-> no success movement
```

这不是“残差太大被 NoisyNet 主导”，也不是“动作通道完全没权限”。它是
**PPO 的 residual 头在长 episode、terminal-sparse 任务上没有获得足够梯度/
探索**，同时 BC base 已经接近包线，所以 PPO 的 3% 增量被闭环淹没。

## 6. 决策

预注册 Gate 判 `AUTHORITY_PRESENT`，但本 Goal 还不够判 SAC：

- 我们知道了“权限存在”；
- 我们还没有证明“PPO 学到的方向是对的，只是样本效率不足”；
- `ppo-4x` 仍无 success 增益，说明仅放大现有方向不够。

因此先做一个更便宜的 **PPO residual gain sweep**（Goal122）：

```text
ppo-8x / ppo-16x / ppo-32x / ppo-64x
```

如果 32x/64x 仍不能让 success 或终态 eta 移动，说明 PPO 学到的方向本身
没有可用信号；这时才预注册 SAC 同协议对照。若某个 gain 恢复 success，
则优先修 residual scale/gain，不换算法。

```text
decision = continue
next = Goal122 PPO residual gain sweep
```
