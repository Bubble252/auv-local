## 1. 结论

`P_D3` 与 `P_BC15` 两个 1-seed screen arm 都没有达到预注册阈值：

| arm | default | strict125 | 预注册阈值 | 判定 |

| `P_D3` | 30/40 | 19/40 | default >=31，strict >=21 | `FAIL` |
| `P_BC15` | 30/40 | 19/40 | default >=31，strict >=21 | `FAIL` |

作为同 seed 参照，Goal94 `S15_s86201` 的原始 summary 是 default `31/40`、
strict125 `20/40`（不是交接口头比较中的 `21/40`；本文以原始 summary 为准）。
因此两个 P-* arm 相对 S0 至少各丢 1 个 default、1 个 strict 成功，不能扩
`86202/86203`，也不能把失败解释成 seed 波动。

但这次不是“监督没有装上”：

- PPO/final 的 `residual_to_base_l2_ratio_mean` 为 `0.548–0.561`；
- magnitude clip 为 `0.714–0.721`，rate clip 为 `0.531–0.535`；
- path/endpoint/current encoder 在预训练 checkpoint 中全部非零；
- frozen BC 参数漂移为 `0.0`；
- timeout `0`、safety `0`、无 NaN/Inf。

因此准确表述是：

```text
supervised_prior_installed = true
closed_loop_gain           = false
screen                     = failed
```

PPO 微调也没有把先验变好：两臂 default 都从 initial `31` 降到 final `30`，
strict 都保持 `19`；frozen BC 是 default `31`、strict `20`。这说明当前 1M PPO
更新没有提供正的 terminal capture 增量，甚至损伤了 1 个 default 成功。

终端漏斗显示损失集中在近终端，而不是全局路径跟踪：

- default：`3 m` 入口 `36`，到 `2 m` 只剩 `30`；
- strict125：`2 m` 入口 `30`，到 `1.25 m` 只剩 `19`；
- strict125 失败样本中，距目标 `+1.00 m` 壳层有 `13` 个。

当前最合理的归因是 **terminal capture / reward-credit assignment**，不是
“网络结构接错”，也不是“NoisyNet 主导”。

## 8. 假设裁决

### H95-A：监督先验能打破 PPO residual 的零解锁定

**PARTIAL**。

- 成立部分：residual 非零，`residual/base` 约 `0.53–0.56`；三个 encoder 均加载
  且全非零；frozen BC drift `0`。
- 失败部分：闭环 success 没有提高；default 甚至从 `31` 降到 `30`。

所以“先验安装”成功，但“先验带来闭环增益”不成立。

### H95-B：path/endpoint encoder 必须参与预训练

**FALSIFIED**。

- path/endpoint encoder 预训练后非零；
- path-zero 没有使 success 或 pre-goal RMSE 恶化；
- 说明当前闭环没有表现出对 path 特征的因果依赖。

### H95-C：如果监督先验仍不改善闭环，问题不是初始化

**SUPPORTED**。

- 监督组合动作在离线目标和预训练 loss 上成立；
- PPO 从非零先验继续训练后，strict 仍是 `19/40`，default 还下降 1；
- frozen BC 仍是 default `31`、strict `20`；
- 因此剩余瓶颈指向 reward、terminal capture、credit assignment 和末端动作
  权限，而不是初始化、网络接线或 NoisyNet。
