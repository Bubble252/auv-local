# Goal107 结果：终端 reward 与几何都能区分成败，瓶颈在信用/优化方向

**日期**：2026-11-11<br>

**上游**：Goal106 `NO_SIGNAL`，近终端 rpm 门控路线停止<br>
**性质**：只读审计；固定 P_D3 checkpoint、success 契约、dev seeds 和评估协议。未训练、未改 reward/terminal/success/goal radius，未打开 held-out。

## 1. 结论

4/4 个 dev40 审计 run 完成，C0 复现 Goal105/106：

```text
default: C0 33/40, U050 32/40
strict125: C0 20/40, U050 23/40
timeout = 0, safety = 0
```

冻结 Gate 为：

```text
CREDIT_OR_OPTIMIZATION_LIMITED
reason = terminal_reward_and_geometry_BOTH_separate_but_C0_U050_gap_persists
```

核心判读：

- **terminal reward 不是缺失项**：strict125 的 `reward_terminal`、`reward_terminal_progress`、`reward_goal_plane_miss` 都能强区分 success/failure；
- **capture 几何也不是不可分**：final distance、vertical miss、heading、pitch、最后 2 s closure 都有大效应量；
- **失败不是 residual 幅度不够**：C0 失败种子的最后 2 s applied residual 反而更大；
- **缩小 residual 反而更好**：U050 把 strict 的 applied residual 从 C0 的 282/359 降到 161/169，同时 strict 从 20 提到 23。

因此当前主因不是“动作不够大”“reward 没信号”“NoisyNet 注入噪声”或“网络接错”，而是：

```text
PPO 残余动作的信用分配/优化方向不对：
失败种子在最后阶段施加了更大但方向不利的 residual；
降低 rpm residual 幅度能减少这种有害增量，但不能完成全部 strict capture。
```

## 3. Reward 审计（last 2 s）

strict125 的 success/failure 中位数与 Cliff's delta：

| reward 项 | success median | failure median | Cliff's delta |
|---|---:|---:|---:|
| `reward_terminal` | 300.000 | 0.000 | **1.000** |
| `reward_terminal_progress` | 6.399 | 3.763 | **0.765** |
| `reward_goal_plane_miss` | 0.000 | -105.336 | **1.000** |
| `reward_path_cross` | 52.317 | 118.139 | -0.485 |
| `reward_path_heading` | 15.569 | 31.787 | -0.190 |
| `reward_path_vertical` | -0.967 | 29.266 | 0.015 |
| `reward_command_pitch` | -5.117 | -14.367 | 0.840 |
| `reward_command_yaw` | -5.158 | -15.677 | 0.515 |
| `reward_total` | 271.538 | -165.932 | 1.000 |
| `reward_ppo_scaled` | 2.715 | -1.659 | 1.000 |

份额：

```text
failure terminal share          = 0.1689
failure path/speed/action share = 0.5336
```

解释：

- terminal 项本身有强信号，不是“奖励太弱”；
- 但在失败 episode 的最后 2 s，dense path/speed/action 项的绝对份额约为 terminal 的 3.2 倍；
- `reward_path_cross` 在 failure 中更大（118 vs 52），说明失败种子在最后阶段仍有较大的横向路径代价；
- 因此 reward 不是不可分，而是 terminal credit 被 dense 项包围，策略更可能优化“路径看起来对”而不是“最后 0.2 m 进去”。

这**不满足**预注册的 `TERMINAL_REWARD_UNDERWEIGHTED` 条件，因为 `reward_weak=false`；所以本 Goal 不改 reward。

## 4. Geometry 审计（strict125）

| geometry | success median | failure median | Cliff's delta |
|---|---:|---:|---:|
| `final_goal_distance_m` | 1.237 | 1.784 | **-1.000** |
| `terminal_horizontal_miss_m` | 1.167 | 1.044 | 0.000 |
| `terminal_vertical_miss_m` | 0.426 | 1.484 | **-0.905** |
| `terminal_abs_heading_error_rad` | 0.184 | 0.511 | **-0.555** |
| `terminal_abs_pitch_error_rad` | 0.201 | 0.602 | **-0.740** |
| `last2s_closure_mean_mps` | 1.582 | 0.929 | **0.765** |
| `last2s_closure_last_mps` | 1.403 | 0.122 | **0.965** |

解释：

- 失败不是“水平方向差一点”，而是**最后阶段闭合速度掉到接近 0**；
- `last2s_closure_last_mps` 的效应量最高（0.965），failure 的末段 closure 只有 0.122 m/s；
- 垂直 miss、pitch 和 heading 同时分离，说明失败 episode 在进入 1.25 m 硬壳前没有把姿态和高度收敛；
- 这与 Goal106 的“rpm 收益是全局量”一致：近终端局部降 rpm 不足以修复末段闭合。

## 5. Action 审计（last 2 s）

applied residual 的绝对值均值：

| scenario | profile | success median | failure median | Cliff's delta |
|---|---|---:|---:|---:|
| default | C0 | 288.50 | 501.54 | -0.342 |
| default | U050 | 160.76 | 170.74 | -0.008 |
| strict125 | C0 | 282.13 | 359.49 | -0.195 |
| strict125 | U050 | 160.70 | 169.02 | -0.079 |

解释：

- C0 的失败种子在最后 2 s 施加了**更大**的 residual（default 501 vs 288；strict 359 vs 282）；
- U050 把 residual 幅度整体压低到约 160–170，strict 反而从 20 提到 23；
- 因此“残差大”不是能力不足，而是 PPO 增量在最后阶段制造了方向不利的扰动；
- U050 的收益更像“减少有害增量”，而不是“学会了一个新的捕获动作”。

## 7. 网络结构与历史对照

用户要求网络结构问题必须和之前的情况/代码比对。本 Goal 用实际 checkpoint state_dict 与 Goal89 的逐张量 parity 审计对照：

| 项目 | P_D3 checkpoint | 历史契约/Goal89 审计 | 结果 |
|---|---|---|---|
| actor state encoder | `20→128→128→60` active + 4 reserved | `d_z_total=64`, `[128,128]` | 一致 |
| path encoder（PPO 分支） | `8→64→64` | path8 + endpoint4 拆分 | 一致 |
| path endpoint encoder | `4→32→64` | endpoint4 新增，末层零初始化 | 一致 |
| current encoder | `3→64→60` active + 4 reserved | current3，新增输出为零 | 一致 |
| actor | `131→256→128→3` | `64+3+64=131`, `[256,128]`, ELU | 一致 |
| frozen BC path encoder | `12→64→64` | BC 使用 path12 | 一致 |
| frozen BC actor | `131→256→128→3` | Goal86 P-A BC 语义 | 一致 |
| critic | `131→256→128→1` | 同主干 | 一致 |
| `std` | `(3,)` | PPO 的 log_std | 不是 NoisyNet |
| `noise/sigma` 参数 | 无 | PPO/SAC 不使用 NoisyNet | 一致 |

历史结论：

- Goal89 已对 Goal86 P-A BC 与 Goal89 PPO 的 22 个 `frozen_bc_*` state entry 做逐张量比对，`max abs diff = 0.0`；
- `d_z_total=64`、path12、command3、current3、actor `[256,128]` 从 Goal26/80 到当前没有被重写；
- NoisyNet 只属于历史 DDPG 线；PPO 的探索是 tanh Gaussian 的 `log_std`，SAC 的随机性来自其高斯策略，两者都没有 NoisyNet；
- Goal86 SAC 1M screen 也已明确 `NOISENET_DOMINANT=false`，T1 command residual 有害，T2 actuator residual 正向但不显著。

因此：

```text
network_wiring = same
noisenet_dominant = false
residual_magnitude_is_not_the_bottleneck
```

## 8. 判读

Goal107 同时排除了三类容易误判的方向：

1. **不是 reward 没信号**：terminal 项效应量接近 1；
2. **不是几何不可分**：末段 closure、vertical、pitch 都能区分；
3. **不是 NoisyNet/网络结构**：checkpoint 结构与历史 parity 一致，且无 noise/sigma 参数。

剩余最合理的解释是：

```text
PPO 的 residual credit assignment 在最后阶段把动作推大但没有推对；
U050 通过压低 rpm residual 减少了有害增量，却没有改变“谁来分配 terminal credit”这一层。
```

这也解释了为什么 Goal104–106 的常数/距离门控只能移动 default 和厘米级 strict：它们改的是 residual 幅度，不是 credit 结构。
