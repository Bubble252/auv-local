# Goal97 结果：scale 锚点错误，Phase 0 记为 INVALID

**日期**：2026-11-11<br>
**状态**：`INVALID_SCALE_ANCHOR / NO_GATE_RECORD`<br>
**上游**：Goal96 `DIRECTION_NOT_SUPPORTED / PPO_DEGRADES_PRIOR / NO_SAC`<br>
**性质**：eval-only scale sweep 的协议审计；未训练、未改 reward/terminal/success/goal radius，未打开 held-out。

## 1. 结论

Goal97 不能记为 `SCALE_SUPPORTED`、`SCALE_PARTIAL` 或
`SCALE_NOT_SUPPORTED`。预注册把 `s=1.00` 当作基线，但 Goal95 训练配置
`configs/lowlevel/goal95_20261111/p_d3_ppo.json` 与
`p_bc15_ppo.json` 的 `pc.actuator_residual_scale` 都是 `1.5`。

因此 Goal97 的整个 sweep 实际是：

```text
s ∈ {0.25, 0.50, 0.75, 1.00, 1.25}
全部低于训练时 scale = 1.50
```

`s=1.25` 比 `s=1.00` 更好，只能说明“缩小得少一些更好”，不能说明
“PPO 残差放大是问题”，也不能说明“更大 scale 有效”。按预注册纪律，记为：

```text
status = INVALID
gate_recorded = false
decision = pivot to corrected scale grid
```

## 2. 锚点复核

为排除随机性或 runner 实现差异，补跑同 checkpoint、同 dev40、同
success-frame 的 8 个 eval：

| arm | scenario | no override | override 1.50 | 结论 |
|---|---|---:|---:|---|
| P_D3 | default | 30/40 | 30/40 | 1.50 是 no-op |
| P_D3 | strict125 | 19/40 | 19/40 | 1.50 是 no-op |
| P_BC15 | default | 30/40 | 30/40 | 1.50 是 no-op |
| P_BC15 | strict125 | 19/40 | 19/40 | 1.50 是 no-op |

这与 Goal95 final 的 30/19 完全一致，说明评测链本身没有漂移；错误只在
Goal97 的 scale 锚点。

## 3. 无效 sweep 的实际结果

以下是 `scale_sweep_invalid_scale_anchor_summary` 的记录，只作为 exploratory
证据，不作为 Goal97 Gate。

| arm/scenario | s=0.25 | s=0.50 | s=0.75 | s=1.00 | s=1.25 |
|---|---:|---:|---:|---:|---:|
| P_D3 default | 25 | 27 | 27 | 29 | 30 |
| P_D3 strict125 | 16 | 16 | 15 | 16 | 18 |
| P_BC15 default | 25 | 26 | 28 | 28 | 29 |
| P_BC15 strict125 | 15 | 16 | 15 | 16 | 18 |

趋势是随 scale 接近 1.50 而改善，而不是出现了“某个小 scale 恢复 frozen
31/20”的证据。所有 run 的 timeout/safety 都为 0，path 3D RMSE 相对
`s=1.00` 的变化在 `0.9936–1.0053`，说明无效 sweep 本身没有明显的风险指标
异常。

## 4. 为什么不能写 FAIL

`INVALID` 与 `FAIL` 的区别是：

- `FAIL`：协议有效，假设被证据否定；
- `INVALID`：协议或锚点错误，测量不能回答假设。

本次属于后者。把 `1.00` 当成基线，等价于把训练时的 residual 人为缩小
33%，因此成功的单调改善可以被“接近 1.50”完全解释。若写成
`SCALE_NOT_SUPPORTED`，会错误地得出“PPO residual 净有害”的结论。

## 5. 与网络结构/NoisyNet 的关系

本次没有发现网络接线或 NoisyNet 参与：

- checkpoint SHA 与 Goal95 final 一致：D3
  `2d57745a811268553041c561f2ae1ad590dced472b712efd90cdd9c011c1a616`，
  BC15 `1a6a153d0d2e9548c2e14ebbe1b0fd33b65188a51be5958565b59885f494fe43`；
- 当前低层 PPO 无 NoisyNet，评价走确定性 `act_inference()`；
- 1.50 no-op 与 Goal95 30/19 完全一致，说明网络与评测链可复现。

因此这次失败是**协议锚点错误**，不是网络结构错误，也不是 NoisyNet 主导。
