# Goal64 结果：terminal capture 丢失由 goal-plane 几何触发

**状态**：`GEOMETRY_SUPPORTED`<br>

**上游**：Goal63 `PARTIAL_TERMINAL_SUPPRESSION`

## 1. 协议与完整性

Goal64 没有训练，也没有改 reward、observation、controller、checkpoint 或
Goal63 的 `0.25 m` margin。只把 Goal63 的 10 个 candidate rollout 用同一
`num_envs=40` 重跑，并增加只读 `--trace-output`。

- baseline：Goal60 的 40-seed dev trace；
- candidate：4 个 Goal59 checkpoint × `default/strict125` × policy，加 2 个
  forced zero-residual；
- GOAL 半径：`default 1.75 m`、`strict125 1.00 m`；
- plane-miss guard：原 `r0`，即 `2.00/1.25 m`；
- CPU / float64 / `endpoint_stop`；dev `20–59`；held-out `100–149` 关闭；
- 单 run 先做 40-seed 复现检查：与 Goal63 的 `success`、terminal kind、terminal
  `p_nav/eta` 距离逐 seed 完全一致（0 mismatch）；
- 解析器对每个 run 校验 checkpoint SHA、seed、finite、endpoint_stop 和 eval radius。

## 2. 主结果

### 2.1 strict125 policy 丢失组

6 个 baseline true-success episode 在 candidate 中没有保留。它们全部是
`GOAL_PLANE_MISS`，且全部从未进入过 `1.00 m` 的 candidate GOAL 半径。

| 指标 | lost_true (n=6) | retained_true (n=17) |
|---|---:|---:|
| terminal `p_nav` distance median | `1.254 m` | `0.979 m` |
| terminal `eta` distance median | `1.018 m` | `0.805 m` |
| terminal perpendicular offset median | `1.065 m` | `0.666 m` |
| minimum `p_nav` distance median | `1.172 m` | `0.979 m` |
| steps since last negative plane offset median | `20` | `0` |
| approach cosine median | `0.860` | `0.934` |
| last-100-step residual L2 median | `0.351` | `0.352` |
| action saturation fraction median | `1.000` | `1.000` |
| material saturation rate median | `0.210` | `0.340` |
| scale/rate clip fraction | `0.000 / 0.000` | `0.000 / 0.000` |

关键点：丢失组的 `minimum p_nav` 中位数是 `1.172 m`，高于 candidate 半径
`1.00 m` 约 `0.172 m`；同时 perpendicular offset 中位数达到 `1.065 m`。也就是
说，轨迹在横向仍有约一米偏差时先穿过 goal plane，plane-miss guard 先于收紧
GOAL 半径触发，根本没有机会继续进入 `r_tight`。

### 2.2 default 与 zero-residual

default policy 的 5 个丢失 true-success episode 也全部是
`GOAL_PLANE_MISS`；丢失组 perpendicular offset 中位数 `1.790 m`，minimum
`p_nav` 中位数 `1.884 m`，同样没有进入 `1.75 m` 的 candidate 半径。

zero-residual 的 5 个丢失 episode 全部是 `GOAL_PLANE_MISS`：

| scenario | n lost | plane-miss | perp median | `p_nav` median | `eta` median |
|---|---:|---|---:|---:|---:|
| default | 4 | `1.000` | `1.881 m` | `2.005 m` | `1.871 m` |
| strict125 | 1 | `1.000` | `0.691 m` | `1.250 m` | `1.367 m` |

default 的 zero-residual 与 policy 丢失组 perpendicular offset 中位数只差
`0.091 m`；strict125 zero 的唯一丢失 episode minimum `p_nav=1.045 m`，也只比
`1.00 m` 高 `0.045 m`。这与“通用 terminal geometry/approach”一致。

## 4. 机制解释

当前失败不是“残差不够大”或“NoisyNet 主导”。更准确的表述是：

1. Goal59 的 deterministic residual 已经很大，并且动作长期饱和；
2. 但丢失组和保留组的 residual L2 几乎一样，动作饱和也都接近 1；
3. 丢失的差异出现在 terminal 前约 20 步：轨迹在横向仍有约 `0.7–1.2 m` 偏移时
   穿过 goal plane；
4. plane-miss guard 使用原 `r0`，所以它在收紧 GOAL 半径之前终止，strict125
   尤其容易丢失 true capture；
5. forced zero-residual 也走同一路径，说明这不是 residual 策略特有，而是
   terminal capture 规则与接近几何的交互。

这也解释了为什么调大 residual、换 SAC/REDQ/DroQ 或继续训练不会直接解决：
当前 Gate 的失败发生在动作已经饱和后的终点判定/接近几何，而不是学习信号不足。

## 5. 算力利用

Goal64 充分利用了服务器资源，但没有改变评估语义：

- 10 个 candidate run 全部同时启动，`MAX_PARALLEL=10`；
- 每个 run 内部 `num_envs=40`，一次覆盖完整 dev seed，不重复 seed；
- 每进程 `OMP_NUM_THREADS=1`、`MKL_NUM_THREADS=1`，避免 384 CPU 上的线程过度订阅；
- 10 个 run 墙钟约 `16.5 s`；单 run 与 Goal63 逐 seed 一致；
- 解析器约 `80 s`，主要耗时是 10,000 次 seed-level bootstrap；
- 没有为了加速改变 dtype/device/终止规则，也没有增加无效的重复 env。

后续训练如果继续主线，应按 seed 分 GPU 并行，并在新预注册中明确更大的
`num_envs`/batch、固定总 transitions/UTD/replay 比例和评估协议；不能在正式 Gate
中静默改这些量。

## 6. 下一步

`decision = continue`，但**不重跑 Goal63，也不改 margin**。下一步应新预注册一个
eval-only 的 terminal rule 诊断，优先测试 plane-aware 或 `eta`-aware 的捕获条件，
例如在 GOAL 判定中同时要求：

- `p_nav`/`eta` 进入收紧半径；
- 垂直于 goal tangent 的 offset 小于几何余量；
- 或在 plane crossing 后保留一个很短的 dwell/`eta` 收敛窗口。

这只是候选诊断，不是正式协议。只有在新的预注册 Gate 中同时保住 true capture、
减少 false success、且不增加 timeout/safety，才允许讨论训练或算法升级。

不启动 SAC/REDQ/DroQ：本 Goal 没有优化/探索或样本效率证据。未来若出现明确
optimization/exploration 失败，新开预注册 Goal 用 SAC 同协议对照；若出现明确
sample efficiency 失败，再考虑 REDQ/DroQ。
