# Goal103 结果：B20 strict 失败是终端几何 + 大幅值残差参数化，不是网络接线

**日期**：2026-11-11<br>
**状态**：`CONTROL_AUTHORITY_LIMITED_LABEL / PARAMETERIZATION_NOT_CAUSALLY_ISOLATED / NETWORK_PARITY_OK / EVAL_ONLY / NO_TRAINING`<br>
**上游**：Goal102 `PPO_DOSE_HARM / PIVOT_TERMINAL_AUDIT`<br>
**性质**：只读审计；未训练、未新增 rollout、未改 reward/terminal/success/goal radius，未打开 held-out。

## 1. 结论

B20 strict125 的 20 个失败 seed 在两个 arm 上完全相同。按预注册规则，分类为：

```text
CONTROL_AUTHORITY_LIMITED
```

其中：

| 指标 | P_D3 | P_BC15 |
|---|---:|---:|
| strict 失败数 | 20/40 | 20/40 |
| shell failures | 6 | 6 |
| authority failures | 14 | 14 |
| nav/eta failures | 3 | 3 |
| 反事实半径 1.50 / 1.75 / 2.00 | 26 / 30 / 33 | 26 / 30 / 33 |

但这次审计不能把 `CONTROL_AUTHORITY_LIMITED` 直接解释成“限幅导致失败”：

- 失败集的 magnitude/rate clip 中位数是 `0.746/0.500`；
- 成功集反而更高，是 `0.872/0.613`；
- 失败集和成功集都大量贴边，clip rate 不能区分 outcome；
- `material_saturation_rate` 全为 0，但原因是 actuator wrapper 在送入环境前已经
  clamp，环境的 `material_saturated` 看不到这次 clamp，不能把它当作“没有物理饱和”。

因此正确定义是：

```text
authority_signature_present = true
authority_is_causal_discriminator = false
network_wiring_bug = false
residual_parameterization_needs_audit = true
```

## 2. 终端几何

`vertical_miss_m` 是在第一次 goal-plane 穿越处，误差向量去掉 goal-tangent 分量后
的 NED z 分量，不是全局高度差。20 个失败 seed 中：

- 13/20 的 vertical miss 大于 horizontal miss；
- vertical miss 中位数 `1.485 m`，horizontal 中位数 `1.043 m`；
- radial excess min/median/p90/max：
  `0.015 / 0.534 / 2.918 / 4.261 m`；
- 只有 6 个失败落在 `radius + 0.25 m` 内，不能写成“只差一点壳层”；
- 20/20 都到达 endpoint plane，20/20 都是 plane miss，不是 timeout 或 safety。

典型 seed：

| seed | miss | excess | vertical | horizontal | clip mag/rate |
|---:|---:|---:|---:|---:|---:|
| 25 | 1.326 | 0.076 | 1.284 | 0.329 | 0.87/0.62 |
| 33 | 1.365 | 0.115 | 1.261 | 0.522 | 0.99/0.73 |
| 52 | 5.048 | 3.798 | 1.816 | 4.710 | 0.79/0.34 |
| 58 | 5.511 | 4.261 | 1.097 | 5.401 | 0.95/0.41 |

这说明失败至少有两类几何：

1. 近壳层、以垂直捕获为主：`25/29/31/33/49/50/56`；
2. 较大的水平/复合 miss：`32/47/52/58`。

所以把 goal radius 从 1.25 m 改成 1.50/1.75/2.00 m 只能描述“壳层敏感性”，
不能替代 terminal capture 修复，也不能改写正式成功口径。

## 3. 残差动作参数化

B20 的 BC 输出不是小幅修正，而是大幅值、接近 bang-bang 的 actuator residual。

在最后 `3 m` 窗口，`frozen_residual_base_action` 的归一化 stern 通道：

| outcome | median | p95 | `abs>0.5` | `abs>1.0` |
|---|---:|---:|---:|---:|
| failure | 0.391 | 1.516 | 38.4% | 11.5% |
| success | 0.619 | 1.123 | 60.9% | 7.5% |

全 strict run 的物理 residual delta：

| 通道 | mean abs | 物理上限 |
|---|---:|---:|
| rudder | 0.354 rad | 0.262 rad |
| stern | 0.365 rad | 0.349 rad |
| rpm | 249 rpm | 1525 rpm |

也就是说，B20 的 `scale=2.00` 让 BC 残差在 rudder/stern 上平均已经超过全偏转，
执行动作经常被投影到边界。当前成功与失败更多取决于残差方向/终端几何，而不是
“是否贴边”。

这与历史情况不同：

- Goal7 的 NoisyNet 问题是训练期隐藏层 sigma 主导，真实存在；
- 本次评估是 deterministic mean，没有 NoisyNet；
- Goal89 已证明网络接线和冻结 BC 张量一致；
- 所以不能用旧的 NoisyNet 结论解释本次失败。

## 5. 真正需要改的是什么

当前不是“网络容量不够”，而是 action parameterization：

- BC 标签本身的 residual scale 是 `1.0`；
- Goal95 训练配置是 `1.5`；
- B20 评估 override 到 `2.0`；
- 评估包线是 BC 标签包线的 2 倍、训练包线的 1.33 倍；
- 大量 residual 在进入环境前就被 clamp，PPO 的小增量很难再改变已经贴边的动作；
- 成功集与失败集都高饱和，说明“再多一点 authority”不是充分方向。

因此下一步应做 **eval-only 通道级动作参数化审计**：

- 分别检查 rudder / stern / rpm 通道的 scale；
- 检查 joint norm 约束是否比逐通道 clamp 更能保留方向；
- 检查垂直捕获是否需要独立于水平通道的终端动作参数化；
- 只有在通道审计仍不能解释失败时，才进入 reward/termination audit；
- 不训练 PPO/SAC，不改 primary success，不打开 held-out。
