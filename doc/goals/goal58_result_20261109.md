# Goal58 最终结果：Off-policy 命令残差仍失败，饱和与终端捕获是主因

日期：2026-11-09<br>
状态：**OFFPOLICY_RESIDUAL_FAIL_PIVOT**<br>
预注册：`doc/goals/goal58_offpolicy_residual_credit_assignment_20261109.md`

## 1. 结论

Goal58 按预注册协议完成了 3 个独立训练 seed，每个 5M transitions、40 envs，
并在 dev seeds `20–59` 上用同一 checkpoint 做 `policy` 与 `zero-residual`
配对。结果不是边界噪声，而是明确的失败：

- 没有任何训练 seed 在任一场景达到 pre-goal 3D RMSE 改善 `>=0.10 m`；
- 三个 seed 的配对均值在 default 为 `-0.0051 m`，在 strict125 为 `-0.0150 m`；
- success 平均下降 `0.5167`（default）和 `0.4667`（strict125）；
- plane-miss 平均上升同样的幅度，timeout/safety 均为 `0`；
- applied residual 很大（`1.087–1.097`，L2 ratio `44.6–48.8%`），但三个 final
  deterministic policy 在 heading/pitch/speed 三个维度上 **100% 饱和**；
- NoisyNet 不是唯一原因：确定性 policy 本身已经饱和；NoisyNet 只在其上增加约
  `0.535×` 动作范数的探索；
- 把 S1 的 residual 缩小到 5–10% 可以去掉大部分伤害，但不能同时达到主效果并保住
  success；缩到 50% 时 pre-goal RMSE 改善约 `0.17 m`，success 却从 `0.725` 降到
  `0.600`，plane-miss 从 `0.275` 升到 `0.400`。

因此裁决为 **FAIL / PIVOT**：停止当前 off-policy 命令残差主线；“残差学不出来”
已经不是主因，当前主因是**动作参数化饱和 + 终端捕获/目标不对齐**。本 Goal 不启动
SAC、REDQ 或 DroQ；这些只能在新的预注册 goal 中检验。

## 5. 机制诊断

### 5.1 NoisyNet 不是主因

在 1M screen checkpoint 上，用训练 seeds `240–279` 的 200 control steps 做
deterministic/noisy 对照：

| 量 | 值 |
|---|---:|
| deterministic action abs mean（heading/pitch/speed） | `1.0000 / 0.9997 / 0.5252` |
| NoisyNet noise std / deterministic action norm | `0.535` |
| NoisyNet sample 与 deterministic mean 的 cosine | `0.865` |

NoisyNet 确实增加了探索幅度，但 deterministic mean 本身已经接近 `±1`。因此不能把
大残差归因于“评估时还在采样噪声”；评估已经使用 mean policy。

三个 final checkpoint 的 NoisyNet 参数也没有训练中膨胀：hidden 层
`softplus(rho)` 均值约 `0.299–0.300`，output 层约 `0.100–0.105`，与初始化
`0.3/0.1` 基本一致。因此这不是噪声方差失控，而是 mean-weight policy 自己把
`tanh` 推到了边界；NoisyNet 最多影响探索分布，不能解释确定性动作饱和。

### 5.2 final checkpoint 全部饱和

三个 final checkpoint 在训练 seeds 上各跑 200 control steps，三个维度的
deterministic saturation fraction 都是 `1.0`；applied residual 元素均值约 `0.327`，
L2 ratio 为 `42.1–47.4%`。这不是“学到了很小的修正”，而是把三个命令通道都推到边界。

### 5.3 residual scale 诊断

只对 S1 的 final checkpoint 做 eval-time multiplier 诊断，不改变训练，不把结果当作
新的 Gate：

|---:|---:|---:|---:|---:|---:|---:|
| 0（zero） | 0.725 | 2.643105 | 0.275 | 0.500 | 2.628682 | 0.500 |
| 0.02 | 0.700 | 2.631499 | 0.300 | 0.450 | 2.617546 | 0.550 |
| 0.05 | 0.700 | 2.614610 | 0.300 | 0.425 | 2.601546 | 0.575 |
| 0.10 | 0.650 | 2.592321 | 0.350 | 0.425 | 2.579870 | 0.575 |
| 0.20 | 0.625 | 2.557518 | 0.375 | 0.400 | 2.545184 | 0.600 |

| 1.00 | 0.400 | 2.609705 | 0.600 | 0.075 | 2.600329 | 0.925 |

解读：

- 小 scale 能减少伤害，但 `0.02` 的 RMSE 只改善 `0.012 m`，且 residual L2 低于
  1%，仍不满足主效果；`0.05` 的配对 RMSE 改善只有约 `0.023 m`（CI
  `[0.008, 0.037]`），success 仍下降；
- `0.50` 的 pre-goal RMSE 改善约 `0.17 m`，但配对种子均值 CI 跨零，success 下降
  `0.125`，plane-miss 上升 `0.125`；
- 因此“把 scale 调小”不能救当前策略；它只证明 saturation 放大了伤害，不证明
  saturation 是唯一原因。

### 5.4 reward / terminal capture 审计

当前 termination 使用 `p_nav` 与 goal tangent 平面的 signed offset：先判 `GOAL`
半径，再判 `GOAL_PLANE_MISS`；plane-miss 奖励是稀疏的
`-100 - 10 × excess`，`pc_ppo_scale=0.01`。residual 直接扰动
`[psi_d, theta_d, u_d]`，而 dense command penalty 会惩罚偏离 base 的命令。

这与已有 Goal30/31 的结论一致：**path RMSE 与 terminal capture 不是同一个指标**。
scale `0.50` 改善 path/pre-goal RMSE，却让 plane-miss 变差，说明 residual 学到的
方向更偏向路径跟踪，而不是终点平面捕获。下一步不能只用 pre-goal RMSE 作为唯一机制
证据，必须把 terminal capture 作为独立目标/护栏。
