# Goal110 结果：terminal 事件不足，失败大多在进入 2 m 前已经成形

**日期**：2026-11-11<br>
**状态**：`COMPLETED_AUDIT_ONLY / INSUFFICIENT_EVENTS / HELDOUT_CLOSED`<br>
**上游**：Goal109 `NO_DIRECTION_SIGNAL` / direction-only gate gap；Goal108 PPO/SAC 对照；Goal107 terminal credit<br>
**性质**：只读 Goal107 dev40 trace；未训练、未改 reward/terminal/success/goal radius、未打开 held-out。

## 1. 结论

按 Goal110 冻结 Gate，正式判读为：

```text
INSUFFICIENT_EVENTS
reason = fewer_than_60pct_failures_have_stall_rpm_and_geometry_events
```

strict C0 有 20 个失败，但只有 4 个同时具备进入 2 m、closure stall、rpm reversal
和几何事件，占 `4/20 = 20%`，低于预注册的 60%。因此：

- 不能判 `TERMINAL_GEOMETRY_PRECEDES_RPM`；
- 不能判 `RPM_REVERSAL_PRECEDES_STALL`；
- 不能判 `CLOSURE_STALL_FIRST`；
- 也不能把 `MIXED_OR_AMBIGUOUS` 写成机制结论。

这不是分析器接线失败。事件审计揭示了一个更强的描述性事实：大量失败在首次进入
2 m 之前就已经无法进入可评估的“进入后事件序列”。

## 2. 关键观测

### 2.1 strict C0

| 项目 | 数量/比例 |
|---|---:|
| 失败 episode | 20 |
| 从未进入 2 m | 7 |
| 进入过 2 m 的失败 | 13 |
| 可同时评估 stall/rpm/geometry | 4（20%） |
| 进入时几何阈值已满足 | 11/13 |
| 进入时 rpm 已反转 | 6/13 |
| 进入后才出现 stall | 5/13 |
| 4 个可评估 episode 的分支 | 4/4 `mixed` |

在进入 2 m 的 13 个失败中，事件中位数为：

```text
t_geom_s       = 0.00 s
t_rpm_flip_s   = 0.00 s
t_stall_s      = 0.66 s
stall - geom   = 0.66 s
stall - rpm    = 0.66 s
rpm - geom     = 0.00 s
```

这只能说明：可评估的少数样本在进入 2 m 时 rpm 与几何已经同时异常，之后才出现
closure stall；它不能说明所有失败都由进入后的 rpm 或几何单通道造成。

### 2.2 复现场景

| scenario | profile | success | failure | no entry | evaluable | 主要分类 |
|---|---|---:|---:|---:|---:|---|
| default | C0 | 33/40 | 7 | 7 | 0 | 全部未进入 2 m |

default 的 15 个失败全部没有进入 2 m；strict U050 也只有 1 个可评估事件。
因此两份重复对照都不能用于补救 strict C0 的分支判定。

## 4. 网络结构对照：不是 NoisyNet，也不是 `z_t` 接线错误

用户提示应与历史代码和旧 checkpoint 对照。结果与 Goal108 网络审计一致：

| arm | path 输入 | BC 加载 | 残差输出初始化 | actuator scale |
|---|---|---|---:|---:|
| Goal86 `P-A-SAC` | `bc_path_dim=8 + endpoint4` | D3 path8/state BC | `mu=0` | `0.25` |
| Goal86 `T2-SAC` | `bc_path_dim=12` | 无 | `mu=0` | `0.25` |
| Goal108 `B20-PPO` | `path8 + endpoint4` | frozen B20 BC + trainable 增量 | 末层零初始化 | `2.00` |
| Goal108 `B20-SAC` | `bc_path_dim=12` | `bc_checkpoint=null` | `mu=0` | `2.00` |

已核对的事实：

- Goal108 PPO 与 SAC 的 trainable state encoder 逐元素相同，actor input 都是
  `z_t64 + zero-DADE64 + command3 = 131`；
- 两个 initial checkpoint 的 deterministic 初始增量都为零，step 0 都复现 B20；
- 当前 PPO/SAC 没有 `rho`/`sigma`/NoisyNet 参数；历史 NoisyNet 只属于 Goal58/59
  DDPG 线；
- 但 Goal108 SAC 没有沿用 Goal86 `P-A-SAC` 的 `path8 + endpoint4 + BC encoder`，
  而是 `path12 + bc_checkpoint=null`，path encoder 随机初始化且末层非零。

因此可以排除：

```text
network_wiring_bug = false
noisenet_dominant  = false
state_encoder_parity_failure = false
```

必须保留的可比性边界是：

```text
Goal108 PPO/SAC 不是完全同构 arm
```

所以 SAC 的退化不能写成“纯 SAC 优化器不如 PPO”；更准确的表述是“未对齐的
path 参数化/初始化下，replay 把确定性残差推到了饱和”。PPO 自身 3/3 seeds
完全不动，仍是独立问题，不能由这个差异解释。

Goal110 的主分析使用冻结的 `P_D3` trace，不依赖 Goal108 SAC，因此网络结构边界
不改变本轮 `INSUFFICIENT_EVENTS` 判读。

## 5. 为什么本轮不能继续单通道归因

Goal110 的原始问题是：

```text
rpm 方向反转是 closure stall 的原因，
还是 terminal 几何先失败后，rpm 才被动反转？
```

数据给出的答案是“大多数失败根本没有落到这个可评估窗口里”：

- 7/20 从未进入 2 m；
- 13 个进入者中，11 个进入时几何已经越界；
- 只有 4 个能完整排序，且全部是 mixed。

因此继续在 2 m 之后比较 rpm/几何先后，会系统性删掉最关键的失败样本。下一步应把
锚点前移到 closest approach 和首次进入 3.0/2.5/2.0 m，先回答“接近阶段就失败，
还是进入后才失败”。
