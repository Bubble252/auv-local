## 1. 结论

按 Goal109 冻结 Gate，正式判读为：

```text
NO_DIRECTION_SIGNAL
reason = direction_separates_but_magnitude_does_not_no_preregistered_branch
```

```text
strict C0 的 rpm 方向指标单独达到 0.33；
但幅度指标没有达到 0.33，因此 H109-A 的“方向 + 幅度”条件不成立；
几何指标强分离，但冻结 Gate 要求方向全部 <0.33 才允许判为 geometry-limited；
结果落在预注册分支的空隙里，不能事后改 Gate 把它改判。
```

## 3. 方向审计

strict C0 的 success/failure 中位数：

| metric | success | failure | δ |
|---|---:|---:|---:|
| `rpm_speed_sign_alignment` | `0.6634` | `-0.3960` | `0.3825` |
| `rudder_heading_sign_alignment` | `-0.7327` | `-0.9703` | `0.0750` |
| `stern_pitch_sign_alignment` | `-0.2376` | `0.2178` | `-0.0825` |
| `applied_base_cosine_mean` | `-1.0000` | `-0.9901` | `0.0350` |
| `applied_base_cosine_p05` | `-1.0000` | `-1.0000` | `0.3000` |

解释：

- **rpm 方向有信号**：success 的 rpm residual 多数与 speed error 同向，failure 则多数反向；
- 但 rudder/stern 和 residual/base 整体余弦没有分离；
- default C0 的 rpm 方向更强（δ `0.5411`），说明该现象不是 strict 单场景偶然，
  但冻结 Gate 明确只看 strict C0，不能用 default 的事后结果把 strict 分支补上；
- 方向信号单独出现时，仍可能只是 terminal 几何失败的结果（例如已经进不去，
  速度误差和 rpm 指令随之翻转），不能直接写成因果。

## 4. 幅度与饱和审计

strict C0 的失败 residual 确实更大：

```text
success residual norm mean = 282.13
failure residual norm mean = 359.49
Cliff's delta              = -0.1950
```

但没有达到预注册的 `|δ| >= 0.33`；`residual_norm_p95` 只有 `-0.1400`，
`material_saturated` 在两组都是 `0`。因此当前 trace 不支持：

```text
failure = residual magnitude too large
failure = actuator saturation
```

这也与 Goal107 的结论一致：失败不是在“把动作推得更大”的轴上加预算就能修。

## 5. Terminal capture 审计

strict C0 的失败有非常明确的末段几何特征：

```text
final distance               success 1.237 m  vs failure 1.784 m
vertical miss                success 0.426 m  vs failure 1.484 m
abs heading error            success 0.184 rad vs failure 0.511 rad
abs pitch error              success 0.201 rad vs failure 0.602 rad
last2s closure last          success 1.403 m/s vs failure 0.122 m/s
last2s closure mean          success 1.582 m/s vs failure 0.929 m/s
```

壳层过渡（strict C0，最后 2 s 内位于阈值内的步数比例）：

| shell | success median | failure median | δ |
|---|---:|---:|---:|
| `<= 1.5 m` | `0.0990` | `0.0000` | `0.6100` |
| `<= 1.25 m` | `0.0099` | `0.0000` | `1.0000` |
| `<= 1.0 m` | `0.0000` | `0.0000` | `0.0000` |
| `<= 2.0 m` | `0.2624` | `0.2772` | `0.0725` |

解释：

- failure 并非在 2 m 外就完全不可达；它们能接近 2 m，但在 1.5 m 内几乎不停留；
- 进入硬壳前，垂直、pitch、heading 和闭合速度同时恶化；
- 这更像是 **terminal closure / capture 几何问题**，而不是单纯 residual 幅度问题；
- 但冻结 Gate 的分支要求 direction 全部 `<0.33` 才能判 `TERMINAL_GEOMETRY_LIMITED`，
  单条 rpm 方向指标过线使该分支无法成立。

## 6. Gate 分支歧义

本次结果暴露了预注册 Gate 的结构问题，而不是数据分析错误：

```text
direction_strong = true
magnitude_strong = false
geometry_strong  = true (6 features)
```

现有四个状态只有：

- 方向 + 幅度同时过线；
- 方向不过线、幅度过线；
- 方向和幅度都不过线、几何过线；
- 没有任何类别过线。

没有“方向单独过线”的分支。为了保持预注册纪律，本次不把
`NO_DIRECTION_SIGNAL` 改写成 `TERMINAL_GEOMETRY_LIMITED`，也不打开训练。
后续若继续，必须新开 Goal，预先定义 `DIRECTION_ONLY` / `GEOMETRY_WITH_DIRECTION_SIGNAL`
等分支，再运行分析。

## 7. 决策

```text
decision = pivot
next = Goal110 eval-only terminal closure onset / rpm direction audit
```

不训练 PPO/SAC/REDQ/DroQ/DADE，不扫 residual scale/channel gain，不改 reward、
terminal、success 或 goal radius。下一步只做更接近 terminal 的事件级分析：

- 以首次进入 2.0 m 或 closure 首次跌破 0.2 m/s 为事件锚点；
- 比较事件前后的 rpm 指令/误差符号、vertical error、pitch 和 closure；
- 判断 rpm 方向翻转是 closure stall 的原因，还是 terminal 几何失败的结果；
- 只有新 Goal 给出明确方向或几何机制，才允许预注册动作参数化或 terminal reward
  干预。
