# Goal141 结果：没有观察到 GOAL 吞 safety；success 的主要松动是球面边界内的纵向误差

**日期**：2026-11-11<br>
**状态**：`AUDIT_COMPLETE / PRIORITY_GAP_NOT_OBSERVED / SUCCESS_ENVELOPE_WEAK_VERTICAL / FAILURE_ALREADY_GEOMETRY_BAD / P_D3_UNAVAILABLE`<br>
**预注册**：`doc/goals/goal141_terminal_contract_audit_20261111.md`<br>
**性质**：eval-only 只读审计；未训练，未改 reward、termination、success 或 goal radius，未打开 held-out。

## 1. 结论

这次审计把“终止条件不明确”拆成两个问题，结果不是同一种状态：

```text
GOAL / GOAL_PLANE_MISS 覆盖已触发 safety：0/80（未观察到）
success 回合 terminal 姿态/速度越界：没有；只有 terminal vertical error
success 球面边界内的 |vertical_error|：BC 4/15、zero 2/14 超过 1.0 m
failure：BC 25/25、zero 26/26 全是 GOAL_PLANE_MISS
failure 的 |vertical_error|：BC 21/25、zero 22/26 超过 1.0 m
```

因此：

1. **“某个 safety 条件没算进去，导致 bad state 还在跑”不是当前 dev40 的主要现象**。
   BC 与 zero 两臂的 raw roll/depth/bounds/invalid/NaN safety 计数全是 0；
   `GOAL` 或 `GOAL_PLANE_MISS` 与 safety 同时发生也是 0。
2. **success 定义确实偏松，但松在纵向位置，不在姿态/速度**。
   BC 成功回合的 `|pitch| <= 0.388 rad`、`|q| <= 0.241 rad/s`、
   `|w| <= 0.297 m/s`，都没有超过预注册候选阈值；唯一命中是
   `|vertical_error| >= 1.0 m`，共 4/15，且值只到 1.03-1.05 m。
   这与 goal 球半径 1.25 m 的 endpoint-stop 截断一致：成功样本的
   terminal `eta` 距离全部挤在 `1.207-1.247 m`。
3. **当前 failure 仍然主要是几何失败，不是“少了一个 terminate 条件”**。
   两臂 failure 全部是 `GOAL_PLANE_MISS`，terminal vertical error 中位数
   分别 `1.65 m`（BC）和 `1.83 m`（zero）。追加 vertical-error 终止会把这些
   episode 更早判失败，但不会让策略学会修正纵向误差。
4. **优先级代码本身仍有契约风险**。单元测试证明：在 endpoint-stop 分支里，
   已经满足 `t_phi_term_s` 的横滚 safety 可以被 `GOAL` 或
   `GOAL_PLANE_MISS` 覆盖，并且 `safety_event` 会变成 false。这个风险在本
   dev40 样本中没有实际触发，但不能因为“这次没遇到”就认为契约正确。

一句话判读：

```text
终止条件不是当前 BC proxy 失败的主因；
success 的纵向包络值得单独定义；
GOAL > safety 的优先级风险需要保留为 contract bug，而不是混进 reward 设计。
```

## 3. 终止优先级审计

代码事实：

```text
endpoint-stop:
  GOAL > GOAL_PLANE_MISS > timeout/safety/bounds
legacy:
  GOAL 先写入，随后 safety/bounds 覆盖
```

新增测试 `tests/test_pc_goal141_terminal_contract.py` 固定了 endpoint-stop 的两个行为：

- 横滚 safety 已达到 `t_phi_term_s` 后，若同一帧进入 goal 球，返回 `GOAL`，
  `safety_event=false`；
- 横滚 safety 已达到后，若同一帧满足 plane-miss，返回
  `GOAL_PLANE_MISS`，`safety_event=false`。

所以优先级问题在代码层面存在。只是本 Goal 的 80 个 dev episodes 没有产生
这样的共存状态，不能说它是当前失败的主因。

## 5. 判读

| hypothesis | 结果 | 证据 |
|---|---|---|
| H141-A：GOAL 携带不可接受 terminal 包络 | `SUPPORTED`（但仅纵向） | BC `4/15`、zero `2/14` 的 `|vertical| >= 1m`；pitch/rate/heave 均为 0 命中 |
| H141-B：GOAL / plane-miss 覆盖 safety | `FALSIFIED`（本样本） | raw safety 全 0，co-occurrence `0/80`；但单元测试证明代码可覆盖 |
| H141-C：缺失 terminal 条件能解释 failure | `PARTIAL / RELABEL_ONLY` | failure 84%-85% 命中 vertical 包络，但 100% 已是 plane-miss，且 vertical miss 中位数 1.6-1.8 m |

因此不要把 H141-A 直接翻译成“再奖励一点 vertical error”或“把 vertical
termination 加进环境”。前者是 Goal140 的 tracking reward 问题，后者是
success contract 问题，二者需要分开预注册。

## 6. 下一步建议

优先级从高到低：

1. **保留当前 goal/success 定义做正式训练**，继续 Goal140 的纵向 tracking
   reward/constraint；本审计没有证明现有 safety 漏掉导致 failure。
2. **另开一个 terminal-contract Goal**，只处理 `GOAL > safety` 的优先级；
   建议规则是 safety/bounds/NaN 优先于 GOAL，并补 `GOAL + roll dwell`、
   `plane-miss + roll dwell` 的回归测试。此项不应和 reward 实验混在一起。
3. **若要报告“严格纵向 success”**，新增离线指标即可，例如
   `GOAL and |vertical_error| <= 1.0m`，先作为 secondary metric；在用户明确
   同意前不改正式 success、goal radius 或训练终止。
4. **取回 P_D3/final.pt 后复跑同一审计**，确认 PPO final 是否也有
   `GOAL` 球面边界纵向误差；本机 BC proxy 不能替代该结论。
