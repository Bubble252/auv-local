# Goal39 result：provenance 一致数据上的垂直 miss 重裁无效

**日期**：2026-11-09<br>
**状态**：`RESULT_COMPLETE / INVALID_DIAGNOSTIC`<br>
**上游协议**：`doc/goals/goal39_goal38_vertical_readjudication_20261109.md`<br>
**Ledger decision**：`pivot`

## 1. 结论

Goal39 的输入和执行链全部通过预注册检查，但三个冻结分析器都返回
`INVALID_DIAGNOSTIC`。原因不是 trace 损坏，也不是 analyzer 失败，而是修正 path
provenance 后 vertical-miss seed 数显著下降：

| scenario | mode | 旧 Goal31 vertical-miss n | fresh Goal38 n | 原最小样本 |
|---|---|---:|---:|---:|
| default | baseline | 25 | 9 | 10 |
| default | candidate | 25 | 7 | 10 |
| strict125 | baseline | 31 | 19 | 10 |
| strict125 | candidate | 32 | 16 | 10 |

Goal34/35/36 的 old trace 使用 path 0 计算 goal/tangent；修正后 default 两个 block
都不足 10 个 vertical-miss seeds，因此原冻结规则把整体判为
`INVALID_DIAGNOSTIC`。不能为了继续解释机制而降低这个阈值，也不能把旧
`GLOBAL_CARRYOVER_SUPPORTED` / `INITIAL_OFFSET_DOMINANT` 直接搬到新数据上。

## 2. 输入与完整性

四个 trace SHA256、三个 analyzer SHA256、seeds `20-59`、checkpoint SHA256 和
Goal38 provenance 全部与预注册一致；held-out `100-149` 未打开。所有 block 都是
40 seeds，checkpoint 正确，baseline/candidate 初始几何最大差为 `0.0`。

因此本 Goal 的 invalid 是**样本定义和样本量**问题，不是数据完整性失败。

## 3. 三个分析器的结果

| analyzer | H verdicts | overall | invalid reason |
|---|---|---|---|
| Goal34 | H-GLOBAL / H-PHASE / H-SLOPE = FALSIFIED | `INVALID_DIAGNOSTIC` | default vertical-miss n `9/7 < 10` |
| Goal35 | H-INITIAL / H-TRACK / H-HANDOFF = FALSIFIED | `INVALID_DIAGNOSTIC` | 同一 vertical-miss guard |
| Goal36 | H-STATE / H-REFERENCE / H-START-DYNAMICS = FALSIFIED | `INVALID_DIAGNOSTIC` | 同一 vertical-miss guard |

这些 H verdict 是在 invalid 数据上按原公式算出的原始字段，不作为机制裁决。
Goal39 不允许把它们写成 `NO_SUPPORTED_MECHANISM`，也不允许写成 controller FAIL。

## 4. 描述性发现

只能作为下一步设计依据，不能作为机制结论：

- 修正后的 vertical-miss 数从 `25/25/31/32` 降到 `9/7/19/16`；
- default 的 vertical-miss 比例降到 `22.5% / 17.5%`，strict125 为
  `47.5% / 40.0%`；
- 但 Goal38 的 plane miss 仍为 `27.5% / 30.0%` 和 `50.0% / 52.5%`，说明失败
  集合并不等于 vertical-miss 集合；
- 旧 Goal35/36 的“初始垂直偏置主导”很可能受到 stale path 投影放大，但当前样本
  不足以重新裁决。

## 5. 假设裁决

```text
H-PROVENANCE-SENSITIVE = SUPPORTED by miss-count shift
H-MECHANISM-SURVIVES    = NOT ADJUDICATED (invalid sample guard)
```

`H-PROVENANCE-SENSITIVE` 只说明旧轨迹的 vertical-miss 标签对 path 修复敏感；它
不证明新的失败机制是水平、垂直还是 estimator/protocol 差异。

## 6. 裁决与下一步

```text
decision = pivot
```

停止在旧 vertical-miss 子群上重裁。下一步预注册 Goal40：

- 使用四个 block 的全部 40 seeds，而不是只取 vertical-miss 子群；
- 把 terminal plane miss / eta miss 的 horizontal-normal、vertical、longitudinal
  分量拆开；
- 同时检查 `p_nav` protocol success 与 true-`eta` terminal capture 的 discordance；
- 不训练、不新增 rollout、不改控制器、不打开 held-out。

这不会降低旧阈值；它改变的是研究问题：先确定修正后剩余的失败到底由哪个终端
分量构成。
