# Goal35 结果：初始垂直偏置主导，早期跟踪与 20 m 交接未获支持

日期：2026-11-09<br>
总体裁决：**INITIAL_OFFSET_DOMINANT**<br>
局部裁决：`H_INITIAL = SUPPORTED`，`H_TRACK = FALSIFIED`，
`H_HANDOFF = FALSIFIED`。

## 1. 结论

Goal35 只读 Goal31 的四组 40-seed formal traces，检查了 episode 初始垂直偏置、
`40 m -> 20 m` 的 reference/actual pitch tracking，以及
`guidance_terminal_phase` 的 20 m 交接。

- **H-INITIAL 得到支持**：四个 block 的初始绝对垂直误差中位数为
  `8.05-8.94 m`，初始距离中位数约 `34.2 m`；`84.0%-96.9%` 的 vertical-miss
  seeds 在初始行已位于捕获半径之外。初始误差对 terminal 绝对垂直误差的
  Spearman 为 `0.5270-0.6215`，初始/终端误差中位数比为 `1.6752-1.7727`。
  终端 miss 首先是一个初始几何/起始参考偏置问题。
- **H-TRACK 被证伪**：reference pitch 幅度足够（中位数 `0.1437-0.1720 rad`），
  pitch tracking error 也很大（`0.1488-0.1547 rad`），但 reference pitch 的
  desired-direction sign match 中位数只有 `0.4677-0.5132`，低于预注册 `0.60`；
  tracking error 与 terminal miss 的 Spearman 也只有
  `-0.0517-0.1023`。因此不能把当前结果写成“reference 正确，只是内环跟踪不足”。
- **H-HANDOFF 被证伪**：20 m 交接处 pitch command jump 中位数为
  `0.1656-0.1797 rad`，说明交接确实改变了 reference；但 post-window 的
  垂直误差中位数没有变差（`vertical_worsening` 中位数为 `0`），且
  worsening 与 terminal miss 的 Spearman 为
  `-0.1714-0.1876`。交接不连续本身不能解释 terminal miss 的排序。

按预注册总体表，下一步不是改 pitch gain、延长 terminal window 或扫 reward，而是
先诊断初始状态/起始参考几何为什么让 vertical-miss seeds 一开始就落在半径外。

解释：

- 初始误差已经远大于捕获半径，且与 terminal 误差保持中等偏强排序关系；
- terminal 段确实降低了绝对误差，但中位数仍为 `4.63-5.34 m`；
- 这不是“终端段新出现”的误差，也不是单纯 authority 不足。

限制：初始偏置可能是初始状态随机化、起点到 goal 的参考几何、或初始 pitch
状态共同造成；Goal35 不能区分这三者。

## 4. H-TRACK：reference 方向与 tracking 排序都不支持（FALSIFIED）

| scenario | mode | command pitch med (rad) | tracking error med (rad) | ref sign match | tracking-terminal rho | high-low delta (m) | verdict |
|---|---|---:|---:|---:|---:|---:|---|
| default | baseline | 0.1437 | 0.1488 | 0.4799 | 0.1023 | 0.0643 | FAIL |
| default | candidate | 0.1554 | 0.1501 | 0.4677 | 0.0838 | 0.3722 | FAIL |
| strict125 | baseline | 0.1479 | 0.1488 | 0.5037 | 0.0685 | 0.5501 | FAIL |
| strict125 | candidate | 0.1720 | 0.1547 | 0.5132 | -0.0517 | -0.5372 | FAIL |

解释：

- reference pitch 不等于零，tracking error 也不小；
- 但 reference pitch 在 desired vertical direction 上的 sign match 不到 `0.60`，
  说明 reference 本身并不总是朝向减小当前垂直误差；
- tracking error 与 terminal miss 的相关性接近零，且高低组方向不稳定；
- 因此 H-TRACK 的核心前提“reference 方向正确”不成立，不能把大 tracking error
  直接解释为内环问题。

## 5. H-HANDOFF：有 reference jump，但没有单调恶化（FALSIFIED）

| scenario | mode | pitch jump med (rad) | worsening med (m) | closure drop med | worsening-terminal rho | high-low delta (m) | verdict |
|---|---|---:|---:|---:|---:|---:|---|
| default | baseline | 0.1656 | 0.0000 | 0.3140 | -0.0698 | 1.0271 | FAIL |
| default | candidate | 0.1797 | 0.0000 | 0.0000 | -0.1714 | -0.3463 | FAIL |
| strict125 | baseline | 0.1768 | 0.0000 | 0.1361 | 0.1876 | 0.8365 | FAIL |
| strict125 | candidate | 0.1763 | 0.0000 | 0.0050 | 0.1171 | 0.5162 | FAIL |

解释：

- `guidance_terminal_phase` 交接处确实存在明显的 reference pitch 跳变；
- 但 post-window 的绝对垂直误差中位数没有上升，closure drop 也不是所有 block
  都存在；
- worsening 与 terminal miss 的排序关系不满足预注册 `>= 0.30`；
- 因此“20 m 交接造成不连续并加剧垂直 miss”的因果链不成立。交接是伴随现象，
  不是当前 traces 支持的主机制。
