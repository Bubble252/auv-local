# Goal155 结果：训练时 residual gate 收回了 path，但没有收回 success

**日期**：2026-11-12<br>
**状态**：`COMPLETED / CAPTURE_TRADEOFF / HELDOUT_CLOSED`<br>
**上游**：Goal86 T2-SAC、Goal151 near10_2、Goal152 train-time gate、Goal154 authority confound<br>
**性质**：预注册 1M training screen；不改 reward、terminal、success、radius、算法、held-out。

## 1. 裁决

正式 CPU/float64 复评的 verdict 为 **`CAPTURE_TRADEOFF`**。

这不是“gate 没生效”，也不是“residual 全零”。实际发生的是：

- gate 确实把 3D path RMSE 收回到 zero 附近；
- 但训练时 gate 也把 success 压回 zero 附近，甚至低于 zero；
- `near10_2` 最接近 zero，`mid_only` 和 `far_off_only` 更差；
- 因此不能把训练时硬 gate 直接推进到 5M formal。

## 2. 主表

协议：`3 training seeds × 40 dev seeds = 120` 配对；default `2.0 m`，strict125 `1.25 m`；
checkpoint 为各 arm 的 `final.zip`；评估设备 CPU/float64。

| arm | scenario | policy / zero | Δsuccess | path P/Z (m) | Δpath (m) | Δvertical (m) | Gate |
|---|---|---:|---:|---:|---:|---:|---|
| `full` | default | `86/81` | `+5/120` | `2.6041 / 2.3272` | `+0.2769` | `-0.0041` | FAIL path |
| `full` | strict125 | `46/42` | `+4/120` | `2.5977 / 2.3223` | `+0.2754` | `-0.0029` | FAIL path |
| `near10_2` | default | `80/81` | `-1/120` | `2.3275 / 2.3272` | `+0.0003` | `+0.0012` | FAIL success/seed |
| `near10_2` | strict125 | `44/42` | `+2/120` | `2.3225 / 2.3223` | `+0.0002` | `+0.0018` | FAIL success |
| `mid_only` | default | `75/81` | `-6/120` | `2.3289 / 2.3272` | `+0.0017` | `+0.0061` | FAIL success/seed |
| `mid_only` | strict125 | `42/42` | `0/120` | `2.3246 / 2.3223` | `+0.0022` | `+0.0065` | FAIL success |
| `far_off_only` | default | `75/81` | `-6/120` | `2.3333 / 2.3272` | `+0.0061` | `+0.0179` | FAIL success/seed |
| `far_off_only` | strict125 | `42/42` | `0/120` | `2.3277 / 2.3223` | `+0.0053` | `+0.0186` | FAIL success |

`full` 精确复现 Goal86 的方向：success 弱正、path 约 `+0.277 m`。这说明新评估管线、
zero 对照和 checkpoint 读取链路可信，gated arms 的失败不是评估器造成的。

## 3. Seed 一致性

default success，逐 seed 对比 zero `27/40`：

| arm | 86201 | 86202 | 86203 | seed 结论 |
|---|---:|---:|---:|---|
| `full` | `28` (`+1`) | `29` (`+2`) | `29` (`+2`) | 3/3 非负 |
| `near10_2` | `29` (`+2`) | `25` (`-2`) | `26` (`-1`) | 1/3 非负 |
| `mid_only` | `24` (`-3`) | `27` (`0`) | `24` (`-3`) | 1/3 非负 |
| `far_off_only` | `23` (`-4`) | `26` (`-1`) | `26` (`-1`) | 0/3 非负 |

`full` 的 success 方向在 3 个 seed 上都为正，但 path 代价集中在 86202/86203
（`+0.4204 / +0.3961 m`）；86201 的 path 只有 `+0.0141 m`。这再次说明 full 训练的
收益和 path 代价都依赖 shell 内动作，而不是全局零残差。

## 4. Residual 结构

按 `<=2 m / 2–10 m / >10 m` 分箱，pooled trace：

| arm | RMS <=2 m | RMS 2–10 m | RMS >10 m | bias <=2/2–10/>10 | head saturation |
|---|---:|---:|---:|---|---:|
| `full` | `1.4639` | `1.3724` | `1.3299` | `0.256 / 0.411 / 0.440` | `0.602` |
| `near10_2` | `1.5476` | `0.9134` | `0.0001` | `0.715 / 0.461 / 0.005` | `0.584` |
| `mid_only` | `0.0097` | `0.9337` | `0.0003` | `0.233 / 0.177 / 0.002` | `0.616` |
| `far_off_only` | `1.5709` | `1.4662` | `0.0424` | `0.666 / 0.688 / 0.020` | `0.492` |

结论：

1. gated arms 没有塌缩成零残差；`near10_2` 和 `far_off_only` 在 shell 内仍有
   `0.91–1.57` 的 residual RMS；
2. `mid_only` 的 `<=2 m` residual 接近零是 gate 设计使然，不是训练塌缩；
3. `full` 的远段 residual 仍有高 bias fraction（`0.440`）和高 lag-1（`0.987`），
   与 Goal154 的“持续偏置”一致；
4. 训练时 gate 降低了远段动作，但没有把 shell 内动作转化成更高的 success。

## 5. Terminal capture

final goal distance 分布（120 episodes）：

| arm | median (m) | p90 (m) | within 2.5 m | within 3.0 m |
|---|---:|---:|---:|---:|
| `full` | `1.9894` | `3.0481` | `0.8000` | `0.8833` |
| `near10_2` | `1.9930` | `2.6786` | `0.8500` | `0.9750` |
| `mid_only` | `1.9954` | `2.8073` | `0.8417` | `0.9583` |
| `far_off_only` | `1.9963` | `2.9283` | `0.8083` | `0.9167` |

`near10_2` 的 p90 和 3 m 内比例明显优于 `full`，但 default success 仍为 `80/81`，
strict125 只有 `44/42`。因此“把远段 residual 关掉”改善了 terminal 尾部，却没有
解决从 2–3 m 到 goal 的最后一段捕获；这正是 `CAPTURE_TRADEOFF` 的含义。

## 6. 机制判断

最符合数据的解释不是“gate 位置错”，而是：

- full-authority 训练先探索到 shell 动作，再在部署时 gate，能保留 Goal154 的
  `mid_only` 收益；
- 训练时从一开始就 gate，actor 没有机会学习远段动作对 terminal capture 的信用，
  shell 内的 residual 也被压小；
- `near10_2` 是训练时 gate 的最好变体，但仍未过 success Gate；
- `mid_only` 完全关闭 `<=2 m` residual，success 最差，说明最后一段仍需要权限；
- `far_off_only` 保留 shell 内全部动作，但 success 仍低于 zero，说明仅关闭 >10 m
  不足以保证 credit 分配到 terminal capture。

## 7. 决策

- **不**扩 seed、不换算法、不放宽阈值、不打开 held-out；
- **不**把训练时 `near10_2/mid_only/far_off_only` 推进到 5M formal；
- 按 Goal156 预注册执行 `full-residual 训练 + 部署时 mid gate`，检验“训练时 full
  authority、评估时 gate”是否能保留 success 并收回 path；
- 如果 Goal156 仍失败，再按 terminal capture / 动作参数化 / reward-critic credit
  归因，不把失败解释成“需要换 SAC”。

## 9. 补充：终端捕获归因（2026-11-12）

用 `analyze_pc_goal153_eval_grid.py` 对 Goal155 `eval_cpu` 做 pooled active-step
复核后，失败结构比 success 数字更明确：

- 所有 arm 的失败几乎全是 `PLANE_MISS`，`TIME_LIMIT=0`、`SAFETY=0`；问题不是
  timeout 或安全，而是穿过 goal plane 时纵向/横向包络不满足。
- default 下 `near10_2` 的失败终点 `final d` 仍约 `2.55–2.60 m`，失败纵向误差
  `1.83–1.98 m`；进入 2 m 球时纵向 p90 已有 `1.76–1.87 m`。
- strict125 下失败纵向误差 `1.59–1.69 m`，入口 2 m 纵向 p90 仍为
  `1.64–1.87 m`；above/below 约各占一半，不是单侧偏置。
- `near10_2` 把 final-distance p90 从 `full` 的约 `3.0–3.1 m` 收窄到
  `2.57–2.80 m`，但没有降低纵向误差；`mid_only` 把 `<=2 m` residual 压到约
  `0.007–0.011`，success 反而下降。
- 因此“关远段 residual”改善的是尾部/路径，不是最终的纵向捕获。下一步若
  Goal156 仍失败，优先做 Goal140 的 `F_z/F_zdot/F_predz` 纵向 reward pilot，
  或 terminal vertical capture 的动作参数化；不要先换 SAC，也不要把失败归因于
  单纯样本效率。

进一步检查 2–10 m 的 `learned_residual_action` 与纵向误差/heave/pitch-rate 的
within-episode 相关性：

- residual 没有塌缩：`near10_2` 的 2–10 m 各通道 `mean_abs` 约 `0.34–0.45`，
  `full` 约 `0.40–0.96`；
- 但方向性跨 seed 不稳定：`near10_2` 的通道 1 与纵向误差相关约
  `-0.08 / -0.12 / -0.30`，通道 0 约 `+0.27 / +0.24 / -0.02`；`full` 的通道 1
  在一个 seed 为 `+0.245`、另一个为 `-0.249`；
- `mid_only` 在 `<=2 m` 的 residual 接近零（`mean_abs ≈ 0.002–0.003`），
  success 反而下降，说明最后一段需要权限；但现有 near-goal residual 并不是
  一致的纵向纠偏信号。

因此当前证据**不支持**“方向正确、只是幅度不够，所以放大 residual/重跑 R1/R2”
这一解释。更符合数据的是：近端 residual 必要，但 reward/credit 没有把它对齐到
纵向捕获；下一步应先做 terminal vertical credit 或动作参数化的最便宜证伪，
再决定是否启用 `F_z/F_predz` reward。

注意：以上证据来自 Goal155 的 1M checkpoints；Goal156 的 5M full-training
checkpoint 需要用同一套 terminal-near 分析复核后，才能写成正式方法结论。
