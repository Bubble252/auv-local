## 1. 结论

Goal60 只读审计完成，不训练、不换算法、不打开 held-out。结果不是“再来一次
residual 调参”，而是把失败原因拆开：

- **H-C 强支持**：protocol success 与 true-state terminal capture 在两个场景都
  系统性不一致。default 的 discordance 为 `38.1%`（CI `30.6–45.6%`），strict125
  为 `26.9%`（CI `20.6–34.4%`）。success 使用 `p_nav` 判定，true capture 使用
  `eta` 判定；success 但未 capture 的 episode，terminal true distance 明显更大。
- **H-B 弱/部分支持**：按预注册 OR 规则触发了“path/command 为正但 capture 为负”
  的比例（default `33.3%`、strict125 `25.7%`），但 path/command 奖励与 terminal
  distance 的 Spearman 相关 CI 都跨零；分解后 command reward 在失败 episode 中
  100% 为负，total reward 也 100% 为负。更准确的解释是 **path 正项被 command
  负项淹没**，不是简单的 reward hacking。
- **H-A 被否**：8/8 的 saturation 仍是全局现象（pooled mean `0.833`，其中
  240/752/880 接近 1，1008 约 0.333），但 failed-success 的 saturation 中位数差
  只有 `1e-5` 量级；saturation 与 terminal distance 的 pooled rho 为
  `0.062/default`、`0.031/strict125`，CI 跨零。752 有中等正相关
  （`0.427/0.491`），但未达到预注册的失败/成功差异阈值。**动作饱和是策略的
  全局属性，不是 episode 级失败判别器。**
- **H-D/H-E 不支持**：residual-to-base ratio 仍为 `0.063/0.065`，训练曲线最后
  10% 的 residual ratio 变化均值约 `-0.0002`，已经平台化。没有证据支持 SAC 或
  REDQ/DroQ 分支。

因此下一步不是继续换 squash/scale，也不是换 SAC/REDQ/DroQ；应先把
**success/termination 的 p_nav 口径与 true eta capture 对齐**，再处理 reward
composition。

## 3. H-A：动作饱和不是 episode 级失败判别器

Pooled policy（160 episodes/scenario）：

| scenario | sat mean | residual L2 | rho(sat, terminal distance) | 95% CI | failed-success median diff |
|---|---:|---:|---:|---|---:|
| default | 0.833 | 0.090 | 0.062 | `[-0.096, 0.217]` | `2.8e-5` |
| strict125 | 0.833 | 0.094 | 0.031 | `[-0.132, 0.185]` | `1.1e-5` |

逐 checkpoint：

- 240/752/880 的 saturation 约 `0.9996–1.000`；1008 约 `0.333`。
- 752 的 rho 为 `0.427/default`、`0.491/strict125`，但 failed-success 的饱和
  中位数差仍只有 `5.3e-5/4.1e-5`，远低于预注册的 `0.05`。
- 880 和 1008 的 saturation 在 episode 间几乎常数，Spearman 退化为 `None`。

结论：H-A **不被支持**。饱和是全局策略属性，不能解释同一 checkpoint 内哪些
episode 成功、哪些失败；把 softsign/scale 再换一次不是有证据的下一步。

## 4. H-B：path 正项被 command 负项淹没（弱/部分支持）

失败 episode 的 terminal-window 奖励分解：

| scenario | failed | conflict fraction | path mean | command mean | total mean | path>0 | command>0 | total>0 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| default | 48 | 0.333 | `+54.77` | `-71.69` | `-187.07` | 0.604 | 0.000 | 0.000 |
| strict125 | 101 | 0.257 | `+18.53` | `-69.38` | `-182.67` | 0.554 | 0.000 | 0.000 |

`conflict fraction` 是“path+command 和为正、capture 为负”的失败 episode 比例，
按预注册 OR 规则达到 `>=0.20`，所以形式上触发 H-B。但：

- `rho(path reward, terminal distance)` 为 `0.083/default`、`0.011/strict125`，
  CI 都跨零；
- command reward 在失败 episode 中 100% 为负，total reward 也 100% 为负；
- 因此不能写成“path reward 在奖励错误行为”；更准确的机制是
  **path 正项不足以抵消 command tracking 惩罚**，agent 仍在优化命令跟随而不是
  true terminal capture。

结论：H-B 记为 **WEAK / PARTIAL**，不是强支持。它提示 reward composition 需要
在 terminal 阶段重新加权，但不能单独解释 success/capture discordance。

## 5. H-C：terminal capture 口径强支持

| scenario | success/capture discordance | 95% CI | success_no_capture | no_success_capture |
|---|---:|---|---:|---:|
| default | 0.381 | `[0.306, 0.456]` | 58 | 3 |
| strict125 | 0.269 | `[0.206, 0.344]` | 36 | 7 |

2×2 与 terminal true distance：

| scenario | group | count | true distance mean (m) | signed offset mean (m) |
|---|---|---:|---:|---:|
| default | success_capture | 54 | 1.785 | -1.036 |
| default | success_no_capture | 58 | 2.261 | -1.308 |
| default | no_success_capture | 3 | 1.833 | +0.107 |
| default | no_success_no_capture | 45 | 3.031 | +0.111 |
| strict125 | success_capture | 23 | 1.013 | -0.631 |
| strict125 | success_no_capture | 36 | 1.540 | -0.706 |
| strict125 | no_success_capture | 7 | 1.114 | +0.126 |
| strict125 | no_success_no_capture | 94 | 2.426 | +0.088 |

逐 checkpoint 的 discordance 也全部触发（default `0.30–0.475`，strict125
`0.225–0.30`）。这与 Goal40–43 的结论一致：`success` 使用 `p_nav` 距离，
true capture 使用 `eta` 距离；`p_nav` 在终点附近系统性地更靠近 goal，因此
“协议成功”不等于“真实捕获”。

结论：H-C **强支持**。它是当前最可靠的失败机制，也是下一步优先级最高的修复点。

## 6. H-D / H-E：不支持换 SAC/REDQ/DroQ

| 检查 | 结果 |
|---|---|
| residual saturation | pooled mean `0.833`，不是“残差很小” |
| residual-to-base ratio | `0.063/default`、`0.065/strict125` |
| training curve last-10% residual ratio 变化 | 240 `-0.00149`、752 `+0.00502`、880 `-0.00037`、1008 `-0.00405`；均值 `-0.00022` |
| H-D（优化/探索） | 不成立 |
| H-E（样本效率） | 不成立；曲线已平台化，不是更新不足 |

因此不启动 SAC，也不启动 REDQ/DroQ。换算法不能修复 `p_nav` success 与 `eta`
capture 的口径不一致。

## 7. 决策与下一步

决策：`pivot`。停止“动作参数化/softsign 继续调参”作为主线；保留 H-A 为全局
风险，但不再把它当作 episode 级失败解释。

下一 Goal 的优先级：

1. **terminal capture 口径**：预注册只读/1-seed 诊断，比较 `p_nav` success、
   `eta` capture、`terminal_kind` 和 terminal offsets；确认 p_nav 偏差是否能在
   不打开 held-out 的前提下被校准或改写终止规则；
2. **reward composition**：只在 terminal 窗口重加权 path/command 项，先做
   frozen-checkpoint 的只读反事实或 1-seed falsification，不直接长训练；
3. 不启动 SAC/REDQ/DroQ；不重开 Goal27；不打开 held-out。

## 8. 限制

- 这是 4 个 Goal59 checkpoint 的 dev 诊断，不是新的性能 Gate；
- H-B 的 OR 规则触发但相关 CI 跨零，不能把“conflict fraction”单独当作因果证据；
- saturation 在 240/752/880 上接近常数，episode 级相关本身受限；
- p_nav/eta 的差异与 Goal40–43 的估计器偏差一致，但本 Goal 没有重新做传感器
  校准或真实部署验证；
- 所有结论只覆盖 dev `20–59`，held-out 仍未打开。
