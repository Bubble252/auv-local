# Goal105 结果：rpm 降权方向可复现，但静态 rudder 交互不能同时保住 default 与 strict

**日期**：2026-11-11<br>
**状态**：`RPM_ONLY_SIGNAL / INTERACTION_NOT_SUPPORTED / EVAL_ONLY / NO_TRAINING / NO_SAC`<br>
**上游**：Goal104 `CHANNEL_SIGNAL_WEAK`<br>
**性质**：只读评估；未训练、未改 reward/terminal/success/goal radius，未打开 held-out。

## 1. 结论

10 个 eval run 全部完成，C0 精确复现：

```text
default 33/40, strict125 20/40, timeout 0, safety 0
```

冻结 Gate 判为：

```text
RPM_ONLY_SIGNAL
```

没有一个 profile 同时达到 `default>=33 + strict>=23`。结果如下：

| profile | rudder | rpm | default | strict125 | path ratio default/strict |
|---|---:|---:|---:|---:|---:|
| `C0` | 1.00 | 1.00 | 33 | 20 | 1.0000 / 1.0000 |
| `U075` | 1.00 | 0.75 | 32 | 22 | 0.9841 / 0.9839 |
| `U050` | 1.00 | 0.50 | 32 | 23 | 0.9737 / 0.9733 |
| `U050R075` | 0.75 | 0.50 | 33 | 22 | 0.9675 / 0.9668 |
| `U050R125` | 1.25 | 0.50 | 32 | 23 | 0.9785 / 0.9784 |

所有 run `timeout=0`、`safety=0`。

## 2. rpm 方向复现

Goal104 的 `U050` 结果被逐 seed 复现：

```text
default: 32/40  (+1/-2: gained 39, lost 26/33)
strict125: 23/40 (+4/-1: gained 25/51/56/59, lost 24)
McNemar exact p = 0.375
```

Goal104 的 U050 gained 集合 `25/51/56/59` 在 Goal105 中四个全部重现。因此
H105-C “只是 seed 边界噪声”不成立；rpm 降权确实是一个稳定方向。

## 3. rudder 交互假设

H105-A 预测 `U050+R075` 能同时保住 default 33 并把 strict 推到 23。实际：

```text
U050R075: default 33, strict 22
```

default 确实恢复到 33，但 strict 比 U050 少 1 个 success，因此交互没有产生
“两边都赚”的效果。

`U050R125`：

```text
default 32, strict 23
```

strict 与 U050 相同，default 没有恢复。因此增加 rudder 也不能补偿 default。

结论：

```text
H105-A = FALSIFIED
H105-B = SUPPORTED
rudder_static_interaction = no_free_lunch
```

## 4. 路径与终端指标

rpm 降权不仅没有恶化路径，反而降低了 path RMSE：

| profile | default pre-goal median | strict pre-goal median | strict final-distance median |
|---|---:|---:|---:|
| `C0` | 2.177 | 2.168 | 1.257 |
| `U075` | 2.127 | 2.111 | 1.247 |
| `U050` | 2.093 | 2.086 | 1.247 |
| `U050R075` | 2.018 | 2.003 | 1.247 |

这说明 rpm 降权不是简单地把轨迹推远；它同时降低了 pre-goal 误差和终端距离中位数。
但成功仍是 1.25 m 硬壳边界事件，`U050` 的收益需要继续做近终端距离门控确认。

## 5. H105 判定

| hypothesis | 结果 | 证据 |
|---|---|---|
| H105-A 互补交互 | `FALSIFIED` | U050R075 default 33 但 strict 22；U050R125 strict 23 但 default 32 |
| H105-B rpm 单独有效 | `SUPPORTED` | U050 strict 23，gained 25/51/56/59 全部重现 |
| H105-C 只是 seed 噪声 | `FALSIFIED` | U050 gained 集合逐 seed 稳定重现 |
| H105-D 只在边界抖动 | `PARTIAL` | strict final median 1.247、仍贴边，但 pre-goal median 同时改善 |

## 6. 判读

当前最有价值的事实不是“rudder 交互”，而是：

```text
global rpm 0.50
  -> strict +3 net, default -1
  -> path 改善约 2.6%
  -> pre-goal median 改善约 4%
```

这说明 rpm 方向有真实闭环作用，但全局降权会让 default 的 U050 lost seeds `26/33`
掉出成功。下一步不应继续扫静态 rudder，而应测试：

```text
只在接近目标时降低 rpm，远处保持原始 rpm
```

这样保留 U050 在终端闭合上的收益，同时避免远处路径/default 捕获被全局降权改变。

`decision = pivot`
