# Goal96 结果：terminal residual 方向不成立，PPO 放大先验但没有换来闭环

**日期**：2026-11-11<br>
**状态**：`DIRECTION_NOT_SUPPORTED / AUTHORITY_SUFFICIENT / REWARD_CREDIT_MISALIGNED_FORMAL / PPO_DEGRADES_PRIOR / NO_SAC`<br>
**上游**：Goal95 `SCREEN_FAILED`、Goal89 network parity、Goal87 历史结构对照<br>
**性质**：只读 trace 与 reward breakdown；未训练、未改 reward/terminal/success/goal radius，未打开 held-out。

## 1. 结论

Goal96 的四个候选机制里，证据最强的是第 4 个：**PPO 更新在放大已有监督
残差，但没有学出新的 terminal 方向，也没有改善闭环。**

```text
terminal_direction_positive = false
terminal_authority_sufficient = true
reward_credit_aligned_formal = false
ppo_preserves_prior = false
sac_justified = false
```

因此不能把失败归因于“探索/样本效率不足”，也不能现在开 SAC/REDQ/DroQ。
下一步应先修 PPO 的先验保持和终端 residual 选择，而不是换算法。

## 2. 预注册 Gate 结果

### 2.1 Phase A：方向与权限

12 个 run 的 terminal-window 审计全部得到：

```text
direction_positive = false
authority_sufficient = true
terminal_survival_min = 0.9192–0.9662
```

`action_effect_score` 在 `3–2 m` 和 `2–1.25 m` 窗口的 success−failure
bootstrap 95% CI 全部跨 0，没有一个窗口满足预注册的“下界 > 0”。例如
`P_D3_strict125_final` 在 `3–2 m` 为 `1.8835 − 1.5960`，CI
`[-0.3771, 0.9591]`；`P_D3_default_final` 在 `3–2 m` 的 CI 下界也只有
`-0.0480`。因此不能写“残差方向正确，只是不够大”。

权限不是主瓶颈：terminal window 的 effective/applied survival 最低仍为
`0.9192`，高于预注册的 `0.90`。失败不是“策略想动但被包线全部裁掉”。

`300` 落在一条总 reward 略低于 `300` 的 terminal 行，造成“名义占比接近 1”；
按 PPO 的 `gamma=0.995` 折扣后，terminal 项只占总 return 的
`1.2%–1.4%`，不是唯一主导项。

折扣后、去掉 terminal 项的 reward-to-go 在 `3 m` 处仍然有 separation：

所以更准确的判读是：**pre-terminal closure 有信号，但 terminal credit 的
名义尺度失衡；它不是“末端奖励完全没有信息”，更不是当前唯一失败原因。**

## 3. Phase C：逐 seed 配对

新增 `scripts/analyze_pc_goal96_paired_terminal.py`，按同 seed 对齐
initial/final/frozen。success 取自已有 evaluation summary，terminal 行只用于
截取预注册窗口。

### 3.1 success 翻转

| group | initial | final | frozen | initial→final | initial→frozen |
|---|---:|---:|---:|---|---|
| D3 default | 31 | 30 | 31 | lost `26` | 无变化 |
| D3 strict | 19 | 19 | 20 | 无变化 | gained `33` |
| BC15 default | 31 | 30 | 31 | lost `26` | 无变化 |
| BC15 strict | 19 | 19 | 20 | 无变化 | gained `33` |

PPO final 没有在任何 scenario 新增成功；default 只丢了 seed `26`，strict 持平。
frozen BC 反而保住了 default 的 `26`，并救回 strict 的 `33`。这是
`PPO_DEGRADES_PRIOR` 的直接配对证据，虽然幅度只有一个边界 seed，但方向与
“final residual 更大却更差”一致。

### 3.2 终端窗口 initial→final 分叉

| group/window | n | mean cos(initial,final) | mean L2 ratio | mean closure delta |
|---|---:|---:|---:|---:|
| D3 default 3–2 | 36 | 0.9069 | 1.4465 | -0.0201 |
| D3 strict 2–1.25 | 30 | 0.9219 | 1.5193 | -0.0353 |
| BC15 default 3–2 | 36 | 0.9157 | 1.0979 | -0.0061 |
| BC15 strict 2–1.25 | 30 | 0.9688 | 1.1282 | -0.0030 |

关键在 lost seed：

| group | seed | window | cos(initial,final) | L2 ratio | closure initial→final |
|---|---:|---|---:|---:|---:|
| D3 default | 26 | 3–2 | 0.9465 | 2.2862 | 1.2066→0.8846 |
| BC15 default | 26 | 3–2 | 0.9986 | 1.3175 | 1.0823→0.8556 |

这说明 PPO 的 terminal residual **不是随机噪声，也不是新学出的有效方向**：
它与 initial 残差方向高度一致（`cos≈0.91–0.97`），主要变化是幅度放大
`1.10–1.45×`；在唯一丢失的 seed 上幅度放大 `1.32–2.29×`，径向 closure
反而下降 `0.23–0.32 m/s`。

这与 Phase A 的“action_effect_score 不显著”一致：PPO 在终端窗口没有提供
新的方向信息，只是把已有的监督残差放大；放大没有转化为更快的闭合。

## 4. 网络结构对照：不是接线错误，也不是 NoisyNet

按用户要求，把当前网络与历史代码逐项对照。Goal95/Goal89 已有权重级证据：

| 项目 | Goal86 P-A BC | Goal87/89 parity | 当前 Goal95/96 |
|---|---|---|---|
| `d_z_total` | 64 | 64 | 64 |
| `n_z_reserved` | 4 | 4 | 4 |
| state encoder | `[128,128]` | `[128,128]` | `[128,128]` |
| actor/critic | `[256,128]` ELU | `[256,128]` ELU | `[256,128]` ELU |
| path | 12（path8+endpoint4） | 12 | 12 |
| command | 3 | 3 | 3 |
| current encoder | 存在 | 存在 | 存在 |
| DADE | off | off | off |
| frozen BC | 基准 | 22 entries `max abs diff=0.0` | 22 entries `max abs diff=0.0` |

当前低层 PPO 的探索分布是 `Normal(mean, std=0.1)`，评价走
`act_inference()` 的确定性 mean。`use_noisy`/NoisyNet 只存在于
`src/auv_rl/ddpg/` 的 Goal58/59 DDPG 谱系；当前
`src/auv_lowlevel/batch/pc_policy.py` 没有 NoisyLinear，也没有在评价时采样
噪声权重。因此：

```text
network_wiring_bug = false
network_capacity_primary = false
noisenet_dominant = false
```

之前遇到的 NoisyNet 问题不能直接套到当前 PPO；但“PPO 训练噪声约为确定性
残差的数倍”这个观察仍然存在，Goal91 的低噪声 screen 已证伪“低噪声是主瓶颈”。
本次 Phase C 进一步说明问题不是噪声太大，而是确定性部分本身在放大无效残差。

## 5. 裁决

| 维度 | 结果 | 依据 |
|---|---|---|
| 方向 | `DIRECTION_NOT_SUPPORTED` | terminal window CI 全部跨 0 |
| 权限 | `AUTHORITY_SUFFICIENT` | survival 最低 0.9192 |
| Reward | `REWARD_CREDIT_MISALIGNED_FORMAL` | 名义 terminal share > 0.80；折扣后实际占比 1.2%–1.4% |
| 先验 | `PPO_DEGRADES_PRIOR` | default 31→30、strict 19→19；frozen 31/20 |
| 算法 | `NO_SAC` | 没有“方向正确但样本效率不足”的证据 |

```text
decision = pivot
target   = PPO prior-preserving terminal residual update
SAC      = not yet
```

决策矩阵要求：方向 `not_supported` 时先查 terminal residual 方向/观测；先验
`degraded` 时先查 PPO 更新/先验保持。两者都指向同一个下一步：**固定
SAC/PPO 算法族不变，先做一个预注册的 PPO 先验保持实验**，例如对 terminal
window 的 residual 幅度或对 initial prior 的偏离加约束，并在 dev40 上同时
检查 success、closure、residual L2 ratio 和 seed 翻转。
