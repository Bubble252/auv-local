# Goal65 结果：50 步 plane-miss dwell 不足以修复 terminal capture

**日期**：2026-11-10<br>
**状态**：`DWELL_NOT_SUFFICIENT`<br>
**预注册**：`doc/goals/goal65_plane_miss_dwell_20261110.md`<br>
**上游**：Goal27 `H3_SR_FAIL_STOP`、Goal64 `GEOMETRY_SUPPORTED`

## 1. 协议与完整性

Goal65 只测一个因素：plane-miss 条件连续满足 50 步后再终止。没有训练，也没有
改变 reward、observation、controller、checkpoint、GOAL 半径或 plane guard。

- baseline：Goal60 的 10 个 dev trace，seeds `20–59`；
- immediate reference：Goal63 的 10 个 immediate suppression run；
- candidate：4 个 Goal59 checkpoint × `default/strict125` × policy，加 2 个
  forced zero-residual；
- candidate GOAL：`r0 - 0.25 m`，即 `1.75/1.00 m`；
- plane-miss guard：原 `r0`，即 `2.00/1.25 m`；
- action / 精度 / 终止：policy 或 zero-residual，CPU / float64 / `endpoint_stop`；
- held-out `100–149` 关闭；没有扫其他 dwell 值。

实现采用连续计数：`count > dwell_steps` 才终止。因此 `dwell=0` 是 immediate
suppression，`dwell=50` 在第 51 个连续满足步终止。计数器在 episode/reset_mask、
离开 plane-miss 条件或 GOAL 触发时清零。

等价性检查先跑 `default/policy/s240/dwell=0` 的完整 40 seeds，再与 Goal63 的
同 run 逐 seed 比较。`success`、`terminal_kind`、`steps`、`goal_plane_miss`、
`timeout`、`safety`、terminal `p_nav/eta` 和 signed offset 全部为 `0 mismatch`。

## 2. 主结果

### 2.1 Gate 判定

| check | default | strict125 | 判定 |
|---|---:|---:|---|
| policy true retention | `0.907` | `0.739` | default 过，strict 未过 |
| false-success removal | `0.621` | `0.611` | 都过 |
| candidate precision | `0.777` | `0.696` | 都未过 |
| false success vs Goal63 | `23 vs 22` | `14 vs 14` | 都在 `+2` 内 |
| timeout delta | `0.000` | `0.000` | 通过 |
| safety delta | `0.000` | `0.000` | 通过 |
| checkpoint retention | `4/4` | `0/4` | default 过，strict 未过 |
| zero-residual retention | `0.750` | `0.857` | default 未过 |

结论：

- H65-A 只在 default 支持，strict125 `0.739 < 0.85`，因此 H65-A 总体不支持；
- H65-B 两个 scenario 都不支持：default 卡在 precision，strict125 同时卡在
  precision 和 `0/4` checkpoint；
- H65-C 只在 strict125 支持，default zero-residual retention 只有 `0.750`；
- 总状态为 `DWELL_NOT_SUFFICIENT`。

期间离开了 plane-miss 条件，而不是简单“等得还不够久”。

## 3. 只读机制诊断

对 baseline true-success 中被 candidate 丢失的 episode，检查 candidate 的最后
51 个 step（约等于完整 dwell 窗口）：

| scenario | lost true | entered tight radius | minimum `p_nav` median | window-end `p_nav` median |
|---|---:|---:|---:|---:|
| default | 5 | `0/5` | `1.974 m` | `2.922 m` |
| strict125 | 6 | `0/6` | `1.370 m` | `2.458 m` |

strict125 的 candidate GOAL 半径是 `1.00 m`；丢失组的窗口内最小 `p_nav` 中位数
为 `1.370 m`，最大值也只有 `1.799 m`。default 的半径是 `1.75 m`；丢失组窗口内
最小 `p_nav` 中位数为 `1.974 m`。两组都没有任何一个 episode 在 dwell 窗口内进入
收紧半径，窗口末端的距离反而更大。

因此，这次失败不是“50 步太短”或“plane-miss 提前一帧截断”，而是继续闭环后终端
接近仍未收敛到更紧的捕获球。50 步 dwell 只是把同一个失败终点推迟。

## 4. 对 residual / NoisyNet 问题的回答

Goal65 没有提供任何“NoisyNet 主导”的证据，反而继续削弱该解释：

- dwell 只是延迟终止，没有改变 action、policy 或噪声；
- strict125 完整等待 50 步仍没有进入 `1.00 m`；
- forced zero-residual 在 strict125 的 retention 为 `0.857`，但仍未把 default
  拉过 Gate；它与 policy 共享 terminal 接近失败；
- Goal64 已显示 lost/retained 的 residual L2 中位数几乎相同
  （`0.351/0.352`），scale/rate clip 为 0，forced zero 也复现 plane miss。

目前更可信的解释仍是 terminal 接近几何、`p_nav/eta` 估计与控制收敛问题，而不是
“残差不够大”或“噪声把动作主导了”。这也意味着不应通过加大 residual、关闭
NoisyNet、换 SAC/REDQ/DroQ 来救这个 Gate。

## 5. 决策与下一步

`decision = pivot`：停止 plane-miss 短 dwell 轴，不扫更多 dwell 值，不改正式
termination 规则。下一步应新开一个预注册 Goal66，优先做只读的 terminal
estimator/calibration + action/parameterization 审计，回答：

1. 丢失 episode 在 crossing 后，`p_nav` 与 true `eta` 的距离偏差方向和幅度；
2. heading/speed/pitch command 是否在 terminal 阶段继续把载体推离捕获球；
3. 若只修 `p_nav`/`eta` 的 terminal 偏置，理论上能否让这些 seed 进入收紧半径；
4. action parametrization、terminal command 限幅与 reward/terminal capture 是否
   存在明确错配。

在得到明确 optimization/exploration 证据前，不启动 SAC；在得到明确 sample
efficiency 证据前，不考虑 REDQ/DroQ。Goal66 仍需预注册并保持 held-out 关闭。

## 6. 算力使用

- 10 个 candidate 全部并行，`MAX_PARALLEL=10`；
- 每个 run 内部 `num_envs=40`，一次覆盖完整 dev seeds；
- 每进程 `OMP_NUM_THREADS=1`、`MKL_NUM_THREADS=1`；
- 10 个 run 墙钟约 `21 s`；单 run dwell=0 复现约 `16 s`；
- 没有为加速改变 dtype/device、seed、评估协议或终止语义。

后续训练若开启，按 seed 分 GPU 并行；更大 `num_envs`/batch 必须在新预注册中固定
总 transitions、UTD、replay 比例和 checkpoint 选择规则。
