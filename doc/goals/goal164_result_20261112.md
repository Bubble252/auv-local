  `water_velocity_body_mps` 和 `velocity_contract_code`；

但 Gate164-B 未通过：

## 2. 为什么不是先做 anti-windup

审计发现 `pc_controller_gain_residual`、`pc_command_residual` 和
`pc_actuator_residual` 的 actor feedback 分支都存在同一参数化错误：

```text
actor_state = [p_nav(3), attitude(3), angular_rate(3), linear_velocity(3)]
controller_nu = actor_state[:, 6:12]   # 错：把 angular_rate 当线速度
```

因此控制器看到的速度反馈不是 DVL 线速度，速度误差和积分会持续偏置。这个
错误比“终端 anti-windup”更靠前，必须先修。否则再加 anti-windup 只是在错误
反馈上叠补丁，无法判断残差和控制器谁的问题。

## 3. 裁决

| hypothesis | 裁决 |
|---|---|
| H164-A：统一契约后旧评价的大范围超限消失，只剩 terminal 残留 | `SUPPORTED` |
| H164-B：terminal 残留超速由 speed integral/RPM 回收滞后造成 | `PARTIAL`：integral 经常在 cap，但反馈参数化错误是上游原因 |
| H164-C：修正速度语义后 gain residual 相对效果会改变 | `BLOCKED`：Gate164-B 未过，禁止训练 |

**决策**：`pivot` 到 Goal165。先修 actor feedback 的 `nu` 排列和水相对速度
反馈，再重跑 corrected zero-only replay；不换 RL 算法，不放宽 2.5 m/s，
不扩 seed，不打开 held-out，不修改 reward/terminal/success/radius。
