# IsaacLab 隔离安装与并行能力验证：项目背景

记录日期：2026-10-28

## 1. 为什么做这件事

P1 当前是单环境、OceanSim 几何简化声呐、DDPG direct-action 的训练链。单环境 20k 步已经需要较长时间，继续做 critic、奖励、课程和行为克隆对照时，训练吞吐会成为实验迭代的主要限制。

本任务只回答一个工程问题：**在不动现有 OceanSim/Isaac Sim 5.0 环境、不动 P1/P2 实验口径的前提下，能否用隔离的 IsaacLab 环境稳定跑到 1024 个并行环境，并得到可信的吞吐和显存数据。**

IsaacLab 官方的 `Isaac-Cartpole-v0` 只作为并行基础设施探针。它不代表 OceanSim 声呐，也不能用它的吞吐推断 P1-A 的吞吐。

## 2. 任务边界

必须保持：

- 现有 `oceansim` Conda 环境不改、不升级、不卸载包。
- Isaac Sim 继续使用 `5.0.0.0`；不追 5.1 或 6.x。
- 不升级 NVIDIA 驱动、系统 CUDA 或系统级组件。
- 不改 P1/P2 的 17 维观测、动作范围、奖励、阈值、证书和评估协议。
- 不启动 P1 正式训练，不启动多环境 RL 训练。
- 不覆盖 R0–R4 的输出和 checkpoint。
- 不 push；不提交环境、缓存、模型和大日志。
- 服务器密码只通过当前 shell 的 `SSHPASS` 传递，不写入仓库、日志、manifest 或命令历史文件。

## 4. 成功标准

工程门，不是论文阈值：

- 1 个环境完成 100–200 步，reset/step 正常，无 NaN/Inf。
- 1、64、256、1024 个环境都能完成至少 200 步。
- 1024 环境无 OOM、无 NaN、无静默降级。
- 每个配置至少重复 3 次，记录真实 `steps/s`、P50/P95、显存峰值和 CPU 使用率。
- 如果 2048/4096 显存允许则测试；失败也要保留配置和日志。
- 不根据 Cartpole 数据声称 OceanSim 声呐可以线性扩展。

## 5. 已知风险

- Isaac Sim 5.0 必须搭配官方矩阵中的 IsaacLab `v2.2.1`；`v2.3.2` 的 Pillow 锁定与 Isaac Sim 5.0 冲突。安装脚本必须显式固定 5.0、使用约束文件并检查安装后的包版本。
- 1024 环境可能不是显存瓶颈，而是 Python 回调、reset 或场景创建瓶颈；必须看 P95 和启动时间，不只看能否启动。
- 服务器是共享 8 卡机器，训练任务可能随时占用 GPU；测试前必须重新检查 `nvidia-smi`，优先使用空闲卡，不能 kill 他人进程。
- Cartpole 的吞吐不能外推到带相机、点云和 1300 条射线的 OceanSim 感知。
