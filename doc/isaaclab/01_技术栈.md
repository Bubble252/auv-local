## 2. 版本组合

| 组件 | 选择 | 依据 |
| --- | --- | --- |
| Isaac Sim | `5.0.0.0` | 任务要求沿用现有版本；OceanSim 1.0 已在该版本通过 smoke test |
| IsaacLab | `v2.2.1` | 官方兼容矩阵：`v2.2.X` 支持 Isaac Sim 4.5 / 5.0；依赖锁定与 Isaac Sim 5.0 一致 |
| Python | 3.11 | Isaac Sim 5.0 Linux wheel 为 `cp311`；IsaacLab v2.2.1 支持 3.10/3.11 |
| PyTorch | `2.7.0` / `cu128` | Isaac Sim 5.0 / IsaacLab v2.2.1 的官方组合 |
| TorchVision / TorchAudio | `0.22.0` / `2.7.0` | 与 PyTorch 2.7.0 和 Isaac Sim Core 的版本要求一致 |
| 隔离方式 | 独立 venv | 从 `oceansim/bin/python` 创建，但不使用 system site-packages |
| 任务 | `Isaac-Cartpole-v0` | IsaacLab 官方最小任务，仅作基础设施探针 |

官方兼容矩阵来源：<https://github.com/isaac-sim/IsaacLab> 的 “Isaac Sim Compatibility” 表。

OceanSim 侧的版本边界不同：OceanSim 上游 README 和安装文档只声明适配 Isaac Sim 5.0，changelog 也只记录 5.0 兼容；没有 5.1 发布标签或官方兼容声明。因此本任务不把 OceanSim 迁移到 5.1。IsaacLab v2.3.x 即使支持 5.1，也不能替代 OceanSim 的兼容性验证。

版本选择说明：最初评估了 `v2.3.2`，但该版本把 Pillow 固定为 `11.3.0`，而 Isaac Sim 5.0 的 `isaacsim-kernel` 固定为 `11.2.1`，会造成 `pip check` 冲突。`v2.2.1` 是官方矩阵中明确支持 Isaac Sim 5.0 的版本，且其 Pillow、Gymnasium 等锁定与 5.0 一致，因此改用 `v2.2.1`。这不是为了追新，而是为了保持官方兼容组合。

依赖约束文件：`scripts/isaaclab_constraints.txt`，安装时通过 `PIP_CONSTRAINT` 传入，至少锁定：

```text
setuptools==75.3.4
flatdict==4.0.1
click==8.1.7
idna==3.10
packaging==23.0
transformers==4.57.6
pytest==8.4.2
torch==2.7.0
torchvision==0.22.0
torchaudio==2.7.0
numpy==1.26.0
gymnasium==1.2.0
pillow==11.2.1
psutil==5.9.8
```

`setuptools` 也必须锁定：IsaacLab 依赖的 `flatdict==4.0.1` 仍使用 `pkg_resources`，而 setuptools 81+ 已不再提供该模块；使用最新的 84.x 会使 `isaaclab` 的 editable 安装失败。

由于 pip 的构建隔离不会继承 `PIP_CONSTRAINT` 到 `flatdict` 的构建环境，安装脚本还会显式执行 `pip install --no-build-isolation flatdict==4.0.1`，再用同一 venv 安装 IsaacLab。

Isaac Sim 5.0 的包元数据还固定了 `click==8.1.7`、`idna==3.10` 和 `packaging==23.0`；这些也必须写入约束文件，否则最新的 IsaacLab 依赖会把它们升级并导致 `pip check` 失败。

`transformers` 固定为 IsaacLab v2.3.2 已验证使用的 `4.57.6`，避免最新的 5.x 通过 `huggingface-hub 2.x` 拉入 `httpx2` 并要求 `idna>=3.18`。`pytest` 固定为 `8.4.2`，避免 pytest 9.x 要求 `packaging>=24`。安装完成后会条件性移除未被任何包依赖的 `httpx2`。

IsaacLab 安装命令必须使用 `./isaaclab.sh --install none`，不能使用 `sb3`、`all` 或其他 RL extra；本任务不需要 Stable-Baselines3。

安装时必须验证：

- `import isaacsim` 的版本是 `5.0.0.0`，不能是 5.1。
- `import isaaclab` 成功。
- `python -m pip check` 无阻塞性冲突。
- `torch` / `torchvision` / `torchaudio` 分别是 `2.7.0` / `0.22.0` / `2.7.0`。
- 现有 `oceansim` 环境的包列表和版本不变。

## 3. 隔离设计

```text
oceansim 环境（只读复用入口）
    └── /data/.../envs/conda_envs/oceansim/bin/python
            └── 创建独立 venv
                    └── /data/.../envs/venvs/isaaclab
                            ├── isaacsim 5.0.0.0
                            ├── torch 2.7.0
                            └── isaaclab v2.2.1
```

- venv 不继承 `oceansim` 的 site-packages，避免在现有环境中安装 IsaacLab 依赖。
- 不修改 `oceansim` 的 Conda `envs` 目录，不执行 `conda install` 或 `pip uninstall`。
- 不修改 `/usr/local/cuda`、驱动或系统级库。
- 安装前记录 `pip freeze`，安装后再次记录并比较。
- 缓存和临时目录指向 `/data`，避免根分区不足。

## 4. 实测安装结果

`install_manifest.json` 的最终状态为 `PASS`，`pip check` 为 `No broken requirements found.`。

| 组件 | 实测版本 |
| --- | --- |
| Isaac Sim | `5.0.0.0`（`isaacsim-core/kernel/rl` 同为 `5.0.0.0`） |
| IsaacLab | `v2.2.1`，commit `0f00ca2b4b2d54d5f90006a92abb1b00a72b2f20` |
| `isaaclab` / `isaaclab_tasks` | `0.45.9` / `0.10.47` |
| Python | `3.11.13` |
| PyTorch 栈 | `torch 2.7.0+cu128`、`torchvision 0.22.0+cu128`、`torchaudio 2.7.0+cu128` |
| Warp / NumPy / Gymnasium | `warp-lang 1.18.0`、`numpy 1.26.0`、`gymnasium 1.2.0` |
| Pillow / psutil | `11.2.1` / `5.9.8` |
| Stable-Baselines3 | 未安装（符合 `--install none` 要求） |

运行中确认了四个实施细节：

1. `httpx2 2.16.0` 是 transformers 5.x 留下的孤儿包，会要求 `idna>=3.18` 并与 Isaac Sim 5.0 的 `idna 3.10` 冲突；当前通过约束把 transformers 固定在 `4.57.6`，并按依赖关系清理 `httpx2 → httpcore2 → truststore`。
2. 不要在启动 Omniverse 前设置 `CUDA_VISIBLE_DEVICES`。Isaac Sim 会明确警告该变量可能造成设备枚举异常；当前脚本只设置 `ISAACLAB_PHYSICAL_GPU` 供 `nvidia-smi` 采样，并向 AppLauncher 传入 `--device cuda:N`。本次只实测了 `N=0`。
3. `simulation_app.close()` 可能直接结束进程，probe 必须在关闭 App 之前写 JSON；否则会出现“实际已跑完但结果文件缺失”的假失败。
4. 每次启动仍会打印 `Warp CUDA error: cuDeviceGetUuid` 和 `Failed to clone in Fabric`。18 次最终测量均完成 200 步、无 NaN/OOM、环境数正确，因此当前视为非致命启动告警，但仍保留为后续风险。

## 5. 测量定义

| 指标 | 定义 |
| --- | --- |
| `app_ready_s` | 进程启动到 Isaac Sim App 可用 |
| `time_to_first_step_s` | 进程启动到第一次 `env.step()` 完成 |
| `reset_s` | `env.reset(seed=0)` 的墙钟时间 |
| `env_steps_per_s` | `完成步数 × num_envs / 总 step 时间` |
| `control_steps_per_s` | `完成步数 / 总 step 时间` |
| `step_latency_p50/p95` | 单次 `env.step + cuda.synchronize` 的墙钟延迟 |
| GPU 峰值 | 优先用 `nvidia-smi` 采样，辅以 `torch.cuda.max_memory_allocated` |
| CPU 使用率 | 进程 CPU 时间 / 墙钟时间；同时记录系统负载 |
| 失败 | `OOM`、异常退出、NaN/Inf、观测形状不符、环境数不符 |

所有配置先 warmup 20 步，再统计 200 步；每个配置重复 3 次，固定 seed 0。

## 6. 产物格式

- 每个原始 probe 一个 JSON，文件名包含 `num_envs` 和 `repeat`。
- `scaling.csv` 一行一个配置的聚合值，同时保留重复间的最小/最大吞吐。
- `scale_report.json` 记录工程门、失败配置、失败阶段（显存/启动/step/reset/NaN）和结论。
- 任何失败都保留日志和完整命令，不能用“重跑一次成功”覆盖失败记录。
