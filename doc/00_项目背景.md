# 局部规划与反应式导航方向背景

记录日期：2026-10-27

文档性质：方向与边界草案 v0.2。本文档冻结“做什么、为什么做、与已有全局规划器的关系”，不冻结具体算法和创新点。M0 已按用户确认更新平台、首版模式和执行链路；代码实现仍按 `02_执行计划.md` 的里程碑推进。

## 1. 一句话定位

研究三维水下机器人在全局轨迹、名义制导、动态障碍、海流和有限感知条件下的局部规划与反应式安全执行，形成一套可以独立替换局部算法、制导算法、安全滤波和执行平台的模块化实验框架。

本方向首先服务两个目的：

- 为后续局部规划、RL 局部避障、CBF/MPC 安全层和分层导航论文提供统一接口。
- 复现并拆解 Yuan et al. (2025) 的“PSO 全局规划 + DDPG 局部避障 + 3D ALOS 制导”系统，使各个模块可以独立消融和比较。

## 2. 与全局规划方向的关系

全局规划器位于 `../../settled_全局规划器`，当前主线是三维、海流感知、全艇体碰撞和恢复能力约束下的长程路径规划。局部方向不重新实现全局算法，也不修改已经冻结的 M7 基线，而是消费全局规划器输出的：

```text
PlanResult
  ├─ Trajectory
  ├─ RecoveryCertificate
  ├─ status / reason
  └─ diagnostics
```

已有全局规划器接口见：

- `../../settled_全局规划器/src/auv_planner/interfaces.py`
- `../../settled_全局规划器/src/auv_planner/contracts.py`
- `../../settled_全局规划器/src/auv_planner/guidance.py`
- `../../settled_全局规划器/src/auv_planner/evaluation/closed_loop.py`

当前已经成立的事实是：`GlobalPlanner` 和 `Guidance` 是两个独立 Protocol；3D ALOS 只依赖 `State`、`Trajectory` 和 `CurrentField`，不依赖任何具体全局规划器。因此任意全局规划器输出的轨迹都可以交给 ALOS 跟踪。底层执行链也已存在：

```text
Trajectory
  ↓ ThreeDAlosGuidance
Reference
  ↓ Remus100TrackingController
Remus100ActuatorCommand
  ↓ PvsRemus100Backend
SimulationSnapshot
```

尚未成立的事实是：局部项目还没有把 DDPG、rollout 和全局轨迹装配成自己的在线运行器，也没有局部规划器、反应式策略和安全回退的统一接口。首版不需要重写 REMUS 到 PVS 的执行链，只需要把 DDPG 产生的局部航点/轨迹接到既有 ALOS 上游。

## 3. 参考论文及其真实结构

参考论文：

> Jianya Yuan, Hongjian Wang, Bo Zhong, Chengfeng Li, Yutong Huang, Shaozheng Song. Three-Dimensional Autonomous Navigation of Unmanned Underwater Vehicle Based on Deep Reinforcement Learning and Adaptive Line-of-Sight Guidance. Journal of Marine Science and Engineering, 2025, 13, 2360. DOI: 10.3390/jmse13122360.

本地全文：`../../settled_全局规划器/references/papers/Yuan2025_3D_ALOS_JMSE.pdf`。

论文把系统描述为三层：

```text
改进 PSO 全局航路
        ↓
DDPG 局部避障
        ↓
3D ALOS 路径跟踪
        ↓
UUV 控制器与动力学模型
```

需要明确区分论文文字和可执行接口：

- PSO 是全局几何航路规划器。
- DDPG 被论文称为局部避障规划，但 Actor 的直接输出是纵向加速度 `u_dot` 和艏摇角速度 `r`，不是航点或局部轨迹。因此从网络动作看，它本质上是反应式运动策略。
- 3D ALOS 是制导/参考生成层，不是规划器。它根据路径、当前状态和海流计算期望航向、俯仰和速度。
- 论文第 4 章让 ALOS 跟踪局部避障规划产生的航点，说明 ALOS 位于规划结果的下游。
- 论文没有给出 DDPG 与 ALOS 在同一控制周期同时运行时的优先级、覆盖关系或融合公式。

这里必须区分“Actor 的网络输出”和“局部规划器的对外输出”，否则很容易把两层写成互相矛盾：

| 层级 | 论文中的输出 | 说明 |
|---|---|---|
| DDPG Actor 网络 | `[u_dot, r]` | 论文第 3.2 节明确说明为纵向加速度和艏摇角速度 |
| DDPG 动作经运动模型积分 | 下一状态或下一航点 `(x, y, z)` | 动作通过 3DOF 模型积分形成局部位置序列 |
| 局部规划器对外结果 | 避障后的航点/短轨迹 | 论文第 4.1 节的 ALOS 使用这些航点作为输入 |
| 底层 autopilot | 舵角、尾舵和推进器转速 | 由期望航向/俯仰和速度继续生成 |

用简化运动学表示，DDPG 动作单独积分到航点的关系是：

```text
u_{t+1}   = u_t + u_dot * dt
psi_{t+1} = psi_t + r * dt
x_{t+1}   = x_t + u_t * cos(psi_t) * dt
y_{t+1}   = y_t + u_t * sin(psi_t) * dt
z_{t+1}   = z_t        # 仅表示 DDPG 动作本身不产生深度变化
```

因此，把 DDPG 局部层对外描述成“输出下一航点”在系统数据流上是成立的；但更严格的写法是“Actor 输出运动动作，动作经运动模型积分后形成下一航点”。不能把网络直接输出写成航点，也不能因为网络动作是 `[u_dot, r]` 就否认局部层最终会形成航点。在组合系统中，局部航点的 `z` 可以从全局参考航点继承，因此任务过程中深度仍可变化；变化来源是全局航路和 ALOS，而不是 DDPG 的局部决策。

论文的整体是三维导航，但 DDPG 的动作空间只在水平面内改变 `x`、`y` 和艏向，不直接选择新的深度。DDPG 动作本身不产生垂直位移；全局航点可以继续携带深度参考，由 3D ALOS 的期望俯仰去跟踪。因此准确表述是：

> 论文系统是 3D 导航；DDPG 局部避障层是 2.5D，水平避障、深度保持。

因此第一版采用 **online rollout**，而不是先在离线环境生成整条轨迹再一次性跟踪：

```text
当前真实快照
  ↓ 构建局部观测
DDPG 输出 [u_dot, r]
  ↓ 用局部运动模型积分一个短步长，得到一个局部航点
  ↓ 用预测状态更新观测
重复到时域终点，得到局部航点序列/短轨迹
  ↓
3D ALOS 跟踪这条局部轨迹
  ↓
Remus100TrackingController → PVS
```

每个决策周期都从真实快照重新 rollout；仿真环境内部仍以 0.02 s 步长执行。这样“DDPG 先得到局部路径点，再交给 ALOS”与论文的数据流一致，同时不会把 rollout 预测轨迹误当成真实执行结果。完整的离线批量生成流程保留为对照实验，不作为首版主链路。

这里没有新增 `RemusControlAdapter`：`Remus100TrackingController` 已经负责把 ALOS 的 `Reference` 转换为舵角、艉水平舵和 RPM。`PolicyRolloutPlanner` 只负责把 DDPG 的闭环动作展开成局部轨迹，不重复实现底层控制。

## 4. 核心概念定义

| 概念 | 定义 | 不负责什么 |
|---|---|---|
| 全局规划 | 从任务起点到目标的长时间、全局路径或轨迹生成 | 不处理高频新障碍和跟踪扰动 |
| 局部路径规划 | 在局部地图和短时域内生成可执行的局部路径/短轨迹 | 不替代全局任务决策 |
| 反应式策略 | 从当前观测直接输出运动动作，轨迹由闭环执行涌现 | 策略本身不显式返回路径；可经 rollout 适配器形成航点/轨迹 |
| 名义制导 | 把路径/轨迹转换为期望姿态、速度和前馈参考 | 不避障，不搜索路径 |
| 3D ALOS | 基于水平/垂直前视向量和海流补偿的制导律 | 不是规划器，不处理障碍 |
| 运动仲裁 | 在名义参考和局部动作之间选择、覆盖或降级 | 不是论文组件，是本项目的工程适配层 |
| 安全滤波 | 检查或修正动作是否满足安全、执行器和能力约束 | 不负责长期目标规划 |
| 运动执行器 | 把通用运动命令转换为平台舵角、推力或 RPM | 不负责算法决策 |
| Policy Rollout Adapter | 让 RL 策略在内部预测模型中滚动生成短轨迹 | 不是 RL 算法本身，也不是纯格式转换 |

“Policy Rollout Adapter”只能算接口适配器，不作为论文创新点。它必须显式记录预测模型、时域、步长和模型偏差。

## 5. 两种局部模式

### 5.1 分层路径模式

```text
全局轨迹
  ↓
局部路径规划器（DWA、局部 RRT、MPC 等）
  ↓ 局部路径/短轨迹
3D ALOS
  ↓ Reference
安全滤波与运动执行
```

该模式适合“局部层输出路径”的算法。ALOS 明确位于局部路径规划器之后。

### 5.2 online rollout 主模式（首版）

```text
全局轨迹 / 目标
  ↓
局部观测
  ↓
DDPG：[u_dot, r] → 局部运动模型 → 局部航点/轨迹
  ↓
3D ALOS
  ↓
Remus100TrackingController → PVS
```

该模式把 DDPG 放在 ALOS 上游：DDPG 只生成局部路径，ALOS 负责路径跟踪和参考生成。因此第一版不存在 DDPG 与 ALOS 同时争抢同一个艏向/速度指令的问题，不需要 `MotionArbiter`。

### 5.3 并行修正模式（后置）

```text
全局轨迹 → 3D ALOS → 名义 Reference ─┐
                                      ├→ MotionArbiter → 安全滤波 → 执行器
传感器 → ReactivePolicy → 动作或轨迹 ─┘
```

只有后续需要把反应式策略与名义制导并行融合时，才使用本项目提出的 `MotionArbiter`。它不是论文组件，也不进入第一版论文复现实验。

## 6. 研究问题

- RQ1：如何在统一接口下公平比较局部路径规划器、反应式 RL 策略和传统避障算法？
- RQ2：RL 动作经 rollout 转成局部路径后，与直接执行动作相比，性能差异来自策略本身还是来自制导/跟踪层？
- RQ3：在深度剪切流、动态障碍和有限声呐视场下，局部层的失效模式是什么？
- RQ4：局部层如何在获得收益的同时保持可解释的回退和安全约束？
- RQ5：2.5D 局部规划与完整 3D 局部规划之间的性能、复杂度和可验证性如何权衡？

## 8. 范围与不做事项

首版范围：

- 三维障碍与海流下的局部路径/反应式策略接口。
- 统一评价、日志、种子和配置管理。
- 2.5D 闭环基线和 online rollout 的 DDPG 完整基线。
- 与现有全局规划器和 3D ALOS 的组合实验。
- PVS/HoloOcean 适配层，外部依赖延迟导入。

首版不做：

- 大规模 RL 算法集合和自动超参数搜索。
- 端到端 VLA、语义地图或完整 SLAM。
- 真实海洋试验或 sim-to-real 声明。
- 在未完成基线前训练复杂 DDPG 变体。
- 为了组合方便而复制 `State`、`Trajectory` 等核心数据结构。
- 修改全局规划器的实验阈值、证书语义或冻结场景来迁就局部结果。

## 9. 主要风险

| 风险 | 表现 | 预防措施 |
|---|---|---|
| 动作抽象错位 | 把 `[u_dot, r]` 误称为局部路径规划器 | 明确 `ReactivePolicy` 与 `LocalPathPlanner` 边界 |
| 双重控制 | DDPG 与 ALOS 同时修改艏向/速度 | 首版把 DDPG 放在 ALOS 上游；只有并行修正模式才启用显式 `MotionArbiter` |
| Rollout 模型偏差 | 局部路径在预测模型中可行，在 PVS/HoloOcean 中不可行 | 记录模型版本并在高保真后端复验 |
| 观测不一致 | 训练、rollout、部署使用不同声呐预处理 | 共用 observation builder 并保存 observation spec |
| 有状态策略污染 | GRU 历史在 rollout 中被意外修改 | 支持策略记忆快照/恢复或独立推理分支 |
| 组合框架失控 | 先写大量算法和空接口，迟迟没有闭环 | 先完成一个 2.5D 基线，再增加第二个算法 |
| 指标混淆 | 策略收益与跟踪器收益混在一起 | 同时报告 direct-action 和 rollout-path 两种模式 |

## 10. 阶段产物

- 可安装的 `auv_rl` 与 `auv_local` Python 包。
- 一套不依赖 ROS 2、HoloOcean 或 PyTorch 的局部契约和导入边界测试。
- 2.5D 纯 Python 闭环基线。
- 至少一个局部路径基线和两个反应式基线。
- DDPG online rollout 主基线；direct-action 仅作为后续诊断对照。
- PVS REMUS 100 和 HoloOcean 适配实验。
- 可复现的实验配置、日志、指标、失败案例和 Git 记录。
