## 2. 冻结的架构方向

### 2.1 两类局部算法

```text
LocalPathPlanner
  局部路径/短轨迹 → 3D ALOS → Reference

ReactivePolicy
  当前观测 + 目标/路径窗口 → 运动动作
  经 online rollout 转成局部短轨迹，再交给 ALOS

并行修正（后置）
  ALOS 名义参考 + ReactivePolicy 动作 → MotionArbiter
```

不能用一个 `LocalPlanner.act()` 同时代表 DWA、MPC、DDPG 和 APF。它们输出的抽象不同，强行统一会把接口做成万能字典。

### 2.2 3D ALOS 的位置

- ALOS 是制导层，不是规划器。
- 在局部路径模式下，ALOS 位于局部路径规划器之后。
- 首版训练采用 direct-action；评估采用 online rollout：DDPG 在每个预测步输出 `[u_dot, r]`，经局部运动模型积分得到局部航点；短轨迹交给 ALOS 跟踪。
- 只有后续“并行修正模式”才让 ALOS 提供名义参考并与反应式动作仲裁。

### 2.3 论文方法与本项目工程组件

| 组件 | 来源 | 用途 |
|---|---|---|
| PSO 全局规划 | 论文 | 全局基线 |
| DDPG `[u_dot, r]` | 论文 | 反应式局部策略 |
| 3D ALOS | 论文思想；本地已有实现 | 共享制导层 |
| `PolicyRolloutPlanner` | 本项目 | 把闭环 RL 策略展开成局部轨迹 |
| `MotionArbiter` | 本项目 | 在线组合 ALOS 与反应式动作；首版不启用 |
| `MotionExecutor` | 本项目 | 通用平台动作分配；首版复现直接复用既有 REMUS 控制器 |
| `NavigationRuntime` | 本项目 | 组合、时序、回退和日志 |

工程组件不得作为论文创新点，除非后续单独完成文献审计、强基线和消融。

### 3.1 训练与评估时序

**P1 多环境训练链（当前主线，2026-10-28）**：

```text
二维场景几何 + 权威状态（N 个独立 episode）
  ↓
解析 1300 条 0.1° 射线 → 13 扇区 → 17 维观测
  ↓
单个 DDPG [u_dot, r]（每环境独立 history/GRU hidden）
  ↓ SurgeYaw 动作适配
批量二维水平运动学 10 × 0.02 s（深度固定）
  ↓ 权威 State + 全艇体二维碰撞/越界检查 + 自动 reset
张量化 replay / PPER → 下一批训练样本
```

**P1 OceanSim 单环境评估链（最终评估）**：

```text
OceanSim 简化声呐 + 同步位姿
  ↓
ObservationBuilder
  ↓
DDPG [u_dot, r]
  ↓ SurgeYaw 动作适配
二维水平运动学 10 × 0.02 s（深度固定）
  ↓ 权威 State + 全艇体二维碰撞/越界检查
OceanSim 位姿同步 → 下一帧简化声呐
  ↓
ObservationBuilder → 下一训练样本
```

P1 只训练二维避障策略，不调用 ALOS、REMUS 控制器或 PVS。多环境训练使用解析 13 扇区，最终评估使用 OceanSim P1-A；两条链共用 17 维 builder 和动作语义，但必须在日志中分别标记来源。旧的单环境 OceanSim 训练链保留为历史基线和控制对照。

**P2 评估与微调链**：

```text
真实 SimulationSnapshot
  ↓
LocalObservation（13 扇区 + 目标信息 + u/r，上一动作可选）
  ↓
DDPG 输出 [u_dot, r]
  ↓ 局部运动模型积分
局部航点（深度继承 route_window/全局参考）
  ↓ 重复到 rollout 时域终点

  ↓

  ↓
```

初始工程参数为 horizon 2.0 s、rollout 步长 0.2 s、每 0.5 s 从真实快照重规划；rollout 内每一步重新调用策略，不是重复同一动作。这些数值只属于 P2 评估链，在 M5 通过收敛与闭环稳定性检查后再冻结，不能写成 P1 训练参数或论文成功阈值。

### 3.2 论文参数核对结论

已核对 Yuan et al. (2025) 的正文、公式和 Table 2/Table 6/Table 7。论文明确给出：

| 项目 | 论文值/事实 | 对本项目的含义 |
|---|---|---|
| DDPG 动作 | `[u_dot, r]` | 不直接输出航点，需经运动模型积分 |
| 运动约束 | `2–8 kn`、`|q|≤10°/s`、`|r|≤15°/s`、`|u_dot|≤1 kn/s` | 论文平台与 REMUS 100 不同，不能直接照搬数值 |
| DDPG 平均单步规划时间 | Table 7：37.9 ms | 约 26 Hz 的单步计算上限参考 |
| 前视声呐更新率 | 最大 27 Hz，512 波束 | 与 37.9 ms 单步量级一致 |
| 训练轮次 | 300 rounds | 只说明训练轮数，不说明单轮时长 |
| DDPG 超参数 | Table 2：batch 64、replay 100000、γ=0.98、lr=0.0002 等 | 可用于训练配置起点 |

论文没有明确给出：

- 仿真积分步长 `h` 的具体数值；`h` 只在海流一阶模型公式中出现符号；
- DDPG 动作的实际控制周期或动作保持时间；
- rollout 时域、航点间距和重规划周期；
- 航点是由在线逐步规划生成，还是离线整段生成后再交给 ALOS；
- 在线 rollout 的计算预算或最坏延迟。

因此首版取值不能写成“论文参数”，只能写成“由论文计算成本和 REMUS 动力学推出的工程初值”：

```text
horizon = 2.0 s        # REMUS 1.0–2.5 m/s → 2–5 m 前视
step = 0.2 s           # 10 次策略调用 × 37.9 ms ≈ 379 ms
replan = 0.5 s         # 给 379 ms 预算留约 121 ms 余量
ALOS/controller = 50 Hz
PVS = 0.02 s
```

379 ms 只是按论文单步规划时间做的预算估计，不是实测值。若把步长直接压到声呐的约 0.04 s，则 2 s rollout 需要约 50 次策略调用，按 37.9 ms/次约 1.9 s，无法放进 0.5 s 重规划预算。因此 0.2 s 是为了保留论文量级计算成本而做的在线折中，不代表还原了论文未公开的控制周期。M5 接入 rollout 后必须记录实际 rollout 平均和 P95 耗时；若超过 0.5 s，优先减少无效策略调用、缓存观测和优化几何，不允许悄悄降低安全距离或延长证书有效期来掩盖超时。

**M4.1 奖励：论文四项（论文式 (20)–(22)）**

```text
R1 距离项 = αd · tanh(d_goal / d_start_goal)
      αd < 0，论文未给具体数值；首版取 αd = -1.0，仅作为可配置初值

R2 障碍项 = -2，若前方 ±30° 最近障碍距离 < 0.7 · d_max
            -1，若 0.7 · d_max ≤ 前方 ±30° 最近障碍距离 < d_max
             0，其他

R3 终止项 = -80，碰撞或越界

R4 终止项 = +50，到达目标

Rt = R1 + R2 + R3 + R4
```

实现约束：

- `R2` 的 `d_max` 是 P1 局部有效视野 `20 m`，不是传感器物理量程 `120 m`，也不是世界尺寸。原始 `RangeScan` 保留 120 m，但观测和 R2 都在 20 m 截断；若直接用 120 m，`0.7 × 120 = 84 m` 就会触发近障碍惩罚，远处目标会支配局部避障奖励。奖励配置、观测 builder 和日志中的 `local_effective_range_m` 必须一致。
- `R2` 只看前方 `±30°`，用该范围内的最近扇区距离；不能把后向避障收益算进论文复现项。
- `αd`、`d_max`、碰撞奖励 50/80 的每一次改动都必须写进实验配置和结果表；不能只说“参考论文”。
- 论文奖励 R0–R4 的 progress shaping 默认关闭。若为加快学习启用，只作为单独消融，不混入论文基线主结果；奖励 v2 中的 goal progress 是独立候选的主组分之一，不属于这里的默认开关。
- 成功由环境显式字段判定：到达目标、无碰撞、无越界、未超时；不能从奖励正负反推。

**M4.1 奖励 v2（2026-10-28 确认）**

奖励 v2 是独立于论文 R0–R4 的候选配置，不替换冻结的论文奖励基线。以下四项都必须实现、记录并参与消融，不能只保留其中一部分：

```text
r_goal   = w_goal   * (d_prev - d_now)
r_obs    = w_obs    * (p_prev - p_now),  p = max(0, c_safe - c)
r_speed  = -w_speed * (u - u_ref)^2
r_smooth = -w_smooth * ||a_norm - a_prev_norm||^2

R_v2 = r_goal + r_obs + r_speed + r_smooth + r_terminal
```

- 目标进度使用 `d_prev - d_now`；`d` 为目标欧氏距离。
- 障碍距离势函数只使用全艇体 `hull_clearance_details(...).clearance_m`，进入 `c_safe` 内才产生单侧惩罚，离开后归零；不能用障碍中心距离或单条射线代替。
- 参考速度惩罚使用当前纵向速度与 `u_ref` 的平方差；`u_ref` 从配置读取，第一版默认取场景 `nominal_speed_mps`。
- 动作平滑在归一化动作空间计算：`a_norm = [u_dot / 0.5, r / 0.2618]`。
- `r_terminal` 暂保留现有 `-80` 碰撞/越界和 `+50` 到达目标，不因参考图使用 `-100/+100` 就直接改动。
- 初始权重仅作为工程起点：`w_goal=1.0`、`w_obs=1.0`、`w_speed=0.1`、`w_smooth=0.1`；必须写入配置并通过奖励分量日志核验量级。
- 每个 episode 必须记录 `reward_goal_progress`、`reward_obstacle`、`reward_reference_speed`、`reward_action_smoothness`、总奖励和终端奖励，不能只看总回报。
- 实验顺序：R5 四项全开；R5 通过 critic 健康门和饱和门后，才运行 R6–R9 的 leave-one-out；R5 未通过则停止扩展，先修 critic 或动作饱和。每个配置 20k、seed 0、S1+S2、单环境，配置放在 `configs/rl/ablations/reward_v2/`，结果写入 `artifacts/m4/p1/convergence/reward_v2_screening.csv`。

以下组件明确后置，本轮不实现、不调参、不进入 P1 主表：HER、TTC、ICM/RND。HER 需要目标重标记和历史序列重算；TTC 依赖动态障碍；ICM/RND 会引入非平稳内在奖励，必须等基础策略和奖励 v2 稳定后单独立项。它们的结果不得回写当前 P1 主表或 C1–C5/SAT/R 实验。

P1 首批场景只启用 S1 空水域和 S2 单圆柱，先固定起点和目标；只有 S1/S2 短训练出现稳定学习后，才启用随机起点、S3 和种子扩展。每回合固定记录：`episode_id`、场景、种子、RL 步数、仿真时间、总回报、`R1/R2/R3/R4` 分量、成功/到达/碰撞/越界/超时、终止原因、初始/最终目标距离、最小 clearance、路径长度、平均速度、最大绝对 `u_dot`/`r`、两个动作维度的饱和比例和 `action_clip_count`。`action_clipped` 布尔值不能代替饱和比例。

## 8. 指标与失败分类

基础指标：

- 成功率、碰撞率、越界率、超时率。
- 最小全艇体 clearance、路径长度、完成时间。
- 横向/垂向跟踪 RMSE、终端误差。
- 舵角、舵速、RPM、饱和比例和约束违反次数。
- 局部决策延迟、rollout 延迟、安全滤波延迟、P99 延迟。
- 每次重规划的 rollout 时间、预测轨迹长度、预测-真实轨迹差。

分层指标：

- 局部层介入率。
- 仲裁权限切换次数和持续时间。
- 回退触发率及回退类型。
- direct-action（若启用）与 rollout-path 的成功率、路径和跟踪差。

失败分类至少包括：

- `stale_observation`
- `stale_reference`

- `arbitration_conflict`
- `safety_rejected`

## 9. 计算与资源策略

- M0–M3 只使用 CPU；M2 起 PVS 仅出现在执行器适配层和运行脚本中，算法核心仍保持纯 Python，
  并由导入隔离测试保证 torch、OceanSim、HoloOcean、ROS 2、PVS 不进入 `auv_local` 核心。
- M4 的向量化 DDPG 先用 `N=1` 验证语义，再用 `N=64` 验证端到端吞吐；`N=64` 不通过时不得直接扩大到 256/1024。
- DDPG 基线使用自研 PyTorch 张量环境，不依赖 IsaacLab；PPO 候选使用 IsaacLab `DirectRLEnv`。
  Cartpole 的 4096 环境结果只作为 IsaacLab 基础设施参考，不能替代 P1 批量环境对齐和 P1 吞吐测试。
- PPO 的 4096 是单进程/单卡口径；8 卡实验按独立进程运行 seed 或配置，不把 8×4096 直接写成
  一个“分布式 32768 环境”结论。
- 预算按总环境转移数记录，同时报告 `env_steps/s`、`control_steps/s`、`gradient_steps/s` 和 `update_to_data_ratio`；不能只用 env steps/s 宣称训练加速。
- 训练和评估的随机种子、环境版本、观测规格和动作规格必须保存。
- 不能使用测试场景进行调参。
- 如果 OceanSim 或 HoloOcean 运行条件不稳定，先用 PVS 闭环完成算法闭环；纯 Python fake 只用于快速契约测试，
  不把仿真器故障或 fake 结果误判为算法失败/成功。

## 11. 停止条件

出现以下任一情况时暂停扩展，不开新算法：

- 2.5D 闭环无法稳定复现。
- ALOS 与局部动作之间没有明确的控制权限。
- 局部层指标被跟踪误差完全吞没。
- online rollout 的重规划时序、时间戳或预测状态被误当成真实状态。
- Policy rollout 与 direct-action 的差异无法解释。
- 训练环境与评估环境的观测预处理不一致。
- OceanSim/HoloOcean 感知失败与算法失败无法区分。
- 组合框架开始出现大量空接口、重复类型或跨包反向依赖。
- 解析 13 扇区与 OceanSim P1-A 的配对误差未通过，仍试图用调策略掩盖感知差异。
- 多环境训练出现 episode、GRU history、replay 序列或随机种子串扰。
- 环境数增加后 `update_to_data_ratio` 明显下降，却把“样本吞吐提高”写成“学习效率提高”。
- `N=64` 未达到端到端吞吐或 5 Hz 门，仍继续扩大环境数。

停止时只允许修契约、时序、观测、控制或评价，不允许为通过门而调整论文阈值和成功判定。
