## 2. 冻结的架构方向

### 2.1 两类局部算法

```text
LocalPathPlanner
  局部路径/短轨迹 → 3D ALOS → Reference

ReactivePolicy
  当前观测 + 目标/路径窗口 → 运动动作
  经 online rollout 转成局部短轨迹，再交给 ALOS

并行修正（后置）
  ALOS 名义参考 + ReactivePolicy 动作 → MotionArbiter
```

不能用一个 `LocalPlanner.act()` 同时代表 DWA、MPC、DDPG 和 APF。它们输出的抽象不同，强行统一会把接口做成万能字典。

### 2.2 3D ALOS 的位置

- ALOS 是制导层，不是规划器。
- 在局部路径模式下，ALOS 位于局部路径规划器之后。
- 首版训练采用 direct-action；评估采用 online rollout：DDPG 在每个预测步输出 `[u_dot, r]`，经局部运动模型积分得到局部航点；短轨迹交给 ALOS 跟踪。
- 只有后续“并行修正模式”才让 ALOS 提供名义参考并与反应式动作仲裁。

### 2.3 论文方法与本项目工程组件

| 组件 | 来源 | 用途 |
|---|---|---|
| PSO 全局规划 | 论文 | 全局基线 |
| DDPG `[u_dot, r]` | 论文 | 反应式局部策略 |
| 3D ALOS | 论文思想；本地已有实现 | 共享制导层 |
| `PolicyRolloutPlanner` | 本项目 | 把闭环 RL 策略展开成局部轨迹 |
| `MotionArbiter` | 本项目 | 在线组合 ALOS 与反应式动作；首版不启用 |
| `MotionExecutor` | 本项目 | 通用平台动作分配；首版复现直接复用既有 REMUS 控制器 |
| `NavigationRuntime` | 本项目 | 组合、时序、回退和日志 |

工程组件不得作为论文创新点，除非后续单独完成文献审计、强基线和消融。

### 3.1 训练与评估时序

**P1 训练链（2026-10-28 冻结）**：

```text
OceanSim 简化声呐 + 同步位姿
  ↓
ObservationBuilder
  ↓
DDPG [u_dot, r]
  ↓ SurgeYaw 动作适配
二维水平运动学 10 × 0.02 s（深度固定）
  ↓ 权威 State + 全艇体二维碰撞/越界检查
OceanSim 位姿同步 → 下一帧简化声呐
  ↓
ObservationBuilder → 下一训练样本
```

P1 只训练二维避障策略，不调用 ALOS、REMUS 控制器或 PVS。OceanSim 负责场景和简化声呐；二维运动学负责权威运动状态。

**P2 评估与微调链**：

```text
真实 SimulationSnapshot
  ↓
LocalObservation（13 扇区 + 目标信息 + u/r，上一动作可选）
  ↓
DDPG 输出 [u_dot, r]
  ↓ 局部运动模型积分
局部航点（深度继承 route_window/全局参考）
  ↓ 重复到 rollout 时域终点
LocalPathPlan.trajectory
  ↓
ThreeDAlosGuidance → Reference
  ↓
Remus100TrackingController → Remus100ActuatorCommand
  ↓
PvsRemus100Backend → 下一真实 SimulationSnapshot
```

初始工程参数为 horizon 2.0 s、rollout 步长 0.2 s、每 0.5 s 从真实快照重规划；rollout 内每一步重新调用策略，不是重复同一动作。这些数值只属于 P2 评估链，在 M5 通过收敛与闭环稳定性检查后再冻结，不能写成 P1 训练参数或论文成功阈值。

P1 训练阶段 DDPG 直接给出 `[u_dot, r]`，由二维运动学执行；P2 再把策略动作展开成局部轨迹并交给 ALOS、REMUS 控制器和 PVS。两层不同时上电，也不存在 DDPG 与 ALOS 同时修改同一个速度/艏向指令的问题，因此不使用 `MotionArbiter`。

### 3.2 论文参数核对结论

已核对 Yuan et al. (2025) 的正文、公式和 Table 2/Table 6/Table 7。论文明确给出：

| 项目 | 论文值/事实 | 对本项目的含义 |
|---|---|---|
| DDPG 动作 | `[u_dot, r]` | 不直接输出航点，需经运动模型积分 |
| 运动约束 | `2–8 kn`、`|q|≤10°/s`、`|r|≤15°/s`、`|u_dot|≤1 kn/s` | 论文平台与 REMUS 100 不同，不能直接照搬数值 |
| DDPG 平均单步规划时间 | Table 7：37.9 ms | 约 26 Hz 的单步计算上限参考 |
| 前视声呐更新率 | 最大 27 Hz，512 波束 | 与 37.9 ms 单步量级一致 |
| 训练轮次 | 300 rounds | 只说明训练轮数，不说明单轮时长 |
| DDPG 超参数 | Table 2：batch 64、replay 100000、γ=0.98、lr=0.0002 等 | 可用于训练配置起点 |

论文没有明确给出：

- 仿真积分步长 `h` 的具体数值；`h` 只在海流一阶模型公式中出现符号；
- DDPG 动作的实际控制周期或动作保持时间；
- rollout 时域、航点间距和重规划周期；
- 航点是由在线逐步规划生成，还是离线整段生成后再交给 ALOS；
- 在线 rollout 的计算预算或最坏延迟。

因此首版取值不能写成“论文参数”，只能写成“由论文计算成本和 REMUS 动力学推出的工程初值”：

```text
horizon = 2.0 s        # REMUS 1.0–2.5 m/s → 2–5 m 前视
step = 0.2 s           # 10 次策略调用 × 37.9 ms ≈ 379 ms
replan = 0.5 s         # 给 379 ms 预算留约 121 ms 余量
ALOS/controller = 50 Hz
PVS = 0.02 s
```

379 ms 只是按论文单步规划时间做的预算估计，不是实测值。若把步长直接压到声呐的约 0.04 s，则 2 s rollout 需要约 50 次策略调用，按 37.9 ms/次约 1.9 s，无法放进 0.5 s 重规划预算。因此 0.2 s 是为了保留论文量级计算成本而做的在线折中，不代表还原了论文未公开的控制周期。M5 接入 rollout 后必须记录实际 rollout 平均和 P95 耗时；若超过 0.5 s，优先减少无效策略调用、缓存观测和优化几何，不允许悄悄降低安全距离或延长证书有效期来掩盖超时。

### 3.3 P1 运动学、PVS 与 OceanSim 的仿真边界

本节是 2026-10-27 架构决策及 2026-10-28 的 P1 课程修订，不是论文方法：

```text
P1：
二维水平运动学（权威状态）
  ↓ 位姿同步
OceanSim 场景 + 简化声呐
  ↓
RangeScan / LocalObservation

P2 / 最终评估：
DDPG / 控制器动作
  ↓
PVS REMUS 100 动力学（权威状态）
  ↓ 位姿、速度、时间
OceanSim 场景同步
  ↓ 声呐、相机、环境观测
RangeScan / LocalObservation
```

- P2 和最终评估以 PVS 的 `State`、`SimulationSnapshot`、`Remus100ActuatorCommand` 为唯一运动真值；P1 例外，以二维水平运动学为唯一运动真值，不启动 PVS。
- OceanSim 默认 BlueROV 的质量、阻尼、重力、碰撞体和刚体积分器不参与 REMUS 动力学。
- P1 的 OceanSim 位姿同步发生在 `0.2 s` RL 决策边界；二维运动学内部仍按 `0.02 s` 子步推进。
- 碰撞和越界由明确的场景几何/碰撞查询判定，不能根据渲染画面或 OceanSim 默认刚体行为推断。
- P1 正式感知使用 P1-A 几何简化声呐，详见技术栈 `6.2.1`；13 扇区、130° 前视场、`120 m` 原始量程、`20 m` 局部有效视野、`0.1°` 采样和关闭噪声均已冻结。
- oracle 仍是单元测试和诊断后端，不能替换 P1 正式训练的 OceanSim 感知。
- 不在 Isaac Sim 刚体上重建 REMUS 推进器、舵面、附加质量、横流阻力和恢复力矩；该路线只在后续需要接触动力学或硬件辨识时重新评估。

**M4.1 奖励：论文四项（论文式 (20)–(22)）**


- 成功由环境显式字段判定：到达目标、无碰撞、无越界、未超时；不能从奖励正负反推。

用途：动态 `ObstacleTrack`、预测有效期和反应式策略。

### S5 深度剪切流

用途：ALOS 海流补偿与局部动作的相互作用。

首批只要求 S1–S3，每个场景 3 个种子调试；接口稳定后再扩展到 S4–S5 和更多种子。不能为获得好看的成功率而缩小世界边界、放宽 clearance 或延长计算预算。

## 8. 指标与失败分类

基础指标：

- 成功率、碰撞率、越界率、超时率。
- 最小全艇体 clearance、路径长度、完成时间。
- 横向/垂向跟踪 RMSE、终端误差。
- 舵角、舵速、RPM、饱和比例和约束违反次数。
- 局部决策延迟、rollout 延迟、安全滤波延迟、P99 延迟。
- 每次重规划的 rollout 时间、预测轨迹长度、预测-真实轨迹差。

分层指标：

- 局部层介入率。
- 仲裁权限切换次数和持续时间。
- 回退触发率及回退类型。
- direct-action（若启用）与 rollout-path 的成功率、路径和跟踪差。

失败分类至少包括：

- `stale_observation`
- `stale_reference`
- `local_no_solution`
- `local_timeout`
- `arbitration_conflict`
- `safety_rejected`
- `constraint_violation`
- `collision`
- `out_of_bounds`
- `goal_not_reached`
- `model_mismatch`

## 9. 计算与资源策略

- M0–M3 只使用 CPU；M2 起 PVS 仅出现在执行器适配层和运行脚本中，算法核心仍保持纯 Python，
  并由导入隔离测试保证 torch、OceanSim、HoloOcean、ROS 2、PVS 不进入 `auv_local` 核心。
- M4 的 DDPG 训练先在单卡 GPU 或 CPU 小规模验证；先证明能学，再扩大规模。
- 训练和评估的随机种子、环境版本、观测规格和动作规格必须保存。
- 不能使用测试场景进行调参。
- 如果 OceanSim 或 HoloOcean 运行条件不稳定，先用 PVS 闭环完成算法闭环；纯 Python fake 只用于快速契约测试，
  不把仿真器故障或 fake 结果误判为算法失败/成功。

## 11. 停止条件

出现以下任一情况时暂停扩展，不开新算法：

- 2.5D 闭环无法稳定复现。
- ALOS 与局部动作之间没有明确的控制权限。
- 局部层指标被跟踪误差完全吞没。
- online rollout 的重规划时序、时间戳或预测状态被误当成真实状态。
- Policy rollout 与 direct-action 的差异无法解释。
- 训练环境与评估环境的观测预处理不一致。
- OceanSim/HoloOcean 感知失败与算法失败无法区分。
- 组合框架开始出现大量空接口、重复类型或跨包反向依赖。

停止时只允许修契约、时序、观测、控制或评价，不允许为通过门而调整论文阈值和成功判定。
