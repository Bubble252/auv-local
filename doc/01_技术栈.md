# 局部规划与反应式导航技术栈

记录日期：2026-10-27

文档性质：架构与接口草案 v0.2。本文档记录软件分层、数据契约、依赖边界和推荐技术选型，作为 M0 评审和后续实现的依据。

## 1. 设计原则

- 算法核心只依赖标准库、NumPy 和项目内 dataclass/Protocol，不直接依赖 ROS 2、HoloOcean、PVS 或具体控制平台。
- 全局规划器、局部路径规划器、反应式策略、制导、安全滤波和执行器分配是不同职责，不通过一个万能接口混合。
- RL 算法库只负责“观测 → 动作”，不依赖局部规划器、全局规划器或制导实现。
- 轨迹、参考、动作和命令都必须带时间戳、有效期、坐标系和状态语义。
- 训练和评估必须共享 observation builder 与 action adapter，避免预处理漂移。
- 先完成一个 2.5D 最小闭环，再增加第二个算法和完整 3D；不以空接口和算法数量衡量进度。
- 论文方法、复现解释和工程适配必须分开记录。`MotionArbiter`、`PolicyRolloutPlanner` 等属于我们的工程组件，不冒充论文贡献。
- 首版复现链固定为 `DDPG → online rollout → 局部航点/轨迹 → 3D ALOS → REMUS 控制器 → PVS`。底层执行链复用既有实现，不新增重复适配器。

## 4. 总体架构

```text
任务与场景
    ↓
GlobalPlanner
    ↓ PlanResult: Trajectory + Certificate + Diagnostics
    │
    ├─ online rollout 主模式（首版）
    │    ReactivePolicy.act()
    │         ↓ [u_dot, r]
    │    局部运动模型积分 → 局部 Trajectory/航点
    │         ↓
    │    ThreeDAlosGuidance（既有）
    │         ↓ Reference
    │    Remus100TrackingController（既有）
    │         ↓ Remus100ActuatorCommand
    │    PvsRemus100Backend（既有）
    │         ↓ SimulationSnapshot
    │    PVS / HoloOcean
    │
    └─ 并行修正模式（后置）
         Guidance 名义 Reference + ReactivePolicy 动作
              ↓
         MotionArbiter → SafetyFilter → MotionExecutor
```

首版只实现在线 rollout 主模式，不需要仲裁器。并行修正模式保留为后续扩展；若启用，必须记录控制权限切换。HoloOcean 只替换后端感知/仿真，不改变主链路的数据契约。

## 5. 模块职责

| 模块 | 输入 | 输出 | 主要责任 | 禁止事项 |
|---|---|---|---|---|
| `GlobalPlanner` | `PlanRequest` | `PlanResult` | 长程路径、轨迹、恢复证书 | 不处理高频局部动作 |
| `LocalPathPlanner` | 局部观测、路径窗口、目标、能力 | `LocalPathPlan` | 生成局部路径/短轨迹 | 不直接生成舵角/RPM |
| `Guidance` | 状态、轨迹、时间 | `Reference` | 生成名义跟踪参考 | 不做障碍决策 |
| `ReactivePolicy` | 观测、目标、可选上一动作 | `Reaction` | 输出直接运动动作 | 不假装直接输出路径 |
| `PolicyRolloutPlanner` | 策略、局部运动模型、`LocalPathRequest` | `LocalPathPlan` | 将闭环动作展开成局部航点/轨迹 | 不替代 ALOS 或底层控制器 |
| `MotionArbiter` | 名义参考、反应动作、模式 | `MotionSelection` | 定义控制权限和覆盖规则 | 首版复现不启用；仅用于并行修正模式 |
| `SafetyFilter` | 运动选择、安全上下文 | `SafeCommand` | 安全约束、否决、回退 | 不负责路径搜索 |
| `MotionExecutor` | 状态、安全动作、能力 | `ActuatorCommand` | 通用平台动作分配 | 首版 REMUS 直接复用既有跟踪控制器，不重复实现 |
| `NavigationRuntime` | 上述组件与场景 | 样本、指标、日志 | 时序、状态机、重规划触发 | 不写具体控制器 |
| `SimulatorBackend` | 执行器命令 | `SimulationSnapshot` | PVS、HoloOcean、ROS 2 适配 | 不进入算法核心 |

## 6. 核心契约

### 6.1 共享状态与轨迹

复用全局方向的以下对象：

```text
State
Trajectory
Reference
CurrentField
CapabilitySet
ScenarioConfig
PlanResult
RecoveryCertificate
```

坐标和时间约定：

- 世界坐标：NED。
- 体坐标：FRD。
- 角度：rad。
- 时间：仿真时间秒 `t_s`，不使用墙钟时间驱动核心逻辑。
- 四元数：`xyzw`。
- 所有观测、参考、动作必须带 `stamp_s`，必要时带 `valid_until_s`。
- 传感器射线方向必须在体坐标中显式给出，不能只保存一串距离。

### 6.2 局部观测

建议在局部项目中定义感知层对象，而不是继续使用单一 `sonar_ranges_m`：

```python
@dataclass(frozen=True)
class RangeScan:
    stamp_s: float
    sensor_id: str
    frame_id: str
    origin_body_m: FloatArray
    directions_body: FloatArray       # (N, 3)
    ranges_m: FloatArray              # (N,)
    min_range_m: float
    max_range_m: float
    confidence: FloatArray | None = None
```

```python
@dataclass(frozen=True)
class ObstacleTrack:
    track_id: str
    stamp_s: float
    shape_ned: Obstacle
    velocity_ned_mps: FloatArray
    covariance_ned_m2: FloatArray | None = None
    confidence: float = 1.0
    predicted_until_s: float | None = None
```

```python
@dataclass(frozen=True)
class LocalObservation:
    stamp_s: float
    state: State
    scans: tuple[RangeScan, ...] = ()
    tracks: tuple[ObstacleTrack, ...] = ()
    health: Mapping[str, float] = field(default_factory=dict)
    observation_source: str = "unknown"
    previous_action: FloatArray | None = None   # 可选；上一动作 [u_dot, r]
```

第一版可以使用 oracle 障碍适配器生成 `ObstacleTrack`，但必须在配置和日志中标记 `observation_source="oracle"`。以后换 HoloOcean 声呐时，算法只消费 `RangeScan` 和 `ObstacleTrack`。

首版不照搬论文的 15 维观测。REMUS 100 在既有 `State`、`SimulationSnapshot.actuator_state` 和 `Remus100ControlDiagnostics` 中可提供：

| 数据 | 来源 | 首版用途 |
|---|---|---|
| `position_ned_m` | `State` | 目标距离、相对方位、rollout 起点 |
| `quat_xyzw` | `State` | 艏向、俯仰、姿态相关特征 |
| `linear_velocity_body_mps` | `State` | 主要使用纵向速度 `u`，`v/w` 可选 |
| `angular_velocity_body_rps` | `State` | 主要使用艏摇角速度 `r`，`p/q` 可选 |
| 舵角、艉水平舵、RPM | `SimulationSnapshot.actuator_state` | 诊断、平滑性和执行器约束 |
| 期望/实际相对速度、速度误差、航向/俯仰误差 | `Remus100ControlDiagnostics` | 可选扩展，不进入第一版最小观测 |
| 当前六自由度加速度 | `PvsRemus100Backend.derivative_nu_dot()` | 动力学诊断；不在训练核心中默认使用 |

第一版最小观测建议为：

```text
13 个声呐扇区距离
+ 目标距离
+ 目标相对艏向角
+ 当前纵向速度 u
+ 当前艏摇角速度 r
= 17 维基础观测（具体维度和预处理在 M1 冻结）
```

`previous_action` 是 `LocalObservation` 的可选字段，默认不作为所有策略的强制输入。论文 Critic 使用上一动作；我们的 DDPG 适配器可以按配置启用，但通用 `LocalObservation` 不强制依赖它。`RangeScan.frame_id` 固定为 `body_frd`，局部请求中的轨迹窗口固定为 `world_ned`。

### 6.4 反应式策略

论文 DDPG 的 `[u_dot, r]` 只作为一个平台动作规格，不能进入通用局部契约的核心字段。它的动作空间是 2D 水平面，但运行场景和观测仍可以是 3D。Actor 的直接输出不是航点；动作经运动模型积分后才形成局部航点/轨迹，这个转换由 `PolicyRolloutPlanner` 完成。局部航点的深度从全局参考/路径窗口继承，不属于 DDPG 的避障决策。RL 层使用动作对象，适配器负责转换：

```python
@dataclass(frozen=True)
class SurgeYawAction:
    u_dot_mps2: float
    yaw_rate_rps: float
```

```python
@dataclass(frozen=True)
class ReactiveRequest:
    request_id: str
    observation: LocalObservation
    goal_ned_m: FloatArray
    route_window: Trajectory | None
    capability: CapabilitySet
    time_budget_s: float
    previous_motion: ControlProposal | None = None
```

```python
@dataclass(frozen=True)
class Reaction:
    status: LocalPlanStatus
    decision_id: str
    motion: ControlProposal | None
    authority: ControlAuthority
    rollout: Trajectory | None = None
    fallback: ControlProposal | None = None
    reason: str | None = None
    diagnostics: Mapping[str, Any] = field(default_factory=dict)
```

```python
class ReactivePolicy(Protocol):
    def reset(self, *, seed: int = 0) -> None: ...
    def decide(self, request: ReactiveRequest) -> Reaction: ...
```

控制权限至少支持：

```text
NOMINAL              使用 ALOS/名义参考
HORIZONTAL_OVERRIDE  局部层只覆盖水平速度或艏向
FULL_OVERRIDE        局部层覆盖三维运动
STOP                 减速、制动或悬停
```

### 6.6 Policy Rollout 适配器与 online rollout

把一个闭环策略转换成局部路径，必须运行一个短时域预测模型。这是“Actor 动作”到“局部规划器对外航点/轨迹”的显式边界，也是首版复现的主链路：

```text
真实快照中的当前状态
  ↓
构建观测 → policy.act(observation)
  ↓ [u_dot, r]
局部运动模型积分 step_s → 下一状态/局部航点
  ↓
用预测状态、障碍和声呐模型构建 predictive observation
  ↓
重复到时域终点，输出局部 Trajectory
```

时序定义：

- 每个局部决策周期从真实快照重规划，不在上一周期预测状态上继续累加。
- rollout 内部每个 `step_s` 重新调用一次策略，而不是重复同一个动作。
- rollout 时域结束或触发碰撞/越界/目标到达时停止。
- 输出轨迹交给现有 `ThreeDAlosGuidance` 跟踪；ALOS 和控制器按真实仿真时间运行，不按 rollout 时间运行。
- 本周期轨迹在下一次决策前是 ALOS 的跟踪对象；新轨迹必须重新映射时间戳，不能造成时间倒退。

首版工程默认值如下。这些是待 M2/M5 验证的实现参数，不是论文参数，也不是成功阈值：

| 参数 | 初始值 | 说明 |
|---|---:|---|
| `rollout.horizon_s` | 2.0 s | 在 REMUS 1.0–2.5 m/s 下对应约 2–5 m 前视路径 |
| `rollout.step_s` | 0.2 s | rollout 内部策略与积分步长；10 次策略调用对应论文 37.9 ms/次约 379 ms |
| `rollout.replan_period_s` | 0.5 s | 从真实快照刷新局部路径的周期 |
| `rollout.max_path_length_m` | 5.0 m | 防止策略原地绕圈或速度过低时无限展开 |
| 策略调用 | 每个 rollout 步一次 | 形成闭环动作序列，不是固定动作重复 |
| 局部深度来源 | `route_window` / 全局参考 | DDPG 不决定深度，ALOS 负责垂直跟踪 |

论文没有明确给出仿真步长 `h`、rollout 时域、重规划周期或航点间距，因此上表不是论文原值。2.0 s 时域来自 REMUS 速度范围 1.0–2.5 m/s（对应 2–5 m 前视路径）；0.2 s 步长和 0.5 s 重规划周期来自论文 37.9 ms 单步规划成本与 512 波束声呐 27 Hz 的实时性上限，属于待 M2/M5 实测校准的工程取值。

建议接口：

```python
@dataclass(frozen=True)
class RolloutConfig:
    horizon_s: float
    step_s: float
    replan_period_s: float
    max_path_length_m: float
    stop_on_collision: bool
    model_id: str
    clip_actions: bool = True
    inherit_depth_from_route: bool = True


class PolicyRolloutPlanner:
    def __init__(self, policy: RLPolicy, model: LocalMotionModel, config: RolloutConfig): ...

    def reset(self, *, seed: int = 0) -> None: ...

    def plan_local(self, request: LocalPathRequest) -> LocalPathPlan: ...
```

适配器必须满足：

- 在预测副本上运行，不能修改在线策略的 GRU/RNN 记忆；或提供显式的 `snapshot/restore` 机制。
- 每次 rollout 记录模型版本、时域、步长、动作限幅、终止原因和计算耗时。
- 预测观测必须由环境模型、障碍模型和传感器模型共同生成，不能只在当前声呐帧上重复动作。
- rollout 只生成 `LocalPathPlan`，不替代 `SafetyFilter`，也不能把预测轨迹直接视为安全。
- 预测轨迹与真实闭环轨迹分开保存，报告中必须标明哪一条是模型预测、哪一条是 PVS/HoloOcean 实际执行。

### 6.7 制导

复用全局方向的 `Guidance` Protocol 和 `ThreeDAlosGuidance`：

```python
class Guidance(Protocol):
    def guide(self, state: State, trajectory: Trajectory, t_s: float) -> Reference: ...
```

首版 ALOS 跟踪 `LocalPathPlan.trajectory`。它使用既有的 `ThreeDAlosGuidance`，输出 `Reference`；`Remus100TrackingController` 继续把 `Reference` 转成 `Remus100ActuatorCommand`。并行修正模式下才需要仲裁器协调 ALOS 与反应式动作。

### 6.8 仲裁、安全与执行

```python
class MotionArbiter(Protocol):
    def arbitrate(
        self,
        nominal: Reference,
        reaction: Reaction | None,
        request: ReactiveRequest,
    ) -> ControlProposal: ...


class SafetyFilter(Protocol):
    def filter(
        self,
        proposal: ControlProposal,
        context: SafetyContext,
    ) -> SafeCommand: ...


class MotionExecutor(Protocol):
    def execute(
        self,
        state: State,
        nominal_reference: Reference | None,
        command: SafeCommand,
        capability: CapabilitySet,
    ) -> ActuatorCommand: ...
```

`MotionArbiter` 不属于参考论文。首版复现把 DDPG 放在 ALOS 上游，只启用单一路径，不使用仲裁器；只有在线联调“反应式策略 + 名义制导”时才启用它。

## 8. 运行时与频率

建议首版控制时序（参数待 M2/M5 验证，不是论文阈值）：

| 模块 | 初始目标频率 | 说明 |
|---|---:|---|
| 全局规划 | 事件触发 | 初始、目标变化、严重偏离或人工请求 |
| online rollout 重规划 | 2 Hz（0.5 s） | 从真实快照刷新局部轨迹 |
| rollout 内部策略调用 | 5 Hz（0.2 s） | 每个预测步调用一次 DDPG |
| ALOS 制导 | 50 Hz | 跟踪当前局部轨迹，生成 Reference |
| 安全滤波 | 与 ALOS 参考同步 | 首版可先做最小限幅检查 |
| REMUS 跟踪控制 | 50 Hz | 既有舵角、舵速、RPM 限制 |
| PVS / HoloOcean | 50–100 Hz | PVS 当前为 0.02 s；后端保持自身步长 |

rollout 内部频率不等于真实执行频率。2 s 的预测时域不会让真实机器人“跳过”2 s；仿真仍按 0.02 s 推进，ALOS 和控制器持续跟踪。上述频率必须通过计算延迟、超时率和闭环稳定性测试后再冻结。

## 11. 实验组合与指标

第一阶段组合：

```text
A. 全局轨迹 + 无局部层 + ALOS
B. 全局轨迹 + 局部路径基线 + ALOS
C. 全局轨迹 + APF 反应式策略 + 仲裁 + ALOS
D. 全局轨迹 + DDPG 直接动作（诊断，后置）
E. 全局轨迹 + DDPG online rollout + 3D ALOS（首版主实验）
```

E 是论文复现主链路。D 用来分离“策略动作本身”和“rollout + ALOS 跟踪层”的影响，不作为首版通过条件。

指标至少包括：

- 任务成功率、碰撞率、越界率、超时率；
- 最小全艇体 clearance、路径长度、完成时间、能量；
- 横向/垂向跟踪 RMSE、终端误差；
- 舵角/舵速/RPM 最大值、均值、饱和比例和约束违反次数；
- 局部层介入率、仲裁覆盖次数、回退触发率；
- 决策延迟、rollout 延迟、P99 延迟；
- direct-action 与 rollout-path 的成功率差、路径差和跟踪差。

所有组合必须使用同一场景、同一种子集合、同一海流、同一感知噪声、同一动作限幅和同一计算预算。不能用一个组合的调参结果去比较另一个组合的默认参数。
