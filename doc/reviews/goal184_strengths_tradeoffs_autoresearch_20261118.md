# Goal184：如何保留路径收益、降低执行器负担

日期：2026-11-18。用户主动发起的一轮 autoresearch；状态：EXPLORATORY / 诊断完成 / 方案待闭环验证。没有新训练、改 reward、改 checkpoint 或改既定 Gate。

## 1. 建议

**以 BCRES 的路径控制为主，优先让策略学会尊重执行器可执行范围；速度环分工是第二候选。不要把 BCFT、BCRES、teacher 的输出直接平均。**

建议的最小训练修改是增加一项连续的“原始舵请求与本步可执行舵角之差”代价。它针对当前确定性策略仍存在的无效大请求，同时保留正常大舵抗流。先只改变这一项，保持架构、残差权限、学习率、探索、课程和其他 reward 不变，才能归因。此处是下一版的候选，不修改运行中的 Goal184。

探索 std 分通道治理排在后面：它可能减少训练期间额外裁剪，但不能消除确定性 BCRES 已有的约 56.4% 材料裁剪。近限位惩罚的优先级下调，因为 teacher 的实际近限位占用更高，却有更低材料裁剪。

这支持“请求明显超出执行器短时能力”，尚不能证明所有大请求都无用，或新增代价不会损害纠偏。材料裁剪高与路径误差低并存，也可能包含任务所需的快速响应。

**不能把高裁剪简单等同于高频反转。**以相邻请求变化都大于0.2°且符号相反定义变化方向反转，BCFT 方向舵/艉翼分别52.46%/50.22%，BCRES为44.23%/40.53%。BCFT反转更频繁但幅度更小。当前支持“BCRES请求变化幅度大”，并未用频谱证明某个频段是根因。

速度方面，按时步加权、标量command减前向地速的相反数（实际−目标），teacher平均偏差−0.065m/s，BC为+0.551，BCFT为+0.259，BCRES为+0.302。正偏差提示PPO仍偏快，但不是reward投影目标口径；它支持考虑速度环分工，不直接证明换PI必定改善。

## 3. 三条路线的排序

| 优先级 | 候选 | 保留什么、改变什么 | 最关键的反证 |
|---|---|---|---|
| 1 | 连续可执行请求代价 | 保留BCRES路径策略与控制权限；让过大的请求付出随幅度增长的代价 | 裁剪/请求差下降，但路线或completion明显退步 |
| 2 | 学习舵控制 + 可部署PI速度环 | 保留学习的路径纠偏，让传统反馈负责稳态速度；属于新控制分工 | RPM改变后舵效下降，路径收益消失；或仅oracle输入有效 |
| 3 | 分通道探索治理 | 保留确定性策略表达能力；限制训练时舵通道不必要的随机大跳 | 训练裁剪下降但确定性动作/路径无改善，或探索不足 |
| 条件分支 | CAPS式策略输出平滑 | 在证据支持观测噪声放大时约束策略均值对邻近输入的敏感性 | 输入扰动破坏历史/状态契约，或平滑使必要响应迟钝 |
| 暂缓 | 近限位惩罚、统一压缩残差、输出滤波、直接平均三套控制 | 可能限制已有纠偏能力，或只改变裁剪发生位置 | 不能证明物理行为改善，或引入相位滞后/权限不足 |

候选筛选还考虑过：调大现有实际动作平滑权重、改速度reward形状、分离actor/critic adaptive LR、学习可行增量动作、局部teacher模仿、终端切换teacher。当前全部后置：分别存在已裁剪信号不敏感、改变任务标度、缺少优化器因果证据、重训动作接口、teacher路线不优、历史终端schedule依赖等问题。不是认为永远无效，而是本轮证据不足以优先采用。

### 3.1 首选：罚不可执行请求，不先罚大舵

对每片舵i，定义未经clamp的归一化组合动作a_i，真实上一执行值δ_prev,i，幅值δ_max=20°，本步速率额度h=3°：

    δ_req,i = δ_max * clamp(a_i, -1, 1)
    δ_feasible,i = δ_prev,i + clamp(δ_req,i - δ_prev,i, -h, h)
    C_request = sum_i (a_i - δ_feasible,i / δ_max)^2
    r_new = r_old - λ_request * C_request

这是一个候选代价，同时对原始幅值越界和速率不可执行差敏感；仅作用两片舵，不把RPM量纲混进来。若只研究速率，也可用clamp后的请求替代a_i，但那不能治理目前34%/38%的原始越界。首轮选定一种定义，不同时叠加margin、CAPS、std约束。

当舵已稳定在20°且请求也为20°时，代价为0；它不禁止持续满舵。快速纠偏暂时超出执行能力时仍允许请求，但有连续代价；它不保证闭环稳定，也不是安全证明。

实现前必须核对信号接线：当前reward的requested输入已clamp，不能只打开旧clip-attempt权重；应保留采样的原始组合动作，计算代价，并按已有pc_ppo_scale一致缩放。PPO的log_prob仍对应实际采样动作，不能静默把动作记录替换成投影后的值。δ_prev可用于仿真代价；若未来把它用于部署控制层，需要真实可获得的执行器反馈，不能直接偷用仿真真值。

本轮不拍脑袋给λ。应先在既定训练/诊断日志中核对该代价与路径reward的尺度，预注册一个弱权重并做一次匹配对照；不根据评价seed反复扫描权重。只增加连续代价，不同时改LR、std、残差scale。

### 3.2 速度分工值得试，但不是直接拼接teacher

候选结构：BCRES负责方向舵和艉翼，可部署PI负责RPM；PI使用明确的速度目标与可部署速度反馈，并有积分抗饱和。必须区分目标地速、前向地速、对水速度及推进器前馈，不把oracle teacher的真值海流直接搬进部署系统。

最便宜的下一步是冻结同一checkpoint，在专门标注的诊断中只替换RPM通道，观察路线、速度偏差、超速、completion和两片舵执行负担。换RPM会改变来流、舵效和姿态，不能由“teacher速度更好”推导出模块可独立组合；历史观测中的动作也需记录实际组合动作。若路线恶化，否定“可以直接拼接”，不立即用大量超参修补。

冻结策略的通道替换只是兼容性诊断，不能替代按新动作契约重新训练。若该结构被采纳，应作为清楚命名的新arm；它不再是原始三执行器PE2E，不能暗中替换原有结果。

### 3.3 探索与学习率：区分作用层次

仅降低init std不能保证后续std不再长大；分通道上界或时间相关探索是不同机制。归一化0.15对应3°，只能提供物理量级，不能直接作为最优std：相邻独立噪声之差、执行器滞后及当前舵角都会影响裁剪。

降低std主要作用随机rollout，不会直接平滑act_inference的均值。当前确定性证据排除了“全部由噪声造成”。现阶段不把actor/critic学习率分离或fixed/adaptive重构当作主药；它们控制参数更新，不直接约束50Hz动作请求。是否改优化器，应另由KL、更新漂移和价值拟合证据决定。

## 4. 一个避免虚假改善的反例

在固定上一步实际舵角下，记现有限幅投影为P。把原始请求预先变成P(a)再送入同一pipeline，则P(P(a))=P(a)。四组trace上，重算投影的最大差均为0°，但第二次投影的裁剪标签可以为零。

这只是同一状态下的本步可执行量恒等式，不是新闭环实验；若动作历史或reward改变，未来策略与轨迹也可能改变。它说明仅靠前置clip消掉material_saturated，不足以证明控制改善。评价必须保留原始请求差，并看真实舵运动、路线、速度和completion。

## 5. 文献交叉核对

[CAPS，Mysore等，ICRA 2021](https://arxiv.org/abs/2012.06644)用时间/空间策略平滑正则抑制不平滑动作，并在四旋翼等任务验证。[作者项目页](https://ai.bu.edu/caps/)给出了策略相邻输出与邻近状态输出的约束形式。它支持把约束放到策略请求端；不证明我们的请求代价最优，也不支持把四旋翼收益比例照搬到AUV。

[L2C2，Kobayashi，IROS 2022](https://arxiv.org/abs/2202.07152)讨论局部连续性约束，明确指出过度平滑会损失表达能力。与CAPS相比，它更强调局部约束的强弱；对我们意味着保留必要快响应，不追求舵动作越小越好。这是机制借鉴，未复现该算法。

[Residual Reinforcement Learning for Robot Control，Johannink等，2018预印本](https://arxiv.org/abs/1812.03201)将传统反馈与学习残差叠加，在装配任务验证。它支持按能力分工的思路；不证明把AUV的PI与已训练舵策略拼起来一定有效。

仓库已有reading note提到Ma等的AUV速度PI/舵RL分工。本次仅通过[Crossref DOI记录](https://doi.org/10.1109/TIV.2023.3282681)核实题名、作者与期刊日期，未取得可读方法全文，故不把其具体PI结构作为本轮已验证依据；2023为DOI年份，Crossref卷期日期为2024年1月。

## 6. 下一步与停止条件

当前决策为continue：保持Goal184主线和完整BCFT/BCRES评价，不根据单个C5诊断换主线。优先准备一个单因素可执行请求代价对照；速度PI组合为后续独立诊断，不与它同时改变。

新协议应预注册基线checkpoint、训练预算、课程/profile、评价矩阵、非劣化容忍度及seed数。候选只有在路线收益保留、completion无不可接受退步、安全无恶化，且真实请求差/执行负担改善时才值得继续。不能只要求饱和率下降；不在看完结果后调整非劣化界限。正式评价仍需完整矩阵及多训练seed证据，不用本批40个评价seed反复调参。

若最小对照否定假设，记录后回到机制判断；满足仓库hard blocker触发条件时才按规定建立blocker和进一步research loop。本次没有伪造Gate FAIL，也没有触发新的长训练。
